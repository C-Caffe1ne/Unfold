# Unfold Product Planning

## 절차

1. `docs/README.md`에서 현재 문서를 찾고 `docs/mvp.md`, `docs/product-direction.md`, `docs/business-model.md`, `docs/development-plan.md`를 읽는다.
2. 현재 체크아웃의 구현과 테스트에서 문서의 핵심 주장을 표본 확인한다.
3. 각 판단을 `구현 확인`, `자동 검증`, `실제 OS 관찰`, `수요 가설`, `미검증`으로 분류한다.
4. 핵심 사용자 문제와 반복 사용 동기를 먼저 정리하고, 그 다음 지불가치 가설을 연결한다.
5. 우선순위마다 사용자 행동으로 측정할 수 있는 수용 기준과 가장 싼 검증 방법을 제시한다.

## 보고서 구조

```markdown
# 제품·BM 감사
## 현재 방향
## 근거와 불일치
## 지불가치 가설
## 우선순위 제안
## 수용 기준과 검증
## 미검증·의사결정 필요 항목
```

제품 코드와 기존 문서를 수정하지 말고 Task가 지정한 보고서만 작성한다.
