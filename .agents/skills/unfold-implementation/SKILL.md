# Unfold Implementation

## 절차

1. Task spec과 관련 감사 보고서에서 원인, 소유 파일, 금지 범위, 수용 기준을 확인한다.
2. 현재 Git 상태를 읽고 기존 변경과 다른 워커의 산출물을 보존한다.
3. 실패를 재현하거나 정적 계약 불일치를 확인한 뒤 최소 변경을 구현한다.
4. 결함이 다시 생기면 실패하는 의미 있는 회귀 검사를 추가한다.
5. 변경 범위의 집중 검사 후 필요한 상위 빌드·진단을 한 번 실행한다.

## 구현 보고서 구조

```markdown
# 구현 보고서
## 원인
## 변경
## 소유 파일
## 검증
## 미검증·위험
```

Task가 지정하지 않은 기능, 리팩터, 문서 정리는 함께 수행하지 않는다.
