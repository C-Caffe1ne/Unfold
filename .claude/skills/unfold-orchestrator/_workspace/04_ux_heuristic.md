# Unfold UX 휴리스틱 평가 (B1 UX Researcher)

대상: `/Users/hwanghyeonseong/.codex/worktrees/beta-v1-1-0/Unfold` (`codex/glb-import-compat`, HEAD `bbdb4a8`, 1.1.1-beta 커밋 / 캡처는 `Beta v1.1.0` 빌드)
평가일: 2026-10-06

## 요약

- 핵심 루프(타이머 → 말풍선 초대 → 휴식 → 완료 → 기록)는 상태 배지·초과 시간·빈 상태 복귀 버튼까지 갖춰 **사용자 통제와 상태 가시성이 전반적으로 양호**하다. 되돌리기 안내("저장하지 않은 변경을 되돌렸어요.")처럼 모범적인 처리도 있다.
- 가장 큰 구조적 문제는 **"지금 무엇이 저장되었는가"가 화면마다 다르게 작동한다**는 점이다. 홈 시간 설정은 수동 저장인데 저장 버튼이 변경 전까지 투명도 0으로 숨겨져 있고, 설정 페이지는 자동 저장인데 성공 피드백이 전혀 없다. 똑같이 생긴 숫자 입력기 두 벌이 정반대 모델로 동작한다.
- 가장 위험한 단일 상호작용은 **펫 팩 "저장" 버튼**이다. 설치·업데이트·교체(기존 설치 펫 덮어쓰기)가 모두 같은 라벨 한 번 클릭으로 확인 없이 실행되며, 되돌릴 수 없다.
- 첫 실행에서 **유료 제품임을 Google 로그인 이전에 알리지 않는다**. 무료 체험이 없는 1회 결제 모델에서 가격·약관 고지가 로그인 뒤에만 나오는 구조는 신뢰와 전환 양쪽에 불리하다.
- 내부 페이지 네 곳(홈·펫 관리·기록·설정)에 **제목이 없다**. 현재 위치는 아이콘 레일의 호버 툴팁으로만 알 수 있어, 특히 안내 문구가 통째로 사라진 펫 관리 첫 화면에서 다음 행동이 보이지 않는다.

## 방법과 한계

- 방법: Nielsen 10 휴리스틱 기반 전문가 평가. 근거는 (a) 읽기 전용 원본 소스 코드, (b) off-screen 렌더 캡처 112개, (c) `docs/mvp.md`·`stretch-notifications.md`·`settings-ui.md`·`pet-packs.md` 동작 계약.
- 한계 1: **실제 사용자 테스트를 수행하지 않았다.** 아래 모든 "사용자 영향"은 코드·화면 근거에서 도출한 가설이며, 실제 혼란 발생률·과업 완료율은 측정되지 않았다. 마지막 절의 테스트 과제로 검증해야 한다.
- 한계 2: 앱 실행·빌드·컴퓨터 조작을 하지 않았다. 호버 툴팁 표시 여부, 비활성 컨트롤의 툴팁 동작, 결제 단계 화면, 실제 OAuth·결제 흐름은 코드 추론이다.
- 한계 3: 캡처에 없는 화면(계정 구매 단계, 펫 우클릭 메뉴, 트레이 메뉴, 3회 연속 미루기 반응)은 **코드 추론**으로 표시했다.
- 범위 제외: MVP Scope boundaries에 명시된 미구현 기능(루틴/프로필 UI, 픽셀 에디터, 클라우드 동기화 등)의 부재, 이미 수정된 QA-01·R-01·R-02·A-02, 별도 추적 중인 P3(이름-only 초안, 중복 RootNode, 내보내기/적용 피드백), 다른 감사자가 보고한 3건(로그아웃 버튼 상태, 픽셀 에디터 영어, 긴 펫 이름 잘림).

## 흐름별 평가

### 1. 첫 실행 — 계정/구매 게이트

**잘 된 점**
- 로그인 화면이 단일 행동(Google로 계속하기)으로 수렴하고, 종료 경로(`Unfold 종료`)를 좌하단에 두어 막다른 길을 만들지 않았다. (`account-login.png`)
- 세션 복원 실패·보안 저장소 실패를 서로 다른 문구로 구분한다. (`AccountScreenCopy.RestoreUnavailable` / `SessionStorageUnavailable`)

**문제**
- 로그인 화면에 가격(4,900원 / US$3.99), 1회 결제라는 사실, 무료 체험 없음, 이용약관·개인정보 고지가 **하나도 없다**. 가격 정보(`markets`)와 `productLabel`("Unfold · 1회 구매")은 구매 단계에만 쓰인다 → **UX-02**
- 이용코드(`codeButton` "코드 입력")도 구매 단계에만 노출된다. 코드를 받은 사용자도 Google 로그인을 먼저 통과해야 한다(코드 추론).
- 실패 문구가 원인·복구 경로 없이 결과만 알린다: "구매 정보를 확인하지 못했어요.", "결제창을 열지 못했어요." → **UX-11**

### 2. 홈 타이머

**잘 된 점**
- 상태 배지가 진행 중·일시정지·중지·자리 비움·휴식 대기 중·휴식 중을 **모두 다른 문구와 색으로 구분**한다. (`SettingsWindow.cs:212-224`) 상태 가시성의 모범 사례다.
- 저장하지 않은 간격 변경이 타이머 재개로 무효화될 때 값만 되돌리지 않고 "저장하지 않은 변경을 되돌렸어요."라고 경고색으로 알린다. (`SettingsWindow.cs:244-252`) 조용한 데이터 손실을 막는 좋은 처리다.
- 중지 확인 대화상자가 결과를 구체적으로 설명한다("남은 시간이 초기화되고 진행 중인 휴식이 취소돼요"). (`confirm-stop.png`)

**문제**
- `시간 설정` 카드에 저장 버튼이 보이지 않는다. 값이 바뀌기 전까지 `Opacity = 0`이라 **수동 저장이 필요한 화면이라는 사실 자체를 알 수 없다**. (`home-default.png`, `SettingsWindow.cs:160-162`) → **UX-04**
- 타이머 진행 중 `스트레칭 알림 간격`이 비활성인데, 화면에는 이유가 없다. 설명("타이머 진행 중에는 스트레칭 시간을 변경할 수 없어요.")은 비활성 컨트롤의 툴팁에만 들어 있다. (`SettingsWindow.cs:248`) → **UX-05**
- 같은 카드 안에서 `스트레칭 알림 간격`은 타이머 상태에 묶이고 `휴식 시간`은 언제든 수정되지만, 두 입력기는 시각적으로 동일하다.

### 3. 휴식 알림

**잘 된 점**
- 초과 시간을 `+00:10` 경고색으로 계속 보여 주며 자동 완료하지 않는다. 완료 시점의 통제권을 사용자에게 남긴다. (`speech-overtime.png`)
- 미루기 버튼 라벨이 설정값을 반영해 `{n}분 뒤에`로 바뀐다. (`PetSpeechBubble.cs:89`) 기억이 아니라 인식으로 선택하게 한다.
- 숨긴 펫을 알림 동안만 임시로 표시하고 저장된 표시 설정을 바꾸지 않는다.

**문제**
- 초대 말풍선은 30초 뒤 자동으로 미뤄진다(`PetReminder.cs:10,40-45`). 화면에 **남은 시간 표시도, 미뤄졌다는 사후 안내도 없다.** 잠깐 자리를 비우면 펫이 말없이 사라지고 다음 알림까지 아무 설명이 없다 → **UX-06**
- 초대에 "건너뛰기"나 "오늘은 그만" 같은 명시적 거절 경로가 없다. 반복 미루기만 가능하다(3회째 삐지기 반응은 코드 추론).
- 펫 우클릭 메뉴는 `설정` / `펫 숨기기` 두 항목뿐이다(`PetWindow.cs:62-70`). 숨기기를 누르면 **다시 보이게 하는 방법을 알려 주지 않는다** → **UX-10**

### 4. 기록/회고

**잘 된 점**
- 빈 기간에서 문구를 현재/과거로 나누고("이 7일 동안 완료한 휴식이 없어요." / "이 기간에는 완료한 휴식이 없어요.") `타이머로 돌아가기` 복귀 버튼을 제공한다. (`BreakReviewWindow.cs:132-136`) 빈 상태 처리의 모범이다.
- 기간 이동 버튼이 경계에서 비활성화된다(과거 77일, 미래 차단). (`BreakReviewWindow.cs:154`)
- CSV 내보내기 성공 메시지가 건수와 파일명을 모두 알려 준다. (`BreakReviewWindow.cs:74`)

**문제**
- 상단 지표 `기록된 시간`은 신규 기록의 실제 휴식 초와 구형 기록의 계획 초가 **섞인 합계**인데, 화면에 설명이 없다. 같은 화면 하단에는 "실제 휴식 시간 미기록" 행이 공존한다. (`review-default.png`, `BreakReviewWindow.cs:96,125,244-247`) → **UX-12**
- `완료한 휴식` / `기록된 시간` / `휴식한 날` / `실제 휴식` 네 가지 시간 용어가 한 화면에 있다.

### 5. 펫 관리

**잘 된 점**
- 커스텀 펫 에디터의 파일 교체는 기존 파일명과 새 파일명을 모두 보여 주며 확인을 받는다("지금은 '{기존}' 파일이 들어 있어요… 다른 동작은 그대로예요."). (`CustomPetWindow.cs:239-241`) 오류 예방의 좋은 사례다.
- 초안을 두고 나갈 때 저장 가능 여부에 따라 안내와 버튼 세트를 바꾼다(저장 가능: "저장하고 종료/버리기/취소", 불가: "계속 작성/버리기/취소"). (`CustomPetWindow.cs:336-339`)
- 펫 팩 미리보기가 설치 전에 동작별 재생·길이·반복 방식을 확인하게 한다. (`pack-preview.png`)

**문제**
- 펫 팩 대화상자의 실행 버튼은 어떤 경우에도 `저장`이다. 상태 캡션만 "저장 준비 완료 / 업데이트 준비 완료 / 재설치 준비 완료 / **교체 준비 완료**"로 바뀌고, 교체(설치본보다 낮은 버전으로 덮어쓰기)에도 **확인 대화상자가 없다**. (`PetPackWindow.cs:61,181,207-230`) → **UX-01**
- 펫 관리 첫 화면에 제목도 안내도 없다. "나만의 펫을 만들어 보세요."는 임베드(`showHeader: false`) 시 버려진다. 보이는 것은 비활성 드롭다운 3개와 "파일 없음"뿐이다. (`settings-pet-create-tab.png`) → **UX-08**
- `펫 팩 만들기…`가 비활성인 이유(이름 + 필수 '기본' 동작)가 화면에 없다. 이 조건은 종료 확인 대화상자에서만 글로 나온다.
- `펫 선택` 드롭다운이 홈(적용할 펫)과 펫 관리(편집할 펫)에 같은 라벨·다른 의미로 존재한다 → **UX-09**

### 6. 설정

**잘 된 점**
- 음량을 전체/스트레칭/완료 3단으로 나누고 각 슬라이더 옆에 미리듣기 버튼을 둬, 저장 전에 결과를 확인하게 한다. (`settings-options-top.png`)
- `로그인 시 자동 실행` 토글 실패 시 시도한 방향을 가정하지 않고 OS 상태를 재조회해 체크박스를 되돌린다. (`SettingsWindow.cs:79-100`) 거짓 상태 표시를 막는 드문 수준의 처리다.

**문제**
- 설정 페이지는 자동 저장인데 **성공 피드백이 단 하나도 없다.** `preferencesStatus`는 오류일 때만 표시된다. (`SettingsWindow.Preferences.cs:27,77,143) 홈의 "저장했어요."와 정반대 모델이다 → **UX-03**
- `디버그 도구` 카드가 일반 사용자 설정 하단에 그대로 노출된다. (`settings-options-bottom.png`) → **UX-15**
- 문서 `docs/stretch-notifications.md`는 설정에 `저장`/`취소` 버튼이 있다고 기술하지만 현재 구현과 캡처에는 없다. 동작 계약 문서가 구버전이다(보고 범위 밖이나, UX-03 수정 시 함께 갱신 필요).

### 7. 트레이·펫 메뉴·업데이트

**잘 된 점**
- 트레이 일시정지 항목이 상태에 따라 `시작`/`계속`/`일시정지`로 라벨을 바꾼다. (`AppRuntime.cs:240`)
- `휴식 알림으로 이동`이 초대의 `휴식 시작` 또는 진행 중의 `완료`로 포커스를 옮긴다. 숨긴 펫을 되찾는 명확한 경로다.
- 종료는 트레이·사이드바 모두 확인을 받고 결과를 설명한다. (`confirm-quit.png`, `AppRuntime.cs:607`)

**문제**
- 트레이 메뉴(일시정지/타이머 중지/업데이트 확인 포함)와 펫 우클릭 메뉴(설정/펫 숨기기)의 항목 집합이 크게 다르다. 펫을 직접 조작하려는 사용자는 타이머 제어를 찾지 못한다(코드 추론).
- 업데이트 미지원 설치본 안내가 "새 버전을 한 번 설치해 주세요"로 끝나고 받을 곳을 알려 주지 않는다. (`app-updates.png`) → **UX-14**
- 사이드바 그룹 분류가 기능과 어긋난다. 상단 묶음 = 홈·펫 관리·기록 + **테마**(설정 성격), 하단 묶음 = **설정** + 종료. (`SettingsWindow.Layout.cs:90-101`) → **UX-13**

## 검증용 사용자 테스트 과제 제안

실제 테스트가 가능해지면 아래 5개 과제로 위 가설을 검증한다. 참가자 5~8명(한국어 사용자, 데스크톱 상시 사용 직군, 유사 앱 경험 유무를 반반), 과제당 성공/실패와 진술을 기록한다. 모든 과제는 생각 말하기(think-aloud) 방식으로 진행하며 진행자는 힌트를 주지 않는다.

**과제 1 — 첫 실행 기대 일치 (UX-02 검증)**
- 과제: "이 앱을 방금 내려받았습니다. 쓸 준비를 해 보세요." 로그인 화면에서 중단시키고 묻는다: "이 앱은 유료일까요, 무료일까요? 그렇게 생각한 근거는?"
- 성공 기준: 로그인 버튼을 누르기 전에 유료(1회 결제)임을 맞히는 참가자 비율 ≥ 70%.
- 관찰 지표: 유료 여부 정답률, 가격을 말할 수 있는 비율, 구매 단계 도달 후 "미리 알았다면 좋았을 것" 진술 수, 로그인 전 이탈 의향.

**과제 2 — 저장 모델 이해 (UX-03, UX-04, UX-05 검증)**
- 과제: "스트레칭 알림을 25분마다, 휴식은 3분으로 바꾸고, 말풍선이 펫 왼쪽에 뜨게 하세요. 끝났다고 생각되면 말해 주세요."
- 성공 기준: 세 값 모두 실제로 저장된 상태로 종료 선언하는 비율 ≥ 80%. 선언 시점에 "이게 저장된 건지 모르겠다"는 진술 0건.
- 관찰 지표: 과업별 완료 시간, 저장 버튼을 찾는 데 든 시간, 타이머 진행 중 간격 입력기를 클릭하고 포기한 횟수, 종료 선언 후 실제 저장값 대조 결과, "저장됐나요?" 확인 질문 빈도.

**과제 3 — 휴식 알림 통제 (UX-06 검증)**
- 과제: 타이머를 1분 간격으로 설정해 초대 말풍선을 띄운 뒤 진행자가 "잠깐 다른 일을 봐 주세요"라며 60초간 다른 과제를 시킨다. 돌아온 뒤 묻는다: "방금 무슨 일이 있었나요? 지금 휴식은 어떤 상태인가요?"
- 성공 기준: "자동으로 미뤄졌다"는 취지로 정확히 설명하는 비율 ≥ 70%.
- 관찰 지표: 상태 설명 정확도(미뤄짐/놓침/버그 추정 분류), 다음 알림까지 남은 시간을 확인하려는 행동 유무, "앱이 고장난 것 같다" 진술 수.

**과제 4 — 펫 추가 시작점과 안전성 (UX-08, UX-01 검증)**
- 과제 4a: "이 GIF 파일로 나만의 펫을 만들어 적용해 보세요." (파일은 바탕화면에 준비)
- 과제 4b: 이미 설치된 펫과 같은 ID의 **구버전** `.unfoldpet`을 주고 "이 파일도 확인해 보세요"라고만 지시한다.
- 성공 기준: 4a는 힌트 없이 5분 내 완료 ≥ 70%. 4b는 `저장`을 누르기 전에 "기존 펫이 바뀐다"는 사실을 인지하는 비율 ≥ 80%(현재 구현에서는 0%에 가까울 것으로 예상).
- 관찰 지표: 첫 클릭 위치(파일 열기 발견 시간), 비활성 `펫 팩 만들기…`를 누른 횟수, 4b에서 캡션 "교체 준비 완료"를 읽은 참가자 비율, 저장 후 기존 펫 소실을 알아차린 시점.

**과제 5 — 복구와 위치 파악 (UX-07, UX-10 검증)**
- 과제: "바탕화면 펫을 잠깐 안 보이게 했다가, 다시 보이게 해 보세요. 그다음 이번 주에 몇 번 쉬었는지 확인하세요."
- 성공 기준: 외부 도움 없이 펫을 복구하는 비율 ≥ 80%, 주간 기록 화면 도달 시간 중앙값 ≤ 20초.
- 관찰 지표: 복구까지 걸린 시간과 시도한 경로(트레이 / 설정 / 재실행), 사이드바 아이콘을 호버로 탐색한 횟수, 페이지 이동 중 잘못 누른 아이콘 수, "여기가 어디인지 모르겠다" 진술 수.
