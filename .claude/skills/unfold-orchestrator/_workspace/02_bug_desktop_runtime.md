# A2 Desktop App Engineer — 펫 창·플랫폼·미디어 결함 감사 (1.1.0-beta / 1a74cbf)

## 요약

- 펫 창의 좌표 계산은 팀 메모 규칙(DesktopScaling 사용)을 **전 경로에서 지키고 있다**. `PetWindow`·`PetWindow.Companion`의 위치·드래그·클램프·말풍선 배치 모두 `DesktopScaling`만 쓰고 `RenderScaling`은 GLB 픽셀 해상도 산정(`AnimationView`)과 진단 캡처에만 쓴다. Retina Dock 회귀는 재발하지 않았다.
- 가장 영향이 큰 신규 발견은 **Windows 클릭 통과 구현이 투명 펫 창에 `WS_EX_LAYERED` + `SetLayeredWindowAttributes(LWA_ALPHA)`를 추가하고 레이어를 되돌리지 않는 점**이다. 이는 미검증 출시 게이트(실제 Windows 클릭 통과·DPI)를 실패시킬 수 있는 구체적 코드 결함 후보다.
- 두 번째 축은 **UI 스레드 동기 블로킹**이다. 휴식 알림 효과음은 최대 5 MiB WAV를 2회 읽고 샘플 단위로 볼륨 변환한 뒤 임시 파일까지 쓰는 작업을 전부 UI 스레드에서 수행하고, 커스텀 펫 파일 배정은 GIF 전체를 UI 스레드에서 디코드한 뒤 같은 디코드를 백그라운드에서 한 번 더 한다.
- 상주 비용 측면에서 펫 표시 중 16 ms 타이머가 커서 위치와 무관하게 항상 60 Hz로 동작하며, GLB 렌더 스크래치는 한 번 요청된 최대 래스터 크기(최대 약 32 MiB)로 모델 수명 동안 상주하고 축소되지 않는다. 후속 문서의 미해결 RSS 추세(G-02)와 직접 연결된다.
- 시작 경로에는 데이터 디렉터리 생성·단일 인스턴스 락 실패가 처리되지 않아 로그·안내 없이 종료/크래시하는 분기가 남아 있다.

## 확인한 결과 결함이 아니었던 항목(중복 보고 방지)

- `MacPetWindow`의 `objc_msgSend` 직접 P/Invoke: `collectionBehavior`(NSUInteger), `setHidesOnDeactivate:`/`setIgnoresMouseEvents:`(BOOL→I1), `mouseLocationOutsideOfEventStream`(NSPoint = double 2개, arm64/x64 모두 레지스터 반환) 모두 시그니처가 맞고, 좌표는 테두리 없는 NSWindow의 bottom-left 기준을 `ClientSize.Height - y`로 올바르게 변환한다(`MacPetWindow.cs:49-59`).
- `ReminderSounds.Duration`의 `rate` 변수는 이름과 달리 fmt 청크의 byteRate(`offset+16`)를 읽으므로 길이 계산은 정확하다(`ReminderSounds.cs:42-54`).
- GLB 파서는 애니메이션이 없는 모델에 `Static` 클립을 합성하므로(`GlbModel.cs:204`) `GlbPetDraft`의 `Model.Animations[0]`·`options[0]` 접근은 빈 배열을 만나지 않는다.
- 커스텀 펫 내보내기의 시트 폭 초과 우려는 성립하지 않는다. 정적 이미지는 512 px로 축소되고(`ImageCodec.cs:12`, `:30`), 정적 이미지가 섞일 때 idle 프레임도 같은 경로로 재축소되므로(`CustomPetDraft.cs:88`) `Columns × FrameWidth ≤ 4096` 제한을 넘지 않는다.
- 저장된 펫 위치가 사라진 모니터를 가리켜도 `ClampPosition`이 앵커 아래 화면→창 화면→주 화면 순으로 폴백해 작업 영역 안으로 되돌린다(`PetWindow.cs:325-336`).
- 스프라이트 시트 폴백(`PetWindow.cs:157-168`)의 `Array.Copy`는 로드 시 `image.Width == Columns × FrameWidth` 검증(`CharacterLibrary.cs:113`)이 보장되므로 범위를 벗어나지 않는다.
- GIF 프레임 지연 0은 100 ms로 정규화되고 프레임 수·디코드 용량 상한이 있어(`ImageCodec.cs:95`, `:108`) 애니메이션이 0 ms 루프로 폭주하지 않는다.
- 파일 연결(`.unfoldpet`/`.glb` 더블클릭) 전달은 구현도 등록도 없다. 설치 스크립트에 연결 등록이 없고(`Packaging/Unfold.Windows.nsi`에 문서 타입 항목 없음) `Program.Main`도 경로 인자를 해석하지 않으므로, 기능 부재로 보고 결함으로 올리지 않았다. 아래 질문 항목으로 넘긴다.

## 실제 OS에서만 확인 가능한 항목

1. **BUG-D-01 (Windows per-pixel 알파)** — 실제 Windows(x64 1개, arm64 가능하면 1개)에서 100 %/150 %/200 % DPI 각각: (a) 펫 표시 직후 투명 배경 캡처, (b) 커서를 투명 픽셀 위로 올려 클릭 통과가 켜진 상태에서 같은 위치 캡처, (c) 다시 펫 몸통 위로 올려 클릭 통과를 끈 상태에서 캡처. 세 캡처의 배경 알파가 동일한지 비교하고, 각 단계에서 `GetWindowLong(GWL_EXSTYLE)` 값을 함께 기록한다. 추가로 외부 창을 펫 뒤에 두고 투명 영역 클릭이 그 창에 전달되는지, 드래그 중 해제가 정상인지 확인한다.
2. **BUG-D-04 (Windows 효과음 실패)** — 출력 장치를 모두 비활성화한 Windows에서 설정 → 알림 → "들어보기"를 누르고, (a) 오류 안내가 뜨는지, (b) 로그에 예외가 남는지 확인한다. 같은 조건을 macOS에서 반복해 동작 차이를 기록한다.
3. **BUG-D-05 (유휴 CPU/배터리)** — 펫 표시 상태로 커서를 화면 반대편에 둔 채 30분 방치하며 Windows는 ETW/`powercfg /energy`, macOS는 `powermetrics --samplers tasks`로 Unfold의 wakeups/s와 CPU 평균을 기록한다. 펫 숨김 상태와 비교해 차이를 남긴다.
4. **BUG-D-07 (macOS 로그인 실행)** — 로그인 시 실행을 켠 뒤 앱 번들을 다른 폴더로 이동하고 재로그인한다. 자동 실행 여부와 설정 화면의 토글 표시, `~/Library/LaunchAgents/app.unfold.desktop.plist`의 경로를 기록한다.
5. **BUG-D-08 (혼합 DPI)** — 배율이 다른 두 모니터(예: 200 %와 100 %)를 연결하고 알림 말풍선이 뜬 상태로 펫을 모니터 경계를 넘겨 끈다. 넘어가는 순간의 말풍선 크기·위치·클램프를 연속 캡처하고, 작업 영역 밖으로 밀리는지 확인한다. 모니터를 분리했다가 재연결하는 절차도 함께 수행한다.
6. **BUG-D-12 / BUG-D-13 (GLB 메모리·프레임)** — 동일 GLB 펫을 적용한 상태에서 설정 → 펫 편집기로 같은 모델을 미리보기한다. (a) 펫의 실제 프레임 간격을 화면 녹화로 측정, (b) 편집기를 닫은 뒤 10분 경과 RSS가 미리보기 이전 수준으로 돌아오는지 `vmmap`/작업 관리자로 기록한다. 후속 문서 G-02의 동일 조건과 비교할 수 있게 warm-up 이후 값을 쓴다.
7. **BUG-D-09 (종료 중 고아 프로세스)** — 알림음 재생 중과 MP4 변환 중 각각 트레이에서 종료한다. 종료 후 소리 지속 여부, `ps`/작업 관리자에서 `afplay`/`ffmpeg` 잔존 여부, `%TMP%`·`/var/folders/.../T`의 `Unfold-sound-*`/`Unfold-video-*` 잔여물을 확인한다.
8. **BUG-D-06 (시작 실패 처리)** — `UNFOLD_DATA_DIR`을 쓰기 불가 경로로 지정해 실행하고, 종료 코드·사용자에게 보이는 메시지·로그 위치를 기록한다(격리된 테스트 경로만 사용).

- **제품/기획(A1)**: `.unfoldpet`/`.glb` 파일 연결(더블클릭으로 열기)은 1.1.0 범위인가? `docs/mvp.md`의 Scope boundaries에 명시가 없고 설치 스크립트·`Program.Main` 모두 미구현이어서 "부재"로 처리했다. 범위라면 단일 인스턴스 전달 프로토콜(`SingleInstance`가 1바이트만 주고받는 구조)부터 설계가 필요하다.
