# 08. UI 시각 디자인 감사

- 감사 대상: `/tmp/unfold-ui-audit-20260916b/verification/`의 PNG 42장(+`smoke.json`, `review.csv`)
- 대조 문서/코드: `docs/design-system.md`, `docs/settings-ui.md`, `src/Unfold.Desktop/DesignSystem.cs`, `Ui.cs`, `SettingsWindow.Layout.cs`, 각 화면 View/Window
- 방법: PNG를 실제 렌더링 근거로 열람하고, 의심 구간은 PNG를 직접 디코딩해 픽셀 색상/좌표를 대조했다(외부 이미지 도구 없이 순수 PNG 파서 스크립트 사용). 코드와 캡처가 다르면 캡처를 우선했다(에이전트 지침).
- 범위 제외: `editor.png`(진단용 픽셀 에디터)는 `docs/design-system.md`에 "편집 도구 배치를 재설계하지 않았다"고 명시된 화면이라 감사 대상에서 제외했다. `pack-*.png`의 미리보기 사각형(주황 테두리 빈 박스)은 `diagnostic-v1/v2.unfoldpet` 진단용 픽셀 아트 고정물이며 실제 캐릭터 아트가 아니므로 렌더링 결함으로 보지 않았다 — 실제 캐릭터 팩의 미리보기 시각 품질은 **미검증**으로 남긴다.

### 2. 설정 대시보드 — 최소 크기 (`settings-minimum.png`, `settings-minimum-scrolled.png`)

- 860×680에서 가운데 펫·타이머와 좌측 레일은 고정되고 우측 카드 열만 세로 스크롤된다는 `docs/settings-ui.md` 설명대로 동작한다(`settings-minimum-scrolled.png`에서 우측 열만 "말풍선 알림" 카드 이하로 스크롤됨을 확인).
- 최소 폭에서도 "적용" 배지 버튼, 수치 입력 화살표가 잘리지 않고 카드 안쪽 여백을 유지한다.
- 스크롤된 상태에서 "오늘의 작은 쉼" 카드가 화면 하단에서 살짝 잘려 보이지만(스크롤 가능 콘텐츠의 정상적인 하단 경계이며 스크롤바가 존재) 이는 결함이 아니라 스크롤 가능 영역의 정상 렌더링이다.

### 3. 펫 추가 — 열기 탭 (`settings-pet-open-tab.png` 기본, `settings-pet-open-minimum.png` 최소)

- 기본 폭(1120)에서는 문제 없음. "펫 팩 열기..." 버튼이 오른쪽 여백과 프레임 사이에 정상 간격을 두고 배치된다(근거: 픽셀 스캔 x=1074에서 버튼 종료, x=1076부터 프레임 배경 `#1D201D`).
- **최소 폭(860)에서 스크롤바가 등장하면서 "펫 팩 열기..." 버튼의 오른쪽 둥근 모서리에 스크롤바 트랙이 거의 맞닿는다** — `settings-pet-open-minimum.png` 크롭 확인. 클릭 가능 영역을 막을 정도는 아니지만 모서리 곡률이 시각적으로 스크롤바에 눌린 것처럼 보인다.

### 4. 펫 추가 — 만들기 탭 (`settings-pet-create-tab.png` 기본, `settings-pet-create-minimum.png`/`-scrolled.png` 최소) — **P1 결함 확인**

- 기본 폭(1120×800)에서는 문제 없음. "펫 이름" 입력창과 "파일 가져오기" 버튼이 프레임과 정상 간격을 유지한다(픽셀 스캔: 버튼 우측 끝 x≈1075, 프레임 배경 전환 x=1078, 스크롤바 없음).
- **최소 폭(860×680)에서는 세로 스크롤바 썸(`#858585`)이 "펫 이름" `TextBox`의 오른쪽 위 둥근 모서리와 "파일 가져오기" 버튼의 오른쪽 절반을 실제로 관통해 그려진다.** 근거: `settings-pet-create-minimum.png`를 (700,170)-(830,300) 영역으로 크롭한 이미지에서 회색 스크롤바 선이 텍스트박스 모서리와 버튼 배경 위에 겹쳐 보이고, 픽셀 스캔(y=257)에서도 버튼 배경색(`#363C33`) 한가운데에 스크롤바 색(`#858585`)이 2px 폭으로 끼어 있음을 확인했다(x=813~814). 같은 y좌표를 기본 폭 캡처와 비교하면 기본 폭에는 이 스크롤바 색이 전혀 나타나지 않는다.
- 이는 취향 문제가 아니라 **관찰 가능한 겹침 결함**이다: `PageBodyScroll`(`Ui.cs`의 `PageContent`)이 최소 창 크기에서 콘텐츠보다 폭이 좁아지면서 스크롤바가 별도 거터 없이 본문 위에 얹혀 그려진다.
- 스크롤된 상태(`settings-pet-create-minimum-scrolled.png`)에서도 동일한 스크롤바가 하단의 두 번째 카드("파일 선택...", "미리보기", "제거" 버튼 행)와는 겹치지 않는다 — 그 버튼 행은 카드 안쪽 여백(16)이 있어 스크롤바와 거리가 있기 때문으로 보인다. 즉 겹침은 **카드 밖에 배치된 상단 컨트롤(이름 입력, 가져오기 버튼)에서만** 발생한다.

### 7. 루틴·프로필 라이브러리 (`routine-library.png`, `work-profiles.png`) — **P2 관찰**

- 640×620, 탭 전환(내 루틴/업무 프로필)과 목록·액션 버튼 구성이 `docs/design-system.md`의 "선택 목록·탭, 선택한 탭의 새 항목·편집·적용·삭제와 닫기를 하단에 고정" 규칙과 일치한다.
- **두 화면 모두에서 동일한 패턴**: 하단 액션 버튼이 "새 루틴/새 프로필·편집·적용·삭제" 4개 + "닫기" 1개, 총 5개이고 `Ui.Actions`(`WrapPanel`, 오른쪽 정렬)가 640px 폭에서 이를 한 줄에 담지 못해 "닫기"만 둘째 줄로 밀려 오른쪽 정렬로 홀로 배치된다. 근거: `routine-library.png`·`work-profiles.png` 모두 "루틴 삭제"/"프로필 삭제" 아래 오른쪽에 "닫기"만 있는 줄이 별도로 존재.
- 대조군: `weekly-review.png`(620×650)는 버튼이 "닫기"+"CSV 내보내기" 2개뿐이라 한 줄에 들어가 이 현상이 없다. 즉 원인은 **버튼 개수 대비 640px 모달 폭이 좁다는 것**이며, `Ui.Actions`의 줄바꿈 자체는 설계대로 동작한다.
- 기능적 결함은 아니지만(줄바꿈은 명시된 설계 규칙), 상단 4버튼 그룹과 하단 "닫기" 사이에 비대칭적인 여백이 생겨 시각적 마무리가 깔끔하지 않다. 취향에 가까운 P2로 분류한다.

### 8. 펫 팩 열기/설치/오류 (`pack-preview.png`, `pack-installed.png`, `pack-reinstall.png`, `pack-update.png`, `pack-error.png`)

- 520×850, "설치" 버튼이 상태에 따라 활성/완료(비활성 "설치 완료")/비활성("일시정지"·"다시 재생"도 동일)으로 정확히 전환된다. 비활성 버튼은 `DesignSystem.cs`의 `:disabled` 규칙(낮은 명도 + 불투명도 0.55 상당)대로 흐릿하게 표현된다.
- `pack-error.png`는 하단에 2줄 오류 메시지가 추가되며 자연스럽게 스크롤바가 나타난다 — 이는 콘텐츠 증가에 따른 정상 스크롤이며 겹침은 없다(픽셀 스캔으로 확인, 프레임 안쪽 여백 유지).
- 미리보기 사각형 내부 아트(주황 테두리 빈 박스)는 진단용 픽셀 고정물이라 실제 캐릭터 아트 렌더링 품질은 **미검증**.

### 9. 커스텀 펫 제작 (`custom-pet-editor.png` 기본, `custom-pet-minimum.png`/`-scrolled.png` 최소, `custom-pet-preview.png`)

### 10. 기록·내보내기 (`weekly-review.png`, `settings-review-tab.png`)

### 11. 펫 말풍선 (`speech-top/left/right/bottom.png`, `speech-five-minutes.png`, `speech-completed.png`, `speech-overtime.png`, `speech-folded.png`)

- 4방향 꼬리(위/아래/왼쪽/오른쪽)가 방향에 맞게 렌더링되고, 말풍선 배경은 진한 색(`#1D201D`~`#141713` 계열 추정, Shell/Canvas 톤)에 크림색 텍스트로 대비가 확보된다.

- `speech-folded.png`(192×192)는 펫만 남고 말풍선이 접힌 상태로, 클릭으로 접을 수 있다는 안내 문구와 일치. 결함 없음.

### 12. 확인·이름 입력·오류 대화상자 (`dialog-confirm.png`, `dialog-prompt.png`, `dialog-error.png`)

- 세 창 모두 동일한 페이지 프레임(둥근 모서리, 제목 "UNFOLD / …")을 공유한다.
- `dialog-confirm.png`: "삭제"가 왼쪽(Danger, 빨강 텍스트)·"취소"가 오른쪽에 배치되고 `docs/design-system.md`의 "삭제 확인에서는 취소에 먼저 포커스" 규칙대로 취소가 시각적으로 강조 없이(Quiet) 표시된다. 포커스 표시 자체는 정적 이미지로 **미검증**(포커스 링은 상호작용 상태라 스크린샷만으로 판단 불가).
- 결함 없음.

## 시각 완료 기준

- **P1 (스크롤바 겹침)**: `settings-pet-create-minimum.png`·`custom-pet-minimum.png`와 동일한 캡처 조건(860×680 / 520×620, 각 창의 기본 스크롤 위치)에서 재캡처했을 때, "펫 이름" `TextBox`와 "파일 가져오기" 버튼의 오른쪽 모서리 x좌표 전 구간에서 스크롤바 색(`#858585` 계열)이 검출되지 않아야 한다(본 감사에서 사용한 픽셀 스캔 방식으로 재검증 가능). 동시에 기본 폭(1120×800) 캡처에서 회귀가 없어야 한다.
- **P2 (버튼 줄바꿈 비대칭)**: `routine-library.png`/`work-profiles.png`와 동일한 조건에서 재캡처했을 때, 하단 액션 버튼이 한 줄에 들어가거나(폭 확장 시), 줄바꿈이 유지되더라도 상단 그룹과 "닫기" 사이 수직 간격이 카드 내부 다른 간격(8~14px 수준)과 비례해 과도한 공백으로 보이지 않아야 한다. 이 기준은 관찰자 판단이 필요한 정성적 기준이므로 취향 조정으로 취급하고 강제하지 않는다.

## 팀 통신 메모

- 동작(흐름) 측면 문제는 발견하지 못했다 — ux-flow-auditor 영역과 겹치는 새 항목 없음.
- 키보드 포커스·접근성 이름·대비 자체는 정적 캡처만으로 검증할 수 없는 부분(포커스 링, 탭 순서 등)이 있어 ui-accessibility-qa 영역으로 남겨둔다. 본 보고서는 그 영역의 결론을 선점하지 않았다.

## 추가 확인 — `settings-routines-tab.png` 프레임/로고/헤더가 "밀려 보인다"는 지적 (2026-09-16 후속)

**결론: 실제 레이아웃 결함이 아니라 둥근 모서리(CornerRadius 32) + RenderTargetBitmap 캡처 방식에서 오는 시각적 인상이다. `settings-review-tab.png`와 픽셀 단위로 바이트 동일함을 확인했다.**

- 근거 1 (프레임 경계 좌표 비교): 두 PNG 모두 1120×800이며, 중앙 행/열 스캔으로 찾은 프레임 테두리(`Outline` `#444B40`) 경계가 `top=16, bottom=783, left=16, right=1103`로 **완전히 동일**하다. `SettingsWindow.Layout.cs`의 `BuildDashboard`에서 `SettingsFrame`에 `Margin = new(16)`을 준 것과 정확히 일치하며, 탭에 따라 달라지지 않는다.
- 근거 2 (좌상단 100×?px 크롭 육안 비교): 로고(크림색 원, 44×44), 타이머 내비게이션 아이콘, `내비게이션 레일` 왼쪽 시작 x좌표(=16)가 두 캡처에서 동일 위치에 있다. 헤더 "UNFOLD / …" 캡션의 시작 x좌표도 111로 동일하다.
- 근거 3 (영역 diff): (0,0)-(300,110) 영역을 픽셀 단위로 비교하면 33,000픽셀 중 4,635픽셀만 다르며, 그 차이는 전부 헤더 제목·설명 텍스트 글자 모양(문구 자체가 "나만의 방식으로 쉬어 가세요." vs "나를 위해 만든 여유."로 다름) 때문이다. 로고·레일·프레임 테두리 영역에는 차이가 없다.
- 근거 4 (캡처 파이프라인, `SmokeDiagnostics.cs:407-422`): `Capture()`는 모든 42개 PNG에 대해 동일하게 `window.UpdateLayout()` 이후 `RenderTargetBitmap(window.ClientSize)`로 렌더링한다. `settings-routines-tab.png`와 `settings-review-tab.png`는 `VerifySettingsLayout`(`SmokeDiagnostics.cs:326-333`)에서 같은 창 인스턴스에 대해 `Press(...) → Task.Delay(100) → window.UpdateLayout() → Capture(...)`를 동일한 패턴으로 연속 호출한 결과물이며, 캡처 방식·창 크기·창 크롬 유무(OS 타이틀바 없음)에 차이가 없다. 즉 "화면 밖으로 밀림"을 만들 수 있는 캡처 단계의 비대칭이 코드상 존재하지 않는다.
- 해석: 프레임이 `CornerRadius(32)`로 둥글게 잘리고 그 바깥이 더 어두운 `Canvas`(`#141713`)로 채워지기 때문에, 축소된 썸네일이나 빠른 훑어보기에서는 마치 프레임·로고·아이콘이 좌상단 모서리 밖으로 "밀려난" 것처럼 보일 수 있다. 이는 두 탭 모두에서 동일하게 나타나는 의도된 프레임 형태이며 결함이 아니다.
- 공통 패턴/화면별 문제 표에 새 항목을 추가하지 않았다 — 근거가 회귀를 반증했기 때문이다. 다만 픽셀 비교로도 판단하기 어려운 부분(예: 실제 macOS/Windows 창에서 타이틀바 포함 캡처 시 좌표계가 달라지는지)은 아래 미검증 항목에 추가했다.

## 미검증 항목

- 실제(비진단) 펫 팩의 미리보기 아트 렌더링 품질(캡처된 것은 빈 사각형 고정물뿐).
- 대화상자의 실시간 포커스 링·키보드 포커스 이동(정적 이미지로는 판단 불가).
- 1120×800과 860×680 사이의 중간 폭에서의 스크롤바 겹침 발생 임계값(어느 폭부터 겹침이 시작되는지는 캡처되지 않음).
- 다른 해상도/DPI(레티나 등)에서의 동일 결함 재현 여부(캡처는 모두 1x로 추정되는 논리 픽셀 크기로 제공됨).
- `RenderTargetBitmap` 캡처(창 콘텐츠만, OS 타이틀바 없음)가 아닌 실제 OS 창 스크린샷에서 프레임 좌상단 모서리·로고가 동일하게 보이는지는 실기 확인이 필요하다(본 감사는 PNG 근거만 사용).
