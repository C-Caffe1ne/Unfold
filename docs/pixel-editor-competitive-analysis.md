# 픽셀 에디터 기능 노출 시 경쟁 가능성 분석

2026-09-14 · [경쟁 서비스 비교 분석](competitive-analysis.md)의 후속. 현재 코드베이스의 실제 에디터 구현(`src/Unfold.Core/PixelDocument.cs`, `EditorSession.cs`, `src/Unfold.Desktop/EditorWindow.cs`, `PiskelCodec.cs`)과 "내 캐릭터 직접 만들기" 카테고리의 실제 경쟁 제품을 조사해 판단한 결과다. `docs/mvp.md`와 `docs/business-model.md`는 이미 **"에디터 확장은 이번 BM의 전제가 아니다" / "에디터를 확장하거나... 기술 스택을 바꾸지 않는다"**고 명시하고 있으므로, 이 문서는 그 결정을 뒤집을 근거가 있는지를 검증하는 성격이다. `docs/reference/revenue-first-product-validation.md`의 판단 원칙(시장 증거 우선, 기능 추가=문제 해결이라는 착각 경계)을 참고했다.

---

## 1. 현재 에디터가 실제로 할 수 있는 것 (코드 확인)

| 항목 | 현재 구현 | 근거 |
|---|---|---|
| 캔버스 크기 | **최대 128×128px** (`PixelDocument.MaxSide = 128`) | `PixelDocument.cs` |
| 프레임 | 최대 24프레임, FPS 1–24 | `PixelDocument.cs` |
| 레이어 | 최대 16개, 레이어별 불투명도 블렌딩 | `PixelDocument.cs` |
| 도구 | Pencil, Eraser, Fill, Eyedropper, Line, Rectangle, Ellipse | `PixelDocument.cs`의 `PixelTool` enum |
| 편집 이력 | Undo/Redo, 스트로크 단위 편집 | `EditorSession.cs` |
| 파일 호환 | Piskel(`.piskel`) 코덱 임포트/익스포트 | `PiskelCodec.cs` |
| UI 진입점 | **없음.** 진단·회귀 테스트 전용으로만 연결 | `docs/mvp.md` "픽셀 에디터는 이 MVP에서 사용자 진입점이 없다" |

**핵심 문제.** `docs/pet-resources.md`가 정한 **신규 판매용 팩 제작 기준은 384×384 캔버스**다. 현재 에디터의 캔버스 한도(128×128)는 이 기준의 1/3 미만이다. 즉 지금 상태로 에디터를 사용자에게 노출하면, Unfold 스스로 정한 상품 품질 기준에도 못 미치는 저해상도 산출물만 나온다. 캔버스 확장 자체가 노출 이전에 필요한 별도 개발 과제다.

## 2. 시장 증거 — "직접 만드는 데스크톱 펫"은 이미 존재하는 카테고리다

지난 비교(Stretchly/BreakTimer/Time Out/Pausitive/Viraam/MicroJoyz/Desktop Mate)에는 편집기를 가진 경쟁자가 없었다. 이번에 "제작 도구" 축으로 좁혀 다시 조사하니 전혀 다른 경쟁 지형이 나온다.

| 제품 | 제작 방식 | 가격 | 비고 |
|---|---|---|---|
| **[Shimeji / Shimeji-ee](https://shimejis.xyz/)** | zip/rar 드래그 앤 드롭 설치 + 전용 무료 **[Shimeji Editor](https://shimejis.xyz/editor)**, 커뮤니티 업로드 라이브러리 | **완전 무료** | 15년 이상 축적된 생태계. "이미 커뮤니티가 대량으로 가져온" 캐릭터가 존재한다고 자체 소개 |
| **[Screen Pet Engine](https://screenpetengine.com/)** | 노코드 비주얼 비헤이비어 에디터, PNG 시퀀스/GIF/스프라이트시트 임포트 | 가격 비공개(Steam 데모) | "Your desktop but alive", 제작자·사용자 두 타겟을 명시적으로 분리 |
| **[Custom Desktop Pet (Steam, 출시예정)](https://store.steampowered.com/app/2297040/Custom_Desktop_Pet/)** | 자체 스크립팅 언어(비개발자도 가능 표방), 페인팅/Spine/스프라이트 지원, **Steam Workshop**으로 타 사용자 캐릭터 공유 | 미정 | Live2D·3D 확장 예고, 103개 언어 지원 |
| **[Deskie](https://deskie.me/)** | "Create Your Own Character" 기능 + AI 채팅 결합, 활발히 업데이트 중 | 확인 안됨 | 캐릭터 제작과 AI 동반자를 동시에 미는 직접 경쟁자 |

**시사점.** "만들기" 기능은 블루오션이 아니라 **이미 15년 된 무료 강자(Shimeji)가 지배하는 레드오션**이다. Shimeji는 (1) 완전 무료 (2) 전용 무료 편집기 (3) 대규모 커뮤니티 콘텐츠 라이브러리 (4) drag-and-drop 설치라는 4중 우위를 가진다. Unfold의 128px 숨겨진 에디터를 그대로 꺼내는 정도로는 이 우위를 넘어설 증거가 없다. Screen Pet Engine·Custom Desktop Pet·Deskie는 "제작 도구"를 아예 제품의 핵심 정체성으로 잡고 만들어진 제품들이라, "휴식 리마인더 앱에 부가 기능으로 얹은 에디터"와 자원 투입 수준 자체가 다르다.

반대로 이전 비교의 Desktop Mate·MicroJoyz는 편집기가 **없다.** 완성된 캐릭터를 팔거나 제공하는 쪽을 택했다. 즉 데스크톱 펫 시장은 "제작 도구 제공"과 "완성품 판매"로 이미 갈라져 있고, 둘을 어중간하게 겸하는 사례는 이번 조사에서 확인되지 않았다.

## 3. 차별화(ERRC) 관점에서 본 에디터의 위치

| 구분 | 판단 |
|---|---|
| **Eliminate 대상에 가까움** | "그림을 그릴 수 있다" 자체는 이미 Piskel(Unfold 에디터의 원조 자체가 이 기반)·Aseprite 등 훨씬 강력한 전용 무료/저가 툴이 있다. 여기에 Shimeji가 "그 결과물을 앱에 바로 쓰게 해주는" 파이프라인까지 무료로 제공한다. |
| **Raise 후보** | 기존 Plus 개인화 가설(루틴·프로필·회고)을 살짝 확장해 "눈 색, 무늬 등 가벼운 외형 커스터마이징" 정도로 좁히면, 새 카테고리 진입이 아니라 기존 Plus 가설의 연장이 된다. |
| **Create 아님** | "384px급 완성 애니메이션 5종을 만드는 풀 에디터"는 Unfold가 새로 만드는 게 아니라 Shimeji·Screen Pet Engine이 이미 하고 있는 것을 뒤늦게 따라가는 것에 가깝다. |

## 4. 검증되지 않은 핵심 가정 (Critical Assumptions)

| 가정 | 현재 증거 |
|---|---|
| H1. Unfold 사용자가 "펫을 받아 쓰기"가 아니라 "직접 만들기"를 원한다 | **없음.** `docs/business-model.md`의 첫 고객 가설은 "시각적 동료는 좋아하지만 반복 알림은 끄는" 사람이지, 제작 의지가 있는 사람이 아니다 |
| H2. 128px 에디터로 384px 기준의 완성도 있는 5종 반응 애니메이션을 만들 수 있다 | **거짓(현재 코드 기준).** 캔버스 한도 자체가 기준 미달 |
| H3. 앱 내장 에디터가 Piskel/Aseprite+Shimeji 조합보다 충분히 편해서 사용자를 끌어온다 | **약함.** Shimeji는 이미 무료+드래그앤드롭으로 마찰이 낮고, 15년 콘텐츠 자산까지 있다 |
| H4. 에디터 노출이 Plus/팩 매출을 늘린다 | **불확실, 오히려 반대 위험.** 사용자가 무료로 직접 만들 수 있으면 유료 캐릭터팩($4.99~7.99 가설) 구매 유인이 줄어드는 **자기잠식(cannibalization)** 가능성이 있다. Desktop Mate·MicroJoyz가 편집기 없이 완성품만 파는 것도 이런 이유일 수 있다(추론) |

## 5. 리소스·운영 비용 관점

`docs/pet-resources.md`는 이미 자체 제작 기준으로 "생성형 이미지 그대로 상품화 금지", "실제 alpha 검수", "연속 재생·루프 이음새 검수", "384px 기준"을 요구한다. 이는 Unfold 팀(1인/소규모 추정) 스스로도 지키기 부담스러운 기준인데, 일반 사용자가 만든 UGC(사용자 제작 콘텐츠)에 같은 기준을 적용하려면:

- 품질 검수·모더레이션(부적절한 콘텐츠, 저작권 침해 캐릭터 등) 비용이 새로 발생한다.
- 현재 `.unfoldpet` 형식은 로컬 파일 설치만 지원하고 중앙 카탈로그·신고·검수 파이프라인이 없다(`docs/pet-packs.md`).
- Custom Desktop Pet은 Steam Workshop이라는 기존 플랫폼 인프라에 검수·신고를 위임하지만, Unfold는 그런 배포 채널이 없다.

즉 에디터 노출은 "기능 하나 추가"가 아니라 **UGC 운영 체계를 새로 만드는 일**이며, 이는 1인/소규모 리소스로 감당 가능한지 별도로 확인해야 한다.

## 6. 판단

`docs/reference/revenue-first-product-validation.md`의 원칙("근거 없는 기능 추가는 추천하지 않는다", "경쟁자가 일주일 안에 복제해도 남는 것이 무엇인가")을 적용하면:

**전면 공개(범용 캐릭터 제작 도구로 마케팅) → HOLD.**
- 이미 15년 된 무료 강자(Shimeji)와 제작 도구를 정체성으로 삼은 신생 경쟁자(Screen Pet Engine, Custom Desktop Pet, Deskie)가 있는 레드오션이다.
- 현재 에디터는 자체 품질 기준(384px)에도 못 미치는 128px 한도라 추가 개발이 선행돼야 한다.
- 캐릭터팩 매출 가설을 자기잠식할 위험이 있고, UGC 운영 비용이 새로 발생한다.
- `docs/mvp.md`·`docs/business-model.md`가 이미 "에디터 확장은 이 BM의 전제가 아니다"라고 명시한 결정과도 배치된다.

**"가벼운 개인화" 축소판으로 Plus에 통합 → TEST 후보(코드 전에 먼저 검증).**
- 384px급 신규 캐릭터 제작이 아니라, 기존 캐릭터의 색상·무늬 같은 얕은 커스터마이징이라면 캔버스 확장·UGC 검수 비용 없이 기존 Plus 가설(§3, `docs/product-direction.md`)의 연장으로 흡수할 수 있다.
- 다만 이조차 "사용자가 원하는지"는 검증된 바 없다. 코드를 확장하기 전에, Plus 가격 관심 등록 실험(`docs/business-model.md` 3단계)에 "외형 커스터마이징" 옵션 하나를 항목으로 추가해 반응을 보는 쪽이 가장 싼 검증이다.

**요약.** 지금 시점에 "제작 도구 공개"로 경쟁하는 것은 근거가 약하다. 시장에 이미 강한 무료 대안이 있고, 현재 구현은 자체 기준에도 못 미치며, 매출 자기잠식 위험까지 있다. 반대로 얕은 개인화 옵션으로 축소해 기존 Plus 검증 절차에 끼워 넣는 것은 비용이 낮으므로 실험해볼 가치는 있다. 두 경우 모두 "만들면 경쟁력이 생긴다"가 아니라 "만들기 전에 관심부터 확인한다"는 프로젝트 문서의 기존 원칙과 같은 결론이다.

## 7. "제작 도구"로 내세우지 않고 조용히 포함한다면?

이 시나리오는 질문 자체를 바꾼다. "경쟁이 가능한가"가 아니라 "그만한 가치가 있는가"가 된다. 마케팅을 하지 않으면 Shimeji·Screen Pet Engine 같은 "제작 도구" 카테고리에서 싸울 필요 자체가 없어진다 — 애초에 그 카테고리 사용자를 데려오려는 시도가 아니기 때문이다. §2~3에서 든 "이미 강한 무료 대안이 있다"는 반론은 이 시나리오에서는 대부분 무력화된다.

다만 판단이 바뀌지 않는 지점도 있다.

- **128px 캔버스 한도는 마케팅 여부와 무관하다.** 조용히 넣어도 발견한 사용자가 캡처해 커뮤니티에 공유하면("Unfold에 숨은 에디터가 있더라") 품질에 대한 첫인상은 그대로 노출된다. 오히려 아무 설명("실험적", "베타") 없이 발견되면 기대치 관리가 더 어렵다.
- **자기잠식 위험은 줄어들지만 사라지지 않는다.** `CharacterLibrary`는 이미 외부 도구(Piskel/Aseprite)로 만든 로컬 팩을 불러오는 경로를 허용하므로 "직접 만들기" 자체는 지금도 가능하다. 다만 매니페스트 작성·폴더 배치 등 기술 지식이 필요해 진입장벽이 있다. 에디터를 앱 안에 넣으면 이 장벽이 비개발자 사용자에게까지 낮아지므로, 유료 캐릭터팩 구매 유인을 깎는 효과를 "지금도 가능하다"는 이유로 무시할 수는 없다.
- **가장 중요한 분기점은 "개인용이냐, 내보내기/공유 가능이냐"다.**
  - **개인용**(내 캐릭터 목록에만 반영되고 `.unfoldpet` 내보내기는 없음)으로 한정하면, 판매용 품질 기준(384px, alpha 검수, 저작권 확인)을 적용할 필요가 없고 중앙 카탈로그·모더레이션·신고 처리 같은 운영 부담도 생기지 않는다. §5에서 지적한 "UGC 운영 체계 신규 구축" 비용이 사실상 사라진다.
  - 반대로 **내보내기/공유까지 열면**, 공식 마케팅이 없어도 Discord·커뮤니티에서 자연 발생적으로 팩이 돌기 시작할 수 있다(Shimeji 생태계가 실제로 이렇게 커졌다). 이 경우 저작권·부적절한 콘텐츠 문제는 "조용히 넣었다"는 이유로 비켜가지 않는다.

**판단.** "제작 도구"를 내세우지 않고 개인용 라이트 기능으로 조용히 넣는다면:

- 경쟁 도구는 되지 않는다. 마케팅이 없으니 신규 유입 효과는 사실상 0에 가깝다. 이건 "경쟁력 확보"가 아니라 **기존 사용자를 위한 리텐션 보너스**에 가깝다.
- §5의 운영 비용 반론은 크게 약해진다 — **내보내기 기능을 끄고 개인 전용으로 한정**하는 조건에서만 그렇다.
- 그래도 (1) 128px 한도로 품질이 낮아 보일 위험, (2) 유료 팩 자기잠식 위험(줄었지만 0은 아님), (3) `docs/mvp.md`가 명시한 "에디터 확장은 MVP 범위 밖" 결정과의 충돌은 남는다. (3)은 마케팅 여부와 무관한 별개의 스코프 결정이라 조용히 넣는다고 자동으로 해소되지 않는다 — 이 결정 자체를 문서에서 의식적으로 갱신해야 한다.

**요약.** 원래 질문("경쟁이 가능한가")에는 여전히 "아니오, 이건 경쟁 도구가 아니라 리텐션 보너스다"가 답이다. 그 자체는 나쁘지 않지만, 경쟁력 확보를 목적으로 정당화할 수는 없다. 시도한다면 **개인 전용(내보내기 없음)** 범위로 한정하는 것이 §5의 운영 비용 우려를 크게 줄이는 사실상 유일한 조건이다.
