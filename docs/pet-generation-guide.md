# 보리·Mochi 스타일의 펫 생성·적용 가이드

2026-09-22. 사용자가 이번 펫과 동일한 콘셉트를 재사용하도록 요청한 제작 기준이다.
현재 C#·Avalonia 코드, 생성 기록, PNG와 manifest를 대조했다. 새 제작을 시작할 때는
이 문서와 원본 이미지를 먼저 읽고, 구현 계약이 바뀌었는지 확인한다.

## 1. 유지할 디자인

- 심플한 동물 실루엣, 두껍고 끝이 둥근 따뜻한 짙은 갈색 선, 평평한 밝은 단색 채움.
- 작은 타원형 눈과 간결한 표정. 소품·의상·과한 장식 없이 자세와 표정으로 행동을 표현한다.
- Mochi는 크림색 고양이: 작은 삼각 귀, 연한 분홍 귀 안쪽, 긴 곡선 꼬리, 작은 수염.
- 보리는 옅은 오트·베이지색 토끼: 긴 귀, 연한 살구·분홍 귀 안쪽, 작은 코와 둥근 꼬리.
- 부드러운 손그림풍의 `smooth` 리소스다. 예전에 시도한 32×32·64×64 픽셀 아트로 되돌리지 않는다.
- 배경·바닥 타원·그림자·광택·글로우·입자·문자·격자선을 넣지 않는다. 배경은 실제 alpha 투명이다.

기준 이미지는 [Mochi 원본](../Art/Characters/original-companions-v2/source/mochi-atlas.png)과
[보리 원본](../Art/Characters/original-companions-v2/source/bori-atlas.png)이다.
같은 스타일의 새 동물은 이 이미지의 선·색감·비율을 참조하고, 동물 고유의 귀·꼬리·실루엣으로 구분한다.

## 2. 실제 생성 방식과 재사용 방법

이번 원본은 내장 `image_gen`으로 생성했다. 보리는 같은 도구로 격자 정렬 수정을 한 번 요청했다.
레이어가 있는 `.aseprite` 원본은 제작하지 않았다. 제작 원본은 RGBA PNG다.

[generation.md](../Art/Characters/original-companions-v2/generation.md)에 두 캐릭터의 전체 생성
프롬프트와 보리의 수정 프롬프트가 보존되어 있다. 새 작업에서는 다음 순서로 재사용한다.

1. 기준 PNG를 열어 확인하고, 생성 도구에 스타일 참조로 제공한다.
2. 원본 프롬프트의 공통 스타일·금지 요소·격자·포즈 순서를 유지한다. 새 동물은 마지막
   `Character:` 문단에서만 종, 몸 색, 귀·꼬리 등 정체성을 바꾸는 것을 출발점으로 삼는다.
3. 한 캐릭터의 포즈 시트를 통째로 생성해 얼굴·선 굵기·몸 비율의 일관성을 맞춘다.
4. 실패한 셀은 원본을 참조한 수정 요청으로 보완한다. 새 결과는 별도 후보 파일로 보존하고 검수한다.
5. 프롬프트, 도구, 참조 이미지, 후보 이력과 최종 SHA-256을 제작 원장에 기록한다.

생성 모델의 결과는 매번 달라질 수 있다. 같은 프롬프트만으로 같은 그림을 보장하지 않는다.
**현재 팩과 완전히 동일한 결과를 적용하려면 보존된 PNG와 manifest 생성 스크립트를 재사용한다.**

## 3. 시트 규격과 포즈 배치

시트는 **1024×1536 RGBA PNG**, **4열×6행**, **셀당 256×256**, 총 24셀이다.
인덱스는 왼쪽 위를 0으로 하여 가로로 먼저 증가한다.

| 행 | 인덱스 | 생성할 포즈 |
|---|---|---|
| 1 | 0–3 | 기본 앉기, 눈 깜빡임, 왼쪽 보기, 오른쪽 보기 |
| 2 | 4–7 | 졸기, 웅크려 잠들기, 잠든 채 호흡, 하품 |
| 3 | 8–11 | 알림에 주목, 스트레칭 시작, 깊은 스트레칭, 복귀 |
| 4 | 12–15 | 기쁨, 놀람, 놀라서 왼쪽 보기, 오른쪽 보기 |
| 5 | 16–19 | 고개 돌려 삐짐, 약하게 화남, 오른쪽 걷기 두 자세 |
| 6 | 20–23 | 오른쪽 걷기 두 자세, 편안한 복귀, 기본 앉기 |

각 동물 전체가 자기 셀 안에 들어가야 한다. 셀마다 크기와 수평 중심을 유지하고, 귀·발·꼬리가
옆 셀에 들어가거나 잘리지 않게 한다. 걷기는 오른쪽을 향한 제자리 발 동작으로 만든다.
화면상의 이동 좌표와 클릭 스퀴시를 그림에 구워 넣지 않는다.

원래 생성 목표는 발 기준선 y=228, 외곽 x=28..228·y=24..230이었다. 보리 수정 프롬프트는
긴 귀를 포함한 높이 175px 이하, 발 y=220, x=24..232·y=32..222로 여유를 늘렸다.
이 값들은 생성 지시이며 실제 출력의 정렬을 보장하지 않는다. 모든 셀을 분리해 검사해야 한다.

현재 보리의 18·19번은 다음 행 귀 조각, 22·23번은 잘린 귀가 있어 참조하지 않는다.
10번은 스트레칭 방향이 달라 제외했다. 원본 PNG는 그대로 보존하고 manifest에서 안전한 셀만 쓴다.
새 시트에는 기존 제외 인덱스를 기계적으로 적용하지 말고 새 결과를 검수한다.

## 4. 행동 타임라인과 앱 모션

실제 프레임 배열의 기준은
[build-manifests.py](../Art/Characters/original-companions-v2/build-manifests.py)다.
같은 셀을 반복 참조하여 자세를 유지하는 시간을 만든다.

| 키 | 표현 / 용도 | FPS | 반복 |
|---|---|---:|---|
| `idle` | 기본 모습과 깜빡임 | 2 | 예 |
| `attention` | 스트레칭 알림에 주목 | 5 | 아니요 |
| `stretch` | 휴식 시작 시 스트레칭 | 4 | 아니요 |
| `celebrate` | 휴식 완료에 기쁨 | 6 | 아니요 |
| `click` | 놀람 → 왼쪽 → 정면 → 오른쪽 → 기본 | 5 | 아니요 |
| `sleep` | 졸기 → 수면·호흡 → 복귀 | 2 | 아니요 |
| `look` | 좌우 둘러보기 | 4 | 아니요 |
| `yawn` | 졸다가 하품 | 4 | 아니요 |
| `sulk` | 약하게 화남·삐짐 | 3 | 아니요 |
| `walk` | 제자리 걷기 | 7 | 예 |

보리는 스트레칭에 `[0,9,9,9,9,9,9,0]`, 걷기에 `[20,21,20,21]`을 쓴다.
Mochi는 스트레칭에 9·10번, 걷기에 18–21번을 사용한다.

앱이 처리하는 동작은 다음과 같다.

- 대기 조건을 만족하는 시간 20–40초마다 잠자기·두리번거리기·하품 중 하나를 선택한다.
  직전 행동의 연속 선택을 피하며 알림·다른 반응·포인터 상호작용 중에는 대기 행동을 시작하지 않는다.
- 기본 펫 5종에는 `pickup`, `held`, `land` 선택 키가 있다. 포인터 다운에 고슴도치는 공 모양으로
  말리고 나머지는 뒷목이 들린 매달린 자세로 전환한다. 누르는 동안과 드래그 중 그 자세를 유지한다.
- 포인터 업에 유지 자세로 한 번 튕긴다. 0.64초 뒤 최종 착지를 마친 다음 `land`를 재생한다.
  고슴도치는 공 상태로 튕기고 이후에만 펼쳐진다. 이동 없이 놓았다면 기존 `click` 클립으로 이어진다.
- 이전 10개 행동만 있는 확장 팩은 기존 스퀴시·들어 올림·바운스를 유지한다. 일반 커스텀 팩의
  5개 행동 계약은 그대로다. 입력 캡처 해제·숨김·펫 변경은 모션과 예약된 클릭을 취소한다.
- 스트레칭을 연속 세 번째 미루면 `sulk`를 재생한다.
- 휴식 시작 시 `stretch`를 한 번 끝낸 뒤 `walk`와 화면 이동을 연결한다. 이동은 작업 영역 안에서
  앱이 처리한다. 사용자가 완료하거나 중지하면 해당 휴식의 이동도 끝난다.

코드 근거: [OriginalCompanion](../src/Unfold.Core/OriginalCompanion.cs),
[PetWindow.Companion](../src/Unfold.Desktop/PetWindow.Companion.cs),
[PetMotion](../src/Unfold.Desktop/PetMotion.cs), [PetWindow](../src/Unfold.Desktop/PetWindow.cs).

## 5. 실행 자산에 적용하기

| 항목 | Mochi | 보리 |
|---|---|---|
| ID / 실행 폴더 이름 | `default-cat` | `bori-rabbit` |
| 현재 팩 내용 버전 | `2.0.0` | `0.2.0` |
| 원본 | `source/mochi-atlas.png` | `source/bori-atlas.png` |

원본·프롬프트·제작 원장은 `Art/Characters/original-companions-v2/`에,
실행용 `character.json`과 `spritesheet.png`는 `Assets/Characters/<id>/`에 둔다.
프로젝트가 `Assets/Characters/**/*`를 빌드·게시 출력에 복사한다.

manifest에는 `version: 1`, `renderStyle: "smooth"`,
`behaviorProfile: "unfold-original-v1"`, 위 시트 규격과 10개 행동을 지정한다.
`version: 1`은 파일 형식 버전이며 앱 버전·팩 내용 버전과 다르다.

2026-09-24 기본 펫의 추가 포즈는 [포인터 리소스 원장](../Art/Characters/pointer-interactions-v1/README.md)에
기록했다. 기존 시트 픽셀을 보존하고 두 행을 추가하므로 현재 Mochi·보리는 4×8셀,
강아지·고슴도치·펭귄은 4×6셀이다. 추가 전용 원본·전체 프롬프트·패킹 스크립트는 해당 원장을 따른다.

확장 행동의 코드 조건은 **프로필 문자열과 필수 10개 키**다. 기본 ID 여부나 제작자 인증으로
판정하는 보안 기능은 아니다. 일반 GIF/MP4 커스텀 제작기는 프로필 없이 기존
`idle`, `attention`, `stretch`, `celebrate`, `click`의 5개 행동을 유지한다.

`AnimationView`는 확장 팩에만 alpha ≥26의 경계를 사용해 수평 중심과 높이 90%의 발 기준선을
맞춘다. 원본 PNG 픽셀을 재가공하지 않으며, 자동으로 동물의 몸 비율까지 통일해 주는 것은 아니다.
클릭 변형과 좌우 반전은 `RenderTransform`으로 처리한다.

현재 두 팩을 보존된 원본으로 다시 적용할 때, 저장소 루트에서 실행한다.

```sh
python3 Art/Characters/original-companions-v2/build-manifests.py
dotnet build Unfold.slnx -c Release --no-restore
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll --validate-characters
```

첫 명령은 그림을 생성하지 않는다. 현재 두 ID의 실행 PNG·manifest·원장만 다시 쓴다.
새 동물을 추가할 때는 이 스크립트가 두 ID를 대상으로 한다는 점을 확인하고 별도 제작 폴더와
새 ID에 맞게 생성 대상을 구성한다. 기존 펫과 사용자의 설치 폴더를 덮어쓰지 않는다.
그림 교체 후 새 빌드로 앱을 재시작해 메모리에 캐시된 이전 클립이 남지 않도록 한다.

배포 파일은 새 출력 경로에 만든다. 아래 버전은 현재 원장의 값이며 그림 개정 시 별도로 올린다.

```sh
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll \
  --pack-character Assets/Characters/default-cat 2.0.0 /tmp/Mochi-2.0.0.unfoldpet
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll \
  --pack-character Assets/Characters/bori-rabbit 0.2.0 /tmp/Bori-0.2.0.unfoldpet
```

두 현재 ID는 기본 팩으로 보호된다. 이 앱에서는 별도 설치로 덮어쓰지 않고 번들에 반영한 뒤
홈에서 선택한다. 다른 ID의 설치 팩은 펫 팩 열기·미리보기·설치 흐름을 사용한다.

## 6. 검수와 재발 방지

원본/실행 PNG의 SHA-256 일치, 실제 투명도, 셀 침범, 귀·발·꼬리 잘림, 방향·크기·발 위치,
반복 이음새와 동작 종료 후 복귀를 확인한다. 기본 192px 및 확대·축소, 밝고 어두운 배경에서 본다.
클립 10초 이내·팩 디코딩 픽셀 합계 64 MiB 이내는 현재 제작 목표다.

```sh
dotnet test Unfold.slnx -c Release --no-restore
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll --review-original-pets
```

진단에는 새 빈 `UNFOLD_DATA_DIR`을 지정하거나 변수를 생략해 자동 임시 프로필을 사용한다.
실제 사용자 프로필을 지정하지 않는다. `--review-original-pets`는 로드한 펫 중
`HasOriginalBehavior`가 참인 팩을 검사한다. 현재 기본 다섯 팩이 해당한다.
새 팩을 추가할 때 진단 결과의 ID 목록과 설치 보호 ID를 확인한다.

macOS의 클릭 잔상은 원본 이미지와 별도로 확인한다. 현재 `Program.ConfigureRendering`은
Metal 대신 OpenGL 우선·Software 대체를 사용한다. 활성화된 실제 창에서 빠르게 연속 클릭하며
녹화 전체 프레임을 확인해야 한다. 일부 정지 캡처만으로는 짧은 잔상을 놓칠 수 있다.
[클릭 잔상 검증](validation/2026-09-22-pet-click-rendering.md)을 참고한다.

이번 문서 정리에서는 두 원본의 RGBA 규격, 실행 PNG와의 바이트·해시 일치, 10개 키와
타임라인을 다시 확인했다. 코드·그림을 새로 만들거나 테스트를 재실행한 작업은 아니다.
원장에 남은 사람의 최종 아트 승인 상태는 별도 관리한다.

## 7. 강아지·고슴도치·펭귄 제작의 차이

같은 스타일의 세 팩을 [original-companions-v3](../Art/Characters/original-companions-v3/README.md)에
추가했다. ID는 `puppy-dog`, `hedgehog`, `penguin`이고 각 내용 버전은 `0.1.0`이다.
앞 절의 24셀 포즈 배열과 원본·실행 PNG의 바이트 일치는 기존 보리·Mochi에 해당한다.

세 새 팩은 격자 침범이 반복되어 **16개 자세·4×4 실행 시트**로 구성했다.
최종 생성 원본 1254×1254 RGBA를 보존하고, 사용자 진행 승인 후 Pillow로 자세를
잘라서 256×256 셀에 수평 중앙·발 기준선 230px으로 정렬했다. 확대·축소나 재도색 없이
원본 RGBA를 복사한다. 10개 행동 계약과 일반 커스텀 팩의 다섯 행동은 유지한다.
잠자기·스트레칭은 한 자세를 유지하고 걷기는 네 자세를 반복한다.

원본 PNG와 실행 PNG의 해시를 각각 기록하고 잘라낸 모든 영역의 픽셀 일치를 확인한다.
정렬 스크립트의 원본 분리 좌표는 이 세 생성물에만 유효하다. 다른 그림에 재사용하기 전
셀별 실루엣과 분리 경계를 다시 검사한다. 명령은 다음과 같다.

```sh
python3 Art/Characters/original-companions-v3/build-assets.py
```
