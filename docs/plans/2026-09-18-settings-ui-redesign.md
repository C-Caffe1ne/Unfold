# 설정 탭 UI 검수 및 구현 계획

2026-09-18 · 상태: 승인된 2차 시안 구현·자동 검증 완료.

[구현 및 검증 결과](../validation/2026-09-18-settings-ui-redesign.md): Release 테스트 202개 통과,
macOS 네이티브 off-screen 진단 통과. 아래 검수 결과는 수정 전 상태이며, 구현 기준과 함께 보존한다.

## 작업 순서와 범위

사용자의 최신 지시에 따라 **UI 수정 → UI 검증 → UX 수정·구현** 순서로 진행한다.
이번 대상은 사이드바의 **설정 탭**이며, 알림 설정·타이머 설정 두 섹션과 그 안의 드롭다운,
텍스트 위계, 간격, 입력·버튼 배치를 다룬다. 이 문서가 다음 설정 UI 작업의 기준이다.

기존 차콜·크림 팔레트, 사이드바, 같은 창의 탭 전환, 페이지 상단 대형 헤더 제거는 유지한다.
입력 호버·포커스 시 배경/테두리가 바뀌지 않는 규칙, 숫자의 왼쪽·수직 중앙 정렬,
외곽 단일 테두리도 유지한다. 홈의 스트레칭 간격·휴식 시간은 설정 탭으로 옮기지 않는다.

사용자의 시안 수정 요청으로 **카드별 적용 버튼을 제거하고 페이지 하단의 취소·저장으로 통합**한다.
수정 전에는 저장을 비활성화하고, 저장된 값과 달라지면 활성화한다. 저장 유도 문구는 표시하지 않는다.
알림 효과음 사용 체크박스는 완료 알림 아래에 배치한다. 이 변경은 이번 UI 시안에 명시적으로 포함된 범위다.
자동 저장, 효과음 재생 방식, 자리 비움 판정, 다시 알림 동작과 그 밖의 새 기능은 포함하지 않는다.
일반적인 UX 후속 작업은 UI 완료 후 남은 문제를 다시 확인해 별도 계획으로 정한다.

## 제안 배치

두 카드를 세로로 배치하고 카드 상단에는 제목만 둔다. 설정 페이지 우측 최하단에 **취소 → 저장** 순서로 배치한다.
실제 앱 구현 시 이 버튼 영역은 본문 스크롤 밖의 하단 행에 두어 창 높이가 줄어도 접근할 수 있게 한다.
카드별 적용 버튼과 상시 저장 안내/수정 후 저장 유도 문구는 제거한다.
저장 실패나 잘못된 입력처럼 실제 오류를 설명하는 기능은 유지한다.

```text
알림 설정

말풍선 위치                   [위                 ⌄]  ← 200px

스트레칭 알림                 [미리듣기] [파일 가져오기] [기본]
기본 효과음

완료 알림                     [미리듣기] [파일 가져오기] [기본]
기본 효과음

[✓] 알림 효과음 사용
WAV · 최대 30초 / 5 MiB · 기존 미리듣기 안내

타이머 설정

자리 비움 시간 (분)                             [5     ∧ ∨] ← 160px
입력이 없을 때 작업 타이머를 멈춰요.

다시 알림 시간 (분)                             [5     ∧ ∨]
알림을 미룬 뒤 다시 기다릴 시간이에요.

                                               [취소] [저장]
```

승인된 배치를 제품 코드에 반영했다. 알림·타이머 설정은 하나의 저장 버튼으로 함께 저장한다.
‘파일…’ 표시는 현재 기능을 드러내는 ‘파일 가져오기’로만 바꾸고 파일 선택/검증 로직은 유지한다.
‘기본’은 보조 버튼으로 약하게 표시한다. 저장은 변경 전 차콜색 비활성, 변경 후 크림색 활성 상태로 표현한다.

### 저장·취소 상태 계약

- 처음 열거나 저장을 마친 상태에서는 저장 버튼을 비활성화한다.
- 말풍선 위치, 효과음 사용 여부, 두 효과음 파일, 자리 비움·다시 알림 시간 중 저장된 값과 다른 항목이 있으면 활성화한다.
- 값을 원래대로 되돌리면 다시 비활성화한다. 효과음 미리듣기/정지만으로는 변경 상태가 되지 않는다.
- 저장은 두 섹션의 유효한 값을 함께 저장한 후 그 값을 새 기준으로 삼는다. 저장 실패 시 초안을 보존한다.
- 취소는 미저장 변경을 마지막 저장 상태로 복원하고 현재 설정 탭을 유지한다.
- 취소는 항상 표시하며, 저장은 변경 여부와 입력 유효성을 함께 확인한다. 기존 1~60분 정수 범위를 유지한다.
- 저장 또는 파일 가져오기 처리 중에는 폼과 취소·저장을 잠시 비활성화해 처리 중인 초안이 바뀌지 않게 한다.
- 시안의 파일 가져오기는 예시 파일명을 사용하고 저장은 시안 내부 상태만 갱신한다. 실제 앱 데이터나 소리는 변경하지 않는다.

열린 목록의 행 하이라이트는 선택 위치를 보여주는 표현이다. 닫힌 입력의 호버/포커스 배경·외곽선 변경과 구별한다.

기본 1120×800과 최소 860×680을 모두 기준으로 검증한다. 글자를 줄여 억지로 한 화면에 맞추지 않는다.
최소 창이나 긴 오류 문구에서 높이가 부족하면 **본문의 세로 스크롤 하나**로 모든 항목에 접근하고 취소·저장은 하단에 유지한다.
가로 스크롤, 내부 중첩 스크롤, 잘려 보이지 않는 버튼은 허용하지 않는다.

## 구현 순서와 파일 경계

1. **UI-1: 레이아웃·위계** — SUI-02/03/04/05/07.
   `SettingsWindow.Layout.cs`의 설정 본문/타이머 카드와 `SettingsWindow.Notifications.cs`의 시각 구성만 수정한다.
   카드별 적용 버튼을 제거하고 체크박스를 이동한다. 페이지 하단에 취소·저장 영역을 만든다.
   공통 크기·서체 값은 `DesignSystem.cs`의 설정 전용 역할로 정의한다. 홈 카드와 다른 탭의 배치는 바꾸지 않는다.
2. **UI-2: 드롭다운·컨트롤** — SUI-01/06.
   같은 알림 뷰에 고정 폭/높이를 적용하고, `DesignSystem.cs`에서 설정 전용 클래스의 닫힘·펼침·선택 상태를 정리한다.
   현재 Fluent template part를 확인한 뒤 작성하며 임의의 광범위한 Border 선택자를 추가하지 않는다.
   SUI-07의 변경 상태·저장·취소 연결은 `SettingsWindow.cs`와 알림 뷰의 초안 상태에 한정해 조정한다.
3. **UI-3: 화면 검증·보완** — 기본/최소 창, 드롭다운 열림, 긴 파일명, 미리듣기/정지 라벨, 비활성,
   저장 성공/오류 표시를 캡처한다. 행과 버튼의 크기/정렬, 가로 넘침, 세로 스크롤을 확인하고 시각 회귀를 수정한다.
4. **UX 후속** — UI-1~3이 끝난 뒤 필요한 동작 변경만 별도로 검수·계획한다. 위 세 단계와 병행하지 않는다.

기존 `AppRuntime.UpdateSettings` 경로와 데이터 형식·타이머·재생 규칙을 재사용한다.
뷰의 카드별 저장 연결은 사용자 요청에 따라 페이지 단위 저장으로 교체한다. 제거하는 적용 버튼 이외의
컨트롤 Name과 파일 가져오기·재생 연결을 보존한다. `Ui.cs`를 바꿔야 한다면 설정 전용 helper에 한정한다.

## 구현 완료 확인

- 기본·최소 크기에서 알림/타이머 카드의 정렬과 여백이 제안 값과 일치한다.
- 드롭다운 닫힘/펼침/선택·마우스 진입의 실제 렌더링을 확인한다. 입력은 상태 변경 시 테두리를 다시 강조하지 않는다.
- 긴 한글/영문 파일명, 미리듣기→정지, 도움말·오류 줄바꿈에도 버튼 크기와 열 위치가 안정적이다.
- 가로 스크롤이 없고 모든 조작을 정상적으로 누를 수 있다. 높이가 부족하면 세로 스크롤로 접근한다.
- 수정→저장 활성, 원상 복원→비활성, 취소→마지막 저장값 복원, 저장→새 기준으로 갱신을 확인한다.
- 알림·타이머를 함께 저장하며 기존 설정 값 형식, 1~60분 입력 범위, 미리듣기/정지 동작에 회귀가 없다.
- 공유 스타일의 영향을 받는 홈·펫 드롭다운과 비활성 숫자 입력을 대조한다.

구현 단계에서는 `SettingsDashboardTests`, `UiAuditRegressionTests`, `DesignSystemTests`의 관련 검사를 실행한다.
폭/행 정렬/가로 넘침은 실제 배치 검사를 보강하되 시안의 숫자를 그대로 복제하는 테스트를 늘리지 않는다.
Release 빌드·전체 회귀 검사는 최종 변경 후 한 번 수행하고 새 `UNFOLD_DATA_DIR`의 macOS 진단으로 화면 근거를 남긴다.
Windows 화면을 실제로 확인하지 못했으면 macOS 결과와 구분해 보고한다.

SUI-01~07을 구현하고 이번 변경 후 새로 검증했다. 결과와 미검증 범위는
[설정 탭 UI 개편 검증](../validation/2026-09-18-settings-ui-redesign.md)에 기록했다.
일반적인 UX 후속 작업은 이번 구현 범위에 포함하지 않았다.
