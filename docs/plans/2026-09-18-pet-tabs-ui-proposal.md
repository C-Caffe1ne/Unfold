# 펫 추가 탭 UI 후속 시안

2026-09-18 · 상태: 카드 클릭 미리보기를 반영한 2차 시안 승인 후 제품 코드 적용 완료.
[구현·검증 기록](../validation/2026-09-18-pet-tabs-ui.md): Release 205개 통과, macOS off-screen 진단 통과.
아래 시안 검증은 코드 적용 전 기록이며, 실제 앱 캡처와 미검증 항목은 구현 기록에 구분한다.

## 작업 순서

사용자 요청에 따라 **검수 보고서와 현재 구현 대조 → 화면 시안 → 사용자 확인 → 제품 코드 적용 → 검증** 순서로 진행한다.
이번 제안은 펫 추가의 ‘펫 팩 열기’와 ‘펫 팩 만들기’ 두 탭에 한정한다. 일반적인 UX 기능은 UI 정리 이후에 다룬다.

[9/18 감사](../validation/2026-09-18-ui-ux-audit.md)의 12개 기능 수정 항목은
[후속 구현](../validation/2026-09-18-ui-ux-implementation.md)에 반영돼 있다.
[설정 탭 개편](../validation/2026-09-18-settings-ui-redesign.md)도 완료했다.
따라서 이번 제안은 완료된 결함을 미해결로 다시 분류하는 작업이 아니다.
감사의 UI-01·UI-02와 UX-05에서 확인한 상태 표현·작은 창 배치를 토대로 펫 화면의 시각적 일관성을 보완한다.

## 현재 화면과 후속 제안

현재 코드 `CustomPetView`는 132×132 행동 카드와 8px 간격을 사용한다. 최소 창에서 첫 줄 추가 버튼은
이미 보이지만 다섯 번째 카드는 두 번째 줄로 내려간다. 입력 위계가 대부분 12~14px이고 긴 변환 안내가
이름과 미리보기 사이에 있다. 이는 첫 파일 추가가 불가능한 결함이 아니라 밀도와 읽는 순서의 후속 개선이다.

현재 `PetPackView`의 미리보기 아래에는 배경/크기, 동작/파일 열기, 재생 설명이 나뉘어 있다.
파일을 열기 전에는 화면 상단 제목과 하단 안내가 반복되고, 넓은 미리보기에는 설명이 없다.
이번에는 조작을 가까이 묶고 빈 미리보기에 짧은 안내를 둔다.

| ID | 제안 | 구현 후 확인 기준 |
|---|---|---|
| PUI-01 | 두 내부 탭의 크기·선택선을 통일하고 본문 최대 760px, 왼쪽 정렬을 사용한다. | 설정과 본문 축·14px 항목명·12px 설명 위계가 일관된다. 큰 페이지 제목은 추가하지 않는다. |
| PUI-02 | 이름 입력 320×40px 유지. 제작 미리보기 최대 폭 520px, 높이 기본 272px/작은 창 156px. | 입력이 전체 너비로 늘어나지 않고, 미리보기 이미지와 현재 행동명이 겹치지 않는다. |
| PUI-03 | 행동 카드 128×148px, 간격 8px, 내부 패딩 10px, 아이콘 32px. | 860px 최소 창에서 다섯 카드와 추가 버튼을 한 줄에 표시한다. 파일 추가 전후 카드 크기는 같다. 필요 시 줄바꿈하며 가로 스크롤은 만들지 않는다. |
| PUI-04 | 별도 미리보기 아이콘을 제거하고 파일이 있는 행동 카드를 누르면 해당 행동을 미리본다. 선택된 카드는 테두리와 미리보기 하단 이름으로 표시한다. 긴 GIF/MP4 안내는 카드 아래 두 줄로 정리한다. | 카드에는 파일명 대신 크기·프레임·시간만 보인다. 추가·제거 아이콘은 우측 하단에 유지하며 카드 클릭과 독립적으로 동작한다. 빈 카드 클릭은 현재 미리보기를 바꾸지 않는다. |
| PUI-05 | 열기 탭 위쪽에 200px 동작 드롭다운과 우측 120px 펫 팩 열기 버튼을 묶는다. | 사용자 지정 순서와 12px 버튼 간격 유지. 파일 열기 전에는 드롭다운에 비활성 안내를 표시한다. |
| PUI-06 | 520px 미리보기 아래 중앙의 일시정지/다시 재생 아이콘을 유지한다. 배경·크기 148px 선택기를 아래에 나란히 둔다. | 실제 192/288/384px 미리보기 크기와 재생 규칙 유지. 큰 미리보기에서는 본문만 세로 스크롤한다. |
| PUI-07 | 하단 왼쪽에는 필요한 상태/오류/참고 사항, 오른쪽에는 설치 또는 만들기 주 버튼을 둔다. | 제품에서는 본문 스크롤 밖에 주 버튼·참고 사항 요약을 고정한다. 가져오기/설치/저장 실패가 정상 안내와 구별된다. |

카드의 ‘선택 · 한 번’은 기존 ‘선택 · 한 번 재생’의 좁은 카드용 표시다. 반복 여부의 의미는 바꾸지 않는다.
입력의 호버/포커스 테두리 강조 제거, 파일명 생략, 필수 쉬는 모습, 파일별 교체 확인,
다른 동작 제거 시 현재 미리보기 유지, 탭 전환 시 작성 내용 유지 계약을 보존한다.

## 시안 확인 방법과 한계

대화의 시안에서 열기·만들기 탭, 행동 카드 클릭 미리보기와 파일 추가/제거, 일시정지/다시 재생, 배경과 크기를 전환할 수 있다.
시안 옵션에서는 기본/최소 창 배치, 빈 화면·파일 입력·참고 사항·오류 상태, 본문 폭 760/720px를 비교한다.
추천 기본값은 최소 창 배치와 760px 본문이다.

‘+’와 ‘펫 팩 열기’는 예시 상태를 불러오며, ‘만들기’와 ‘설치’는 시안 안의 표시만 바꾼다.
사용자 파일을 읽거나 앱 데이터를 저장하지 않는다. 펫은 기존 macOS 캡처를 사용한 정적 예시이고,
192×192·24프레임·2초는 카드 배치 확인을 위한 예시값이다. 실제 애니메이션 품질을 검증한 결과가 아니다.

대화에서는 긴 상태를 펼쳐 보여주므로 최소 창의 팩 정보·큰 이미지·참고 사항에 따라 시안의 높이가 늘어날 수 있다.
제품 적용 시에는 기존 본문 세로 스크롤과 고정 하단을 사용해 860×680 경계를 지켜야 한다.
320~736px 재배치는 대화의 좁은 화면에서 시안을 읽기 위한 것이며 앱의 최소 창 크기를 변경하는 제안이 아니다.

## 코드 적용 전 시안에서 확인한 결과

- 로컬 브라우저에서 탭, 카드 클릭 미리보기와 독립적인 추가·제거, 빈 카드 클릭, 이름 유지, 생성 후 열기 전환, 재생 버튼과 설치 예시를 확인했다.
- 파일 추가 전후 다섯 카드의 위치와 크기가 같고, 860×680 제작 시안에 다섯 카드가 모두 표시된다.
- 빈 상태·오류·참고 사항, 기본 1120px 및 좁은 대화 화면의 가로 넘침을 검사했다.
- 검사 결과와 캡처는 [시안 검증 JSON](../validation/2026-09-18-pet-ui-proposal.json)에 기록한다.
- 시안 단계에서 제품 코드·테스트·리소스의 작업 전후 해시를 비교했다. 당시에는 .NET 테스트나 네이티브 앱 검증을 다시 실행하지 않았다.

## 승인 후 구현 경계

1. `PetManagementView.cs`: 탭 외형과 콘텐츠 축.
2. `CustomPetWindow.cs`: 이름·미리보기·행동 카드·안내·하단 배치. 초안과 파일 처리 로직은 보존한다.
3. `PetPackWindow.cs`: 동작/열기 행, 팩 정보, 미리보기 옵션, 빈 화면과 상태 배치. 설치/재생 동작은 보존한다.
4. `DesignSystem.cs`: 펫 페이지에 한정한 토큰/클래스. 이미 승인·적용된 설정 화면의 값은 변경하지 않는다.
5. 관련 레이아웃 회귀 검사와 새 데이터의 macOS 진단으로 860×680, 1120×800, 긴 이름/오류,
   배율 100/150/200%, 버튼 고정, 파일 전후 카드 크기를 확인한다. Windows 실기는 별도로 기록한다.

펫 페이지 적용과 검증을 마친 후 홈의 위계·간격, 기록/말풍선의 밀도를 현재 화면으로 다시 검수한다.
후속 화면도 시안을 먼저 보여주며, 이번 문서가 해당 화면의 코드 수정을 승인하는 것은 아니다.
