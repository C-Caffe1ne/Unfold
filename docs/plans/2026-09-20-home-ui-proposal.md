# 홈 화면 UI 검수와 수정 시안

2026-09-20 · 상태: 2차 시안 사용자 승인 및 제품 코드 적용 완료.
[구현·검증 결과](../validation/2026-09-20-home-ui-implementation.md): Release 207개 통과, 기본·최소 창 렌더링 확인.

## 기준과 현재 상태

`release/mvp`, `0b72a36`의 C#·Avalonia 구현과 새 격리 프로필의 macOS 렌더링을 확인했다.
[개발 순서](../development-plan.md)에 따라 설정·펫 추가 다음으로 홈을 검수한다.
사용자가 정한 **검수 → 시안 → 사용자 확인 → 코드 적용 → 검증** 순서를 따른다.
아래 검수·시안 단계의 근거는 승인 전 기록이다. 이후 사용자 요청 “이 시안 적용하고 작업 계속 진행해줘”에
따라 홈 코드·회귀 검사를 수정했다. 펫 리소스와 기록·말풍선 제품 코드는 수정하지 않았다.

[9/18 감사](../validation/2026-09-18-ui-ux-audit.md)의 ‘스트레칭 시간’ 명칭과 작은 시간 설명은
현재 ‘스트레칭 알림 간격 (분)’·12px 설명으로 개선돼 있다. 휴식 대기·진행 상태도 이미 분리됐다.
이를 미해결 기능 오류로 다시 분류하지 않는다. 이번 발견은 홈의 남은 시각적 일관성에 관한 P3 개선이다.

## 2차 시안의 배치와 유지할 동작

- 사용자 요청으로 가운데의 위아래 순서를 **타이머 위·펫 아래**로 바꾼다. 오른쪽은 시간 설정 위·오늘 기록 아래를 유지한다.
- 타이머와 시간 설정의 윗선을 맞춘다. 데스크톱 시안의 타이머 높이는 196px로 고정하고 펫 영역이 남은 높이를 채운다.
  최소 창·긴 이름에서는 펫 미리보기부터 축소하며 타이머의 재생/중지 버튼은 상단에 유지한다.
- 내비게이션과 네 카드의 나머지 디자인·동작은 1차 시안을 유지한다. DOM 순서도 타이머→펫으로 바꿔 시각 순서와 키보드 순서를 맞춘다.
- 기본 창 1120×800, 최소 창 860×680, 오른쪽 상세 영역의 필요 시 세로 스크롤을 유지한다.
- 큰 페이지 헤더, 루틴·프로필 UI, 타이머 초기화 버튼, 펫 추가 버튼을 홈에 다시 넣지 않는다.
- 알림 간격 5~240분·휴식 1~10분, 1분 단위, 진행 중 알림 간격 잠금과 다음 휴식 적용 규칙을 유지한다.
- 홈의 **적용** 버튼과 현재 저장 동작은 유지한다. 설정 탭에서 승인한 취소·저장 동작을 홈에 임의로 옮기지 않는다.
- 일시정지는 남은 시간 유지, 중지는 00:00, 중지 후 재생은 저장된 간격으로 시작하는 동작을 유지한다.
- 펫 표시·로그인·기록의 데이터 저장 방식, 실제 애니메이션·알림·효과음은 변경하지 않는다.

## 시안 확인

대화의 시안에서 재생/일시정지·중지, 숫자 증감과 적용, 펫 선택·체크박스를 눌러 볼 수 있다.
시안 옵션은 기본/최소 창, 타이머 여섯 상태, 카드 간격 20px/16px, 빈 기록/완료 예시,
긴 펫 이름, 저장·기록 오류 표시를 비교한다. 추천값은 카드 간격 20px다.

시안의 펫은 이번 네이티브 캡처를 재사용한 정적 이미지다. 24:38 및 3회·9분 20초는 배치 확인용 예시이며
실제 기록이 아니다. 실제 시간 경과·파일 저장·로그인 등록을 실행하지 않는다.
펫 선택 예시는 같은 이미지를 사용한다. 바탕화면 표시 체크는 홈 미리보기를 숨기지 않는다.
기록 버튼은 기록 화면 이동 대신 시안 안내만 표시하며, 내비게이션은 위치 확인용이다.

대화 화면이 앱 최소 폭보다 좁으면 시안의 카드가 아래로 재배치된다. 이는 시안을 읽기 위한 대응이며
실제 앱을 모바일 레이아웃으로 바꾸는 제안이 아니다. 시안의 숫자 필드와 팝업은 브라우저 표현이므로
Avalonia에서의 실제 입력 렌더링은 코드 적용 후 별도로 확인한다.

## 확인한 결과

- 현재 제품 Release 빌드: 종료 코드 0, 경고·오류 0.
- 새 `UNFOLD_DATA_DIR`의 macOS off-screen 진단: 종료 코드 0, `success: true`, PNG 46장.
  이는 현재 앱의 기준 화면·동작 확인이며 제안된 새 UI가 제품에서 통과했다는 의미가 아니다.
- 브라우저 시안: 일시정지 때 간격 편집 가능, 1분 증가 후 적용, 중지 00:00, 재시작,
  진행 중 휴식 시간 적용과 펫 선택을 확인했다.
- 기본 시안 1120×800, 최소 시안 860×680, 두 줄 이름·저장 오류의 860×680 배치를 확인했다.
  좁은 대화 화면에서는 입력 폭이 카드 경계를 넘지 않도록 보완했다.
- 검증 수치와 소스 변경 여부는 [검증 JSON](../validation/2026-09-20-home-ui-proposal.json)에 기록한다.
- 2차 시안은 기본·최소·긴 이름/저장 오류에서 타이머 상단 31px·높이 196px, 펫 시작 247px를 확인했다.
  기본 창의 펫 하단은 769px, 최소 창은 649px다. 좁은 대화 화면에서도 타이머가 펫보다 먼저 나오고 가로 넘침이 없다.
  재생/중지 버튼 순서·일시정지·00:00 표시와 브라우저 오류 없음도 확인했다. 수치는 JSON의 `timerFirstRevision`에 추가했다.
  이 재배치 단계에서는 제품 소스 94개 파일의 변경이 없음을 확인하고 네이티브 빌드·진단을 반복하지 않았다.
- 제품 소스 수정이 없으므로 이번 시안 단계에서 전체 .NET 테스트를 반복하지 않았다.
  이전 205개 통과 기록은 [펫 UI 구현 검증](../validation/2026-09-18-pet-tabs-ui.md)의 결과다.

## 승인 후 구현 순서와 경계

1. `SettingsWindow.Layout.cs`: 가운데 행을 타이머 고정 높이→간격→펫 가변 높이로 바꾸고, 홈 네 카드의 서체·간격·고정 입력 크기와 펫 옵션 정리.
2. `SettingsWindow.cs`: 기존 상태를 배지 제목·설명에 연결. 저장·타이머 전이 조건은 유지.
3. `DesignSystem.cs`: 홈 전용 클래스/필요 토큰만 추가. 이미 적용한 설정·펫 탭의 외형과 입력 계약 보존.
4. 관련 `SettingsDashboardTests`, `TimerControlTests`, `SmokeDiagnostics`에서 최소 창, 긴 이름/오류,
   상태 여섯 종류, 타이머 조작, 입력 잠금·시간 적용을 검증. 기존 기록·설정·펫 탭 회귀도 확인.
5. 승인 후 빌드·관련 테스트·통합 Release 검사와 새 데이터의 macOS 렌더링을 실행하고 구현 보고서 작성.

Windows 실기, OS 배율 125/150/200%, 다중 모니터, 실제 OS 입력·파일 선택과 사용자 체감은 미검증이다.
음성 낭독 기능을 추가하지 않는다. 홈 코드 적용 이후 기록/말풍선 UI도 별도 시안으로 검토한다.
