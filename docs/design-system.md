# Unfold 디자인 시스템

2026-09-14 · 차콜 바탕, 크림색 강조, 둥근 프레임으로 설정 화면과 그 안에서 열리는 창을 연결한다.
화면마다 색상과 버튼 상태를 다시 정의하지 않고 공통 토큰과 컴포넌트를 사용한다.

## 시각 규칙

| 역할 | 값 | 사용 위치 |
|---|---|---|
| 바탕 `Canvas` | `#141713` | 창의 바탕 |
| 프레임 `Shell` | `#1D201D` | 페이지 외곽 프레임 |
| 카드 `Surface` | `#2B2F2A` | 입력 그룹, 기록, 확인 메시지 |
| 보조 표면 `Raised` | `#363C33` | 보조 버튼, 펫·요약 카드 |
| 주요 글자·강조 `Cream` | `#DFE5D1` | 제목, 주요 버튼 바탕, 선택 강조 |
| 강조 위 글자 `Ink` | `#252A23` | 크림색 버튼의 글자·아이콘 |
| 설명 `Muted` | `#B6BEB0` | 필드 이름, 도움말, 상태 설명 |
| 경계 `Outline` | `#444B40` | 프레임, 하단 작업 영역, 조용한 버튼 |
| 오류 `Error` | `#FFB4A3` | 저장 오류, 삭제 동작 |
| 참고 `Warning` | `#E5C58C` | 일시정지·자리 비움 상태, 펫 팩 미리보기 참고 사항 |

본문은 14, 설명은 12, 페이지 제목은 24 논리 픽셀이다. 설정 대시보드는 정보 밀도에 맞게
11~12 크기의 설명과 48·64 크기의 기록·타이머 숫자를 사용한다. 시스템 기본 글꼴과
한국어 글꼴 대체를 유지한다. 제목과 긴 안내는 줄바꿈하고, 입력 필드에는 접근성 이름 또는
연결된 레이블을 둔다.

기본 간격은 8, 항목 간격은 12, 페이지 안쪽 여백은 20이다. 카드 안쪽은 16,
페이지 바깥 여백은 12를 쓴다. 모서리는 컨트롤 12, 카드 24, 외곽 프레임 32다.
설정 대시보드의 조형 카드와 세로 바로가기 막대는 기존 22~64 모서리를 유지한다.
펫 팩 진단 창의 페이지 안쪽 여백은 16이다. 스트레칭 알림은 펫 창의 말풍선으로 표시한다.

## 공통 컴포넌트

| 컴포넌트 | 규칙 |
|---|---|
| `Ui.Page` | 브랜드·페이지 제목 → 스크롤 본문 → 구분선·하단 작업 영역. 본문이 길어져도 하단 버튼과 저장·설치·내보내기 결과는 창 안에 남는다. |
| `Ui.Card` | 같은 설정이나 정보를 한 그룹으로 묶는다. |
| `Ui.Field` | 설명과 입력을 6 간격으로 연결하고 접근성 레이블을 설정한다. |
| `Ui.Actions` | 오른쪽 정렬, 버튼 간격 8. 가로 공간이 부족하면 다음 줄로 배치한다. |
| `Ui.Primary` | 저장·적용·설치·휴식 시작처럼 해당 작업을 완료하는 동작. 크림색 바탕과 어두운 글자를 쓴다. |
| 일반 버튼 | 편집·새 항목·이전·다음처럼 계속 탐색하는 동작. 명도가 다른 차콜 바탕을 쓴다. |
| `Ui.Quiet` | 취소·닫기·새로고침처럼 강조를 줄이는 동작. 투명 바탕과 경계선을 쓴다. |
| `Ui.Danger` | 삭제 동작을 오류 색상의 글자로 구분한다. |
| 아이콘 버튼 | 타이머 44×44, 바로가기 46×46. 한국어 접근성 이름과 500ms 도구 설명을 유지한다. |
| 타이머 상태 배지 | 8px 상태 점과 상태·동작 설명을 함께 표시한다. 진행은 `Cream`, 일시정지·자리 비움·휴식은 `Warning`, 정지는 `Error`를 사용한다. |

일반 버튼의 최소 높이는 38이다. 호버·누름 상태는 실제 버튼 표면에 적용하고,
비활성 상태는 낮은 명도와 불투명도 0.55로 구분한다. 키보드로 접근하면 경계선으로 포커스를
표시한다. 입력·목록·탭·진행 표시줄의 선택 강조도 같은 Fluent 팔레트를 사용한다.

텍스트·숫자·선택 입력 필드는 호버와 포커스 때 배경·테두리 색과 두께가 바뀌지 않는다.
템플릿 내부 테두리의 배경도 고정하며, 숫자 입력의 안쪽 텍스트칸은 투명하게 유지한다.
숫자 입력의 값은 왼쪽에 놓고 수직 중앙을 유지한다. 화살표 버튼의 호버 배경도 고정하고,
오른쪽 끝의 아래 화살표에 위·아래 모서리 곡률을 적용해 입력 테두리와 맞춘다.
입력 포커스와 키보드 조작은 유지하며, 텍스트 선택과 커서는 그대로 표시한다.
비활성 숫자 입력은 바깥 `NumericUpDown`만 반경과 1px 테두리를 그린다. 내부 TextBox는
반경 0과 투명 배경을 유지하고, 화살표 표면은 외곽과 같은 배경·오른쪽 반경을 사용해
컨트롤 사이 틈이나 테두리 밖의 다른 배경이 드러나지 않게 한다.

삭제 확인에서는 취소에 먼저 포커스를 두고 삭제를 기본 Enter 동작으로 지정하지 않는다.
확인 창의 제목 표시줄을 닫으면 취소 결과를 반환한다. 이름 입력 창은 기존 값 전체를 선택하고,
저장·취소 및 오류 창도 같은 페이지 프레임을 사용한다.

## 적용 화면

| 화면 | 공통 적용 내용 |
|---|---|
| 설정 대시보드 | 공통 팔레트·버튼 상태·입력 컨트롤, 기존 펫·타이머·보조 카드 배치 |
| 내 루틴 편집 | 단계별 카드, 500×700 창, 저장·취소와 검증 오류를 하단에 고정 |
| 업무 프로필 편집 | 이름·간격·자리 비움·루틴 입력 그룹, 저장·취소와 검증 오류를 하단에 고정 |
| 루틴·프로필 라이브러리 | 선택 목록·탭, 선택한 탭의 새 항목·편집·적용·삭제와 닫기를 하단에 고정 |
| 기록·내보내기 | 요약·날짜별 기록 카드, 하단 CSV 내보내기·닫기 |
| 펫 추가 | 설정 본문의 열기·만들기 탭, 하단 설치·생성 버튼 고정. 192·288·384 미리보기 크기 유지 |
| 펫 말풍선 | 펫과 같은 창에 둥근 말풍선·방향별 꼬리, 시작·미루기 또는 타이머 아래 완료 버튼 |
| 중첩 확인·이름 입력·오류 창 | 동일한 프레임·카드·작업 버튼과 취소 규칙 |

이 범위는 앱이 그리는 UI다. OS 파일 선택기·알림·트레이 메뉴의 외곽과 제목 표시줄은
운영체제 표현을 따른다. 일반 MVP에서 진입하지 않는 진단용 픽셀 에디터는 공통 테마·버튼·
대화상자를 사용하지만 편집 도구 배치를 재설계하지 않았다. 펫 이미지와 리소스 계약은 유지한다.

## 구현 위치와 확장 방법

- [Figma 디자인 시스템](figma-design-system.md): 편집 가능한 시각 원본, 변수·Variant 구성과 로컬 빌더 사용법.
- [DesignSystem.cs](../src/Unfold.Desktop/DesignSystem.cs): 색상·서체 크기·간격·모서리와 Fluent 팔레트, 버튼 상태.
- [Ui.cs](../src/Unfold.Desktop/Ui.cs): 페이지·카드·필드·작업 영역과 확인·오류·이름 입력 창.
- [SettingsWindow.Layout.cs](../src/Unfold.Desktop/SettingsWindow.Layout.cs): 설정 대시보드의 전용 배치.
- 앱과 headless 테스트는 모두 `DesignSystem.Install`로 같은 테마를 설치한다.

새 창은 `Ui.Page`로 구성하고 본문과 하단 동작을 별도로 전달한다. 새 버튼은 `Ui.Button` 또는
`Ui.AsyncButton`으로 만들고 의미에 따라 `Primary`·`Quiet`·`Danger`를 적용한다. 새로운 색상이나
상태 규칙이 필요하면 먼저 공통 토큰을 갱신한다. 폼과 저장·타이머·설치 로직은 분리한다.
