# Unfold Cat MVP 방향 및 비즈니스 모델 초안

2026-09-13 · `release/mvp` 현재 체크아웃 기준 · **유료 가치 개발 방향으로 갱신한 가설**
2026-09-22 · 상품을 **단일 유료 앱 + 3일 무료 체험**으로 변경 (4·6장과 결론)

상품 구성은 ‘캐릭터 팩만 검증’ → ‘개인화 Plus + 펫 팩’을 거쳐 현재
**단일 유료 앱 + 3일 무료 체험**으로 정리했다. 자세한 상품 구성은
[제품 방향](product-direction.md), 실제 구현은 [MVP 범위](mvp.md)에 있다.
시장 규모, 실제 잔존율, 지불 의사, 전환율, 획득 비용은 아직 **미확인**이다.

## 1. 현재 방향 재확인

| 구분 | 확인된 사실과 그 의미 |
|---|---|
| 제품 | Windows/macOS의 C#·Avalonia 데스크톱 휴식 동료. 작업 시간에 맞춰 초대 창을 열고, 사용자가 루틴을 시작하면 Mochi가 기지개를 켠다. [MVP 범위](mvp.md), [README](../README.md) |
| 사용 경험 | 트레이/메뉴바 타이머, 유휴 시 일시 정지, 일시정지·정지·리셋, 펫 표시·숨김, 기본 휴식 루틴, 미루기·건너뛰기·확인 완료와 로컬 기록을 제공한다. 실제 신체 활동과 사용 지속성은 별도 관찰이 필요하다. [MVP 범위](mvp.md) |
| 자산 | 기본 제공 캐릭터는 Mochi 하나다. 기존 로컬 캐릭터를 불러오고 `.unfoldpet` 파일을 미리보기·설치·갱신·재설치할 수 있다. 일반 사용자용 제작·삭제 UI와 결제·계정 구매 복원은 없다. [팩 안내](pet-packs.md), [MVP 범위](mvp.md) |
| 출시 준비 | 자동 테스트 및 macOS의 제한된 실사용 기록은 있다. Windows 실기 결과, 양 OS의 장시간 사용·로그인·알림·실제 다운로드 파일 신뢰 확인은 남아 있다. macOS 공개 배포용 서명·공증도 별도 작업이다. [검증 안내](verification.md), [플랫폼 안내](cross-platform.md) |

**방향 판단 — 유지하며 검증.** Unfold의 핵심은 기능이 많은 운동 앱이 아니라,
책상에서 오래 일하는 사람이 귀여운 동료의 신호를 보고 짧게 몸을 움직이도록 돕는
경험이다. “부드럽게 환기한다”는 포지셔닝은 아직 가설이다. 휴식 초대 창과 시스템
알림이 집중에 미치는 영향은 실제 사용으로 확인해야 한다. Mochi의 기지개는 사용자가
휴식을 시작할 때 재생한다. Garden 실험이나 에디터 확장은 이 BM의 전제가 아니다.

## 2. 고객과 가치 제안

- **첫 고객 가설:** 하루 대부분을 PC에서 일하고, 기존 휴식 알림을 무시하거나
  끄지만 작은 시각적 동료는 좋아하는 개인 사용자. 개발자·디자이너·글쓰기
  종사자는 모집 가능한 초기 집단이며, 전체 시장 규모를 대표하지 않는다.
- **해결할 일:** 작업 흐름을 지나치게 끊지 않으면서 휴식 시점을 알아차리고
  실제로 한 번 기지개를 켜기. 의료 효과나 통증 치료는 약속하지 않는다.
- **제안 문구:** “Mochi와 잠깐 쉬고, 내 리듬으로 돌아오세요.”
- **차별화 가설:** 정확한 타이머 자체보다, 화면에 머무는 오리지널 캐릭터와
  휴식 순간의 연결이 알림 수용성과 재사용을 높일 수 있다. 사용자 관찰 전에는
  경쟁 우위로 확정하지 않는다.

## 4. 권장 BM과 보류할 선택

**상품은 Unfold 앱 하나다.** 타이머, 휴식 루틴, 말풍선 알림, 펫 표시·크기, 테마 4종,
기록·7일 회고·CSV 내보내기, 펫 팩 설치와 커스텀 펫 제작을 모두 포함한다.
기능으로 과금 경계를 나누지 않는다. **$12.99와 $14.99**를 비교할 가설로 둔다.

**무료 체험은 3일이다.** 설치 후 3일간 전체 기능을 쓰고, 이후 결제 안내를 표시한다.
체험 시작 시각은 계정·기기 조합으로 서버에 고정해 재설치 초기화를 막는다. 체험이
끝나도 기존 설정·완료 기록·설치된 펫 파일은 지우지 않는다. 오프라인이나 서버 장애가
결제한 사용자의 앱 실행을 막지 않게 한다.

**Free/Plus 분리를 폐기한 이유.** 원래 Plus의 네 축 가운데 루틴 라이브러리와 업무
프로필은 2026-09-17에 UI를 제거했고, 방해 상황별 제어는 미구현이다. 남은 회고·내보내기
하나만으로는 무료 대체재 대비 지불 이유가 약하다. [호환 안내](personalization.md)

**펫 팩 판매는 후순위로 미룬다.** 로컬 팩 설치·갱신·같은 버전 재설치는 구현했지만
판매 승인된 신규 아트가 0종이고, 구매 권한 확인과 계정 구매 복원도 없다. 기본 캐릭터
Mochi는 원본·권리가 미확인 상태이며, **유료 앱에 번들하기 전에 권리 정리가 선행돼야 한다.**
리소스 제작과 출시 기준은 [펫 리소스 관리](pet-resources.md)를 따른다.

구독은 정기 제공 가치가 현재 없고 운영·결제 부담을 늘리므로 채택하지 않는다.
팀용 관리자 기능, 광고, 의료·웰니스 성과 판매도 현재 제품·증거와 맞지 않는다.
무료 오픈소스 대체재가 같은 기능 범위를 다루므로, 체험 전환율이 확인되기 전에는
이 가격을 매출 전망으로 쓰지 않는다.

## 5. 판매 경로와 비용 구조

처음에는 10~20초 실제 동작 영상, 명확한 OS 지원 범위, 가입 후 3일 체험 다운로드,
간단한 피드백 창구가 있는 소개 페이지로 테스트한다. 배포 채널은 실제 다운로드 파일의
설치·신뢰 테스트 후 결정한다. macOS 직접 배포에는 Developer ID 서명·공증 준비가
필요하며, [Apple Developer Program](https://developer.apple.com/support/compare-memberships/)은
연 $99(또는 현지 통화)라고 안내한다. 현재 번들은 기본적으로 ad hoc 서명이고
공증을 수행하지 않는다. [플랫폼 안내](cross-platform.md)

초기 유입은 실제 작업 화면에서 Mochi가 스트레칭하는 짧은 영상과 검색 가능한
소개 페이지를 중심으로 시험한다. 개인 채널과 해당 사용자가 모인 개발·디자인
커뮤니티에서 각기 다른 링크를 써서 유입을 구분한다. 커뮤니티의 게시 규칙을
따르고, 유료 광고는 가입·설치·체험 완주의 기초 수치가 잡히기 전에는 집행하지 않는다.
다운로드 수보다 **실제 실행과 다시 켠 사용자 수**를 채널별로 비교한다.

앱 1건의 단위 경제를 아래 식에 대입해 판단한다. Lemon Squeezy 수수료, 간접세, 환불,
계정·DB·바이너리 호스팅, 서명·공증, 고객지원은 채널 확정 전까지 **미확인**으로 둔다.

```text
앱 1건 공헌이익 = 표시 가격 - 간접세 - 결제 대행 수수료 - 예상 환불 손실 - 건별 지원비
월 고정비 = 계정·DB·바이너리 호스팅 + Apple Developer Program 월분 + 코드 서명 월분
월 목표 잔여액에 필요한 판매량 = (월 목표 잔여액 + 월 고정비) / 앱 1건 공헌이익
필요한 체험 시작 수 = 월 목표 잔여액에 필요한 판매량 / 체험 완주 대비 결제 전환율
```

예를 들어 표시 가격 $12.99에서 공헌이익이 **가정상** $10이고 월 고정비가 **가정상**
$30이면, 월 목표 잔여액 $0 기준으로 고정비 회수에 3건이 필요하다. 이는 예측이 아니라
원가·전환율을 채워 넣을 계산 예시다. 월 목표 잔여액도 사용자가 정하기 전까지
임의의 시장 전망으로 만들지 않는다. 펫 팩을 판매하게 되면 팩별 제작비와 공헌이익을
같은 방식으로 따로 계산한다.

## 6. 가장 싼 검증 순서와 판정

| 단계 | 할 일 | 기록할 증거와 다음 판단 |
|---|---|---|
| 0. 사용 가능성 | 서명·공증을 마친 Windows/macOS 게시 파일로 설치·알림·idle/sleep·펫 입력·60~90분 사용을 확인한다. | 재현된 실행 장애 또는 과도한 방해가 있으면 유입 실험 전에 핵심 경험을 고친다. 현재 미검증 항목은 [검증 안내](verification.md)를 따른다. |
| 1. 핵심 가치 | 초기 고객 가설에 맞는 20명 안팎에게 3일 체험을 쓰게 하고 첫 자동 알림 이해 여부, 실제 스트레칭 여부, 체험 중 자발적 재실행, 알림 끔/제거 이유를 묻는다. | 서버 분석 기능은 없다. 동의받은 사후 인터뷰와 사용자가 제공한 로컬 완료 기록을 구분해 보관한다. 모집 편향과 자기 보고 한계를 적는다. |
| 2. 포지셔닝 | 같은 실제 제품 영상으로 ‘Mochi와 함께 쉬기’와 ‘스트레칭 알림’을 비교하고 유입 경로별 가입·다운로드·첫 실행·체험 완주를 기록한다. | 클릭 수만으로 제품 가치를 판정하지 않는다. 메시지별 유입 대비 실제 사용을 비교한다. |
| 3. 지불 의사 | 체험 만료 화면에서 실제 결제를 받는다. $12.99와 $14.99를 기간을 나눠 비교한다. | 가입 수가 아니라 **체험 완주 대비 결제 비율**을 본다. 실제 결제·환불·지원 비용으로만 가격을 확정한다. |

실험 전 판정선을 정한다. **초기 운영 기준안**은 적격 사용자 20명 중 12명 이상이
첫 자동 알림의 의미를 이해하고, 10명 이상이 3일 체험 중 하루 이상 자발적으로 앱을
다시 실행하며, 3명 이상이 체험 만료 후 실제로 결제하는 것이다. 작은 표본의
의사결정 기준일 뿐 통계적 시장 추정치가 아니다. 첫 두 조건이 안 되면 가격·결제보다
알림·펫 경험을 먼저 고친다. 세 번째만 안 되면 체험 길이와 가격을 조정하고, 그래도
안 되면 무료 배포로 되돌려 사용 데이터를 먼저 모은다.

체험 3일은 사용자가 정한 길이다. 확인된 경쟁 제품의 체험은 3일(MicroJoyz, Pausitive)과
14일(Viraam)로 갈린다. 짧은 체험은 결제 시점을 앞당기지만 ‘며칠 켜 두고 실제로 쉬게
되는가’를 관찰할 구간이 줄어든다. 전환율이 낮게 나오면 체험 길이를 먼저 의심한다.

## 현재 결론

**BUILD + TEST:** 짧은 루틴과 펫이 연결된 경험을 3일 체험으로 열고, 단일 유료 앱의
실제 결제로 지불 의사를 검증한다. 계정·체험·결제는 아직 구현하지 않았다.
후속 범위와 완료 조건은 [개발 계획](development-plan.md)에 두며,
실제 유료 전환·판매 계약·외부 배포는 완료됐다고 간주하지 않는다.
결제를 열기 전에 **Mochi 권리 정리, macOS 공증, Windows 코드 서명,
Windows 실기 검증**이 선행돼야 한다.
