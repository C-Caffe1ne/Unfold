# 펫 호버 제거와 모션 복귀 검증

2026-10-09 로컬 구현. 커밋·설치 앱 교체·공개 배포는 수행하지 않았다.

## 기준과 범위

작업 전 worktree별 브랜치·HEAD·미커밋 변경·프로젝트 버전과 커밋 관계를 비교했다. 기준은 `/Users/hwanghyeonseong/Documents/GitHub/Unfold/.worktrees/remove-unused-features`, `codex/remove-unused-features`, HEAD `4858b28`, `1.1.2-beta`다. 최신 로컬 배포 태그 `v1.1.2-beta`의 소스 `ce86c7b`보다 문서 커밋 두 개 앞선 상태였다.

기존 GLB XYZ 방향 설정과 내비게이션 이름 표시 변경을 보존했다. GLB 미리보기 회전의 성능 개선은 사용자 지시에 따라 후속 작업으로 남겼다. GLB 렌더러·미리보기 컨트롤·회전 관련 제품 코드와 내비게이션 파일의 기존 diff가 이번 작업 전과 동일함을 대조했다. 공통 행동 목록에서 호버를 없애는 데 필요한 GLB 편집 검사·문서만 함께 갱신했다.

## 변경과 원인

- 펫 진입·이탈·이동에서 호버 상태나 `hover` 모션을 재생하는 처리를 제거했다. 시간·남은 시간 호버 말풍선도 제거했다. 스트레칭 알림·휴식 타이머·시작·미루기·완료는 유지한다.
- 기본 다섯 펫, 원본 행동 프로필을 가진 팩, GIF/이미지/MP4 기반 커스텀 팩, GLB가 같은 호버 제외 규칙을 사용한다. 행동 편집은 커스텀 7개·GLB 13개다. 기존 팩의 `hover` 데이터는 계속 읽고 보존하지만 편집·미리보기 목록에서는 제외하고 런타임에서 재생하지 않는다.
- 걷기와 자동 대기 행동의 차단 조건에서 `IsPointerOver`를 제거했다. 기존에는 투명 창이나 펫에 포인터가 들어오면 걷기 재생·이동을 중단하고 대기 행동도 시작하지 않았다. 실제 누름·드래그·모션 전환·열린 메뉴 동안의 입력 처리는 유지한다.
- 입력 영역은 현재 프레임의 `OpaqueAt(..., includeEdgeTolerance: false)`를 계속 사용한다. 투명 픽셀·구멍·여백·숨겨진 말풍선·꼬리는 입력을 받지 않는다. 표시 중인 알림 버튼 영역과 드래그 캡처·메뉴는 입력을 유지한다. 호버 말풍선을 없애서 배경 포인터에 따른 별도 상태 전환도 없어졌다. 창은 알림용 여백을 예약하지만 그 여백이 펫 입력 영역이 되지는 않는다.
- 한 번 재생하는 2D 걷기가 마지막 프레임에 멈추던 문제를 수정했다. 종료 후 기본 대기로 돌아가는 처리가 GLB에만 적용돼 있었다.
- 클릭 모션이 없는 펫에서 누름을 해제할 때, 이미 완료된 모션의 기본 대기 복귀가 취소된 채 남을 수 있던 문제를 수정했다. 클릭 모션이 없으면 기본 동작으로 복귀한다.
- 새 모션을 읽는 중 이전 모션이 끝나면 새 모션의 완료까지 처리되던 경합을 수정했다. 새 프레임을 읽고 해당 재생을 시작할 때 완료 이벤트를 구독한다.

모션의 명시적인 반복 설정은 유지한다. 의도적으로 반복하도록 지정한 행동을 임의로 한 번 재생으로 변경하지 않는다.

주요 제품 변경은 `PetWindow.cs`, `PetWindow.Input.cs`, `PetWindow.Companion.cs`, `PetWindow.PointerArt.cs`, `PetSpeechBubble.cs`, `CustomPetDraft.cs`, `GlbPetDraft.cs`, `CharacterLibrary.cs`, `PetPackWindow.cs`다. 호버 전용 크기 상수와 진단의 시계 검사도 갱신했다.

## 실제 macOS 입력과 재생

최신 제품 프로젝트를 참조하는 임시 검증 앱을 사용했다. 매 실행에 새 데이터 폴더를 사용하고 기본 Mochi 및 실제 `Kazusa.glb`를 격리 라이브러리에 설치했다. 검증 앱에서만 offscreen 진단 모드를 해제해 제품의 실제 NSWindow·포인터 조회·입력 통과·걷기를 활성화했다. 제품의 계정·권한 설정은 변경하지 않았다.

CUA의 실제 키보드 입력으로 포인터를 움직이지 않고 휴식을 시작하고, 100ms 간격으로 프레임·재생 상태·창 위치·네이티브 포인터·입력 판정을 기록했다.

- Mochi에서 포인터 진입 상태를 유지한 스트레칭은 0~8 프레임을 진행하고 걷기로 전환했다. 실제 펫 픽셀 위 네이티브 포인터가 잡힌 스트레칭 표본 15개 모두 재생 중이었다. 걷기 표본 32개 모두 재생 중이고 4개 프레임·32개 서로 다른 위치를 기록했다.
- Mochi의 기본 대기·잠자기·하품도 펫 픽셀 위에서 재생을 계속했다.
- Kazusa GLB의 기본 대기는 펫 픽셀 위 표본 151개 모두 재생 중이었고 65개 프레임을 기록했다. 걷기는 펫 픽셀 위 표본 9개 모두 재생 중이었으며 서로 다른 9개 프레임·9개 위치를 기록했다. 이 파일에는 스트레칭 매핑이 없어 기존 규칙에 따라 휴식 시작 후 걷기를 사용했다. GLB 스트레칭 매핑의 전환은 자동 회귀 검사로 확인했다.
- 투명 배경 검사는 검증 키로 펫 창을 이동해 실제 네이티브 커서를 창 내부 `(2, 4)`의 투명 여백에 놓았다. 숨겨진 말풍선, `AcceptsPointerAt=false`, `IsClickThrough=true`가 247개 표본에서 유지됐다. 해당 위치에 CUA로 직접 클릭한 뒤 뒤쪽 버튼의 카운터가 0→1로 증가했다. 펫 프레임은 계속 진행했다.

검증 창에 표시된 ‘호버’는 검증용 `Avalonia.IsPointerOver` 값이다. 이 프레임워크 플래그가 true여도 제품에 호버 상태·호버 모션·시간 말풍선은 없으며, 투명 영역의 입력 허용은 실제 픽셀 판정으로 결정한다.

## 검증 경계

실제 macOS 입력은 Mochi·Kazusa와 투명 배경에서 확인했다. 나머지 기본 펫과 media/original 팩은 자동 검사로 확인했다. Windows 실제 입력·설치 파일·업데이트·공개 배포는 이번 범위에 포함하지 않았다. 미리보기 3D 회전의 끊김 개선은 후속 작업이다.
