# 비활성 숫자 입력 반경·테두리 검증

2026-09-15 · `release/mvp`, 기준 커밋 `e0149e7` 위의 작업 트리. macOS 26.6.2 arm64,
.NET SDK 10.0.401, 런타임 10.0.12에서 확인했다.

비활성 `NumericUpDown` 안에서 Fluent 기본 비활성 배경이 내부 TextBox와 화살표 표면에
다시 적용되어, 내부 오른쪽 반경과 화살표 사이에 틈이 생기고 외곽 테두리 밖으로 다른
어두운 배경이 보였다.

공통 디자인 시스템에서 비활성 상태까지 배경·테두리를 고정했다. 외곽 컨트롤만 12px 반경과
1px 테두리를 그리며 내용을 경계 안에 제한한다. 내부 TextBox와 내부 Border는 반경 0,
투명 배경·테두리를 사용한다. 두 화살표 표면은 외곽과 같은 배경을 사용하고 오른쪽 끝 버튼만
외곽의 오른쪽 반경을 이어받는다.

검증 결과:

- 비활성 템플릿과 타이머 잠금 집중 테스트 **2개 통과**, 실패·건너뜀 0.
- 전체 Release 테스트 **138개 통과**, 실패·건너뜀 0.
- 새 `UNFOLD_DATA_DIR`의 macOS Avalonia 스모크 진단은 종료 코드 0과
  [진단 JSON](2026-09-15-disabled-input.json)의 `success: true`를 기록했다.
- 실제 렌더링의 기본 크기와 860×680 최소 크기에서 비활성 알림 간격 입력을 확인했다.
  숫자·증가·감소 영역 사이의 배경이 이어지고, 왼쪽·오른쪽 모서리와 1px 외곽선 밖으로
  내부의 어두운 표면이 드러나지 않았다.

진단은 실제 macOS Avalonia 렌더러를 사용하지만 창을 화면 밖에 두고 캡처한다. 실제 포인터,
다른 macOS 버전과 Windows의 서브픽셀 렌더링은 이번 환경에서 확인하지 않았다.
