# 펫 팩 설치 기반 및 병합 복구 검증

2026-09-13 · `release/mvp`, 기준 커밋 `06aa43c`에 이번 변경을 적용한 작업 트리.
macOS arm64 / Unix 26.6.2 / .NET 10.0.12.

## 완료한 작업

- 현재 커밋의 C# 5개 파일·플랫폼 문서에 남아 있던 11개 병합 충돌 구간 해소.
  개인화·타이머 변경과 설정 오류 복구·숨김 후 비동기 재생 차단을 함께 보존했다.
- 애니메이션 완료 이벤트 복구. 한 프레임 반응도 한 번 완료하고, 완료 후 Resume가
  완료 이벤트를 중복 발생시키지 않는다. 팩 미리보기는 반응 종료 후 idle로 돌아온다.
- 기존 UI 테스트의 삭제된 Swift 자산 경로와 모호한 ComboBox 선택자를 수정했다.
  파일 저장 실패는 읽기 전용 속성 대신 저장 목적지의 디렉터리 충돌로 재현한다.
  macOS는 읽기 전용 파일도 디렉터리 권한에 따라 교체할 수 있었기 때문이다.
- 로컬 팩 미리보기·설치·버전 갱신·같은 버전 재설치와 제작용 CLI 추가.
  [사용 방법과 계약](../pet-packs.md)에 제한과 복구 동작을 기록했다.

## 게시 앱 진단

최종 실행 데이터는 새 `/private/tmp/unfold-next.OEBmfy/smoke-verified`에만 생성했다.
[원본 결과 JSON](2026-09-13-pet-packs-smoke.json)을 함께 보관한다.

- Settings에서 간격 변경·Reset/Stop 각각 1.2초 대기·초대 생성 취소 검증 유지.
- 루틴 2개·업무 프로필 1개 저장, 진행 중 루틴 스냅샷 유지, 완료 기록·CSV 검증 유지.
- 진단용 펫 1.0.0 미리보기 → 설치·선택 → 1.1.0 업데이트 확인.
- 설치된 PNG를 의도적으로 손상시킨 뒤 같은 1.1.0 파일로 재설치해 원본 바이트 복구.
- 잘못된 ZIP을 열면 설치 버튼 비활성화, 이전 팩의 로딩 유지, 타이머 Pause 유지.
- 미리보기·업데이트·재설치·설치 완료·오류 화면을 포함한 PNG 19장 생성.
  미리보기·업데이트·오류 화면의 텍스트·버튼·정적 배치를 직접 확인했다.

진단 화면의 사각형은 테스트용 픽셀 도형이다. 신규 판매 아트로 제작하거나 기본
캐릭터 목록에 번들링하지 않았다. 실제 Mochi 파일은 변경하지 않았다.

로그·PNG·CSV 사본은 로컬 `artifacts/verification/pet-packs-2026-09-13/`에 있다.
게시 실행 파일은 `/private/tmp/unfold-next.OEBmfy/publish-verified/`에 있다.

## 검증 한계와 다음 단계

네이티브 진단은 macOS 렌더러의 off-screen 창과 프로그래밍된 버튼 이벤트다.
파일 선택기 경로·CSV 목적지를 주입하고 세션 시간을 직접 진행했다. 물리적 입력,
실제 OS 파일 선택기, Windows 실행, 실제 알림·로그인·sleep/wake·다중 모니터,
전체 GIF 재생 품질과 장시간 성능을 검증한 것으로 보지 않는다.
짧은 진단의 CPU/메모리 표본도 성능 통과 근거가 아니다.

다음은 판매용 펫 한 팩의 원본·권리 증빙과 실제 동작 품질 검수, Windows/macOS 실기
사용 확인이다. Mochi 원장의 원본·권리 상태는 미확인으로 유지한다. 결제·계정 구매
복원·원격 카탈로그는 미구현이며 3차 전체 완료나 판매 준비 완료로 판단하지 않는다.
