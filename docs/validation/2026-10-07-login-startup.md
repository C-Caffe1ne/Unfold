# 재실행 로그인 화면 수정

2026-10-07 · macOS arm64 · .NET 10 · C#·Avalonia.

## 원인

로그인 자격 증명은 이미 OS 보안 저장소에 보관되고 있었다.
`AppRuntime.Start`가 로그인 창을 먼저 표시하고 `RestoreAsync`로 저장된 세션·서버 이용 권한을
확인한 뒤 창을 닫아서, 유효한 로그인에도 재실행마다 로그인 화면이 잠깐 나타났다.

작업 시작 시 모든 작업트리의 브랜치·HEAD·미커밋 변경·프로젝트 버전을 대조했다.
기준은 앞선 기능 제거 커밋 `f9cd48d1e4f2168a75414b3a38119d197ff5c9ad`,
`1.1.1-beta`, `codex/remove-unused-features`다.
실행·검증 경로는 `/Users/hwanghyeonseong/Documents/GitHub/Unfold/.worktrees/remove-unused-features`다.
확인한 최신 공개 릴리스는 `v1.1.0-beta`이며, 다른 작업트리의 문서 변경은 보존했다.

## 변경

- 시작 시 계정 모델만 만들고 저장된 세션·이용 권한 검증을 먼저 기다린다.
  정상 복원은 로그인 창을 만들지 않고 타이머·펫을 시작한다. 일반 실행은 설정을 열고 자동실행은 숨겨 둔다.
- 복원·구매 확인 실패는 같은 모델을 계정 창으로 넘겨 계정 정보·오류·재시도 상태를 유지한다.
  저장된 세션이 없거나 무효일 때 로그인 화면을 표시한다.
- 복원 중 재활성화·설정 열기는 검증 완료 후 처리한다. 계정 열기 요청도 로그인 화면을 먼저 표시하지 않는다.
- 종료·로그아웃은 시작 복원 모델을 취소·해제한다. 늦은 응답이 세션이나 이용 권한을 다시 살리지 못한다.
  복원 중에는 아직 표시된 창·진행 중 타이머가 없으므로 트레이 종료에 확인 창을 요구하지 않는다.
- 갱신 토큰의 보안 저장·교체와 서버의 구매·무료 이용 권한 확인 계약을 유지한다.
  [Supabase 세션 문서](https://supabase.com/docs/guides/auth/sessions)와 공식 변경 기록을 확인했다.

## 미검증·위험

- 실제 Google 로그인 → 설치 앱 종료 → 재실행 전 과정과 Windows 실기는 미검증이다.
  네이티브 창 측정은 실제 macOS 런타임이며 인증·구매 응답은 fake다.
- 세션이 서버에서 무효화되거나 통신이 실패하면 로그인·재시도 화면이 필요하다.
  정상 복원에는 계정 창이 표시되지 않는다.
- 이번 변경은 최신 개발 소스와 로컬 빌드에 적용했다. 설치 앱·공개 배포 파일은 교체하지 않았다.
