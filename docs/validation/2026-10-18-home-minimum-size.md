# 홈 펫 영역 기준 최소 창 크기

2026-10-18 · `codex/pet-overlay-hover`, 시작 HEAD `5d0f86e`, 프로젝트 `1.2.0`.
작업트리·후보 브랜치·버전·미커밋 변경·실행 경로를 다시 확인했다. 원격 추적 브랜치와 시작 HEAD는 `0 / 0`, 최신 공개 정식 릴리스는 `v1.2.0` / 제품 소스 `99db377`이다.

## 변경

`SettingsWindow`의 최소 크기를 **640×560 → 860×800** Avalonia 논리 단위로 제한했다. 초기 크기 1120×800은 유지한다. 앞선 GIF·사진 저장·적용과 파일명 변경, 로그인 관련 기존 변경을 보존했다.

폭 860 미만의 기존 레이아웃은 펫 카드를 420 높이로 고정한다. 이 배치에서는 창 높이를 올려도 150% 펫(288×288)의 내부 스크롤을 막을 수 없어, 최소 폭을 두 열 배치의 경계인 860으로 정했다.

최소 높이 780을 먼저 검사했으나 제목 표시줄 공간 32를 예약하면 150% 펫에 비해 미리보기 높이가 부족했다. 한국어·영어는 285, 일본어 277, 중국어 279로 측정되어 높이를 800으로 보정했다. 제품 변경은 생성자의 최소 크기 한 줄이다. 스크롤바를 강제로 숨기거나 펫 크기를 줄이지 않는다.

## 집중 검증

새 임시 `UNFOLD_DATA_DIR`, .NET SDK 10.0.401, Release 빌드를 사용했다.

- 홈·펫 크기·번역·반응형·최소 설정 창의 GLB 편집 관련 **고유 20개 통과**, 실패·건너뜀 0.
- 새 최소 크기 검사 8개는 한국어·영어·일본어·중국어 × 제목 여백 0/32를 확인한다. 각 경우에 4개 테마, 펫 크기 50/100/150%, 최소 크기·최소 미만 축소 요청·1120×800·1440×960에서 실제 창 크기와 펫 영역의 `Extent ≤ Viewport` 양축 및 미리보기 경계를 검사한다.
- 최소 크기보다 작게 축소를 요청해도 실제 창 크기가 최소값 이상으로 유지된다. 홈 전체의 불필요한 세로 스크롤도 생기지 않는다.
- 기존 저장 설정·초안·포커스 유지와 펫 관리 화면의 최소 창 배치를 확인했다.
- 새 검사에 전역 테마 복원을 추가하고 큰 창 크기 사례의 중복을 제거한 뒤 변경된 **8개만 재실행하여 통과**했다. 위 20개에 중복 합산하지 않는다.
- Core·Desktop·Tests Release 빌드와 `git diff --check` 통과.

결과: `/tmp/unfold-home-min-results/final.trx` 및 `/tmp/unfold-home-min-results/minimum-final.trx`.
수정 전 결과는 `before.trx`, 높이 780의 중간 측정은 `after.trx`에 있다.

## 검증 경계

Avalonia headless에서 생산 `SettingsWindow`를 직접 생성했다. 제목 표시줄 32 여백은 자동 검사에서 예약한 공간이며 실제 macOS 또는 Windows 창 조작을 관찰한 증거는 아니다. 전체 테스트·앱 OS 진단·설치 앱 교체·배포는 수행하지 않았다. 실행 중인 `/Applications/Unfold.app`은 변경하지 않았다. 코드는 미커밋 상태다.
