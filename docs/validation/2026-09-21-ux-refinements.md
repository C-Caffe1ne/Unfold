# 알림·저장·입력 동작 검증

## 환경과 범위

2026-09-21 · `release/mvp`, 기준 커밋 `8db9c02`에 변경을 적용한 작업 트리.
Windows 10.0.26200.0 · .NET SDK 10.0.301 / 런타임 10.0.9.
기존 브랜드 팔레트 변경을 유지했다. 실행마다 새로운 `UNFOLD_DATA_DIR`을 사용했다.

| 요청 | 반영 동작 |
|---|---|
| 5분 타이머 | 전체 간격이 5분이면 사전 알림을 생략하고 정시 알림은 유지한다. |
| 펫 크기 슬라이더 | 핸들에만 호버 강조를 적용한다. 바의 색·크기와 드래그·클릭·키보드 조절은 유지한다. |
| 알림 유지 시간 | 안내·완료는 표시 시점에서 5초 후 닫는다. 사용자 답변에 따라 초대·휴식 조작은 유지한다. |
| 알림 음량 | 0~100% 슬라이더, 미리듣기·저장·취소를 연결한다. 기존 설정 기본값은 100%, 0%는 무음이다. |
| 펫 추가 저장 | 팩 생성 성공 후 만들기 초안, 라이브러리 저장 성공 후 열기 상태를 초기화한다. 실패·취소 시 입력은 유지한다. |
| 펫 추가 문구 | 참고 사항 버튼·항목을 제거하고 설치·업데이트·재설치 버튼은 모두 ‘저장’으로 표시한다. |
| 시간 설정 | ‘저장’ 버튼은 변경이 없으면 투명·비활성이다. 수정하면 나타나고 유효한 값만 저장한다. |
| 기록 날짜 | 누를 때의 축소 모션을 제거한다. 상세 펼치기·접기와 키보드 조작은 유지한다. |

## 실행한 명령과 결과

```powershell
dotnet test Unfold.slnx -c Release --no-restore --logger 'trx;LogFileName=final.trx' --results-directory artifacts/ux-refinements-results
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll --smoke-test
git diff --check
```

- Release 빌드와 전체 테스트: 종료 코드 0, **240개 통과 / 2개 건너뜀 / 0개 실패**, 총 242개.
- 건너뛴 2개는 FFmpeg 변환 도구가 없는 환경의 실제 MP4 변환 검사다.
- [Windows 자동 화면 진단](2026-09-21-ux-refinements.json): 종료 코드 0, `success=true`, PNG 82장.
- 타이머·설정 저장, 팩 저장·업데이트·손상 복구, GIF 팩 생성, 최소 창 배치와 네 가지 테마 진단을 통과했다.
- 변경 형식 검사 `git diff --check` 통과.

## 경계면 교차 검증

- 5분 전체 주기에서 사전 알림이 없고, 더 긴 간격의 사전 알림과 정시 알림이 유지된다.
- 안내·완료의 4.999초/5초 경계, 초대·휴식 유지와 일반 작업 타이머 없이 완료 알림이 만료되는 경로를 검사했다.
  별도 만료 타이머를 사용해 기존 1초 작업 갱신 주기만큼 추가로 남지 않도록 했다.
- 음량 설정 저장·복원·취소, 잘못된 저장값 복구, 8/16비트 PCM 감쇠와 원본·길이 보존,
  무음과 재생 완료·취소·실패 시 임시 파일 정리를 검사했다. 시스템 음량은 변경하지 않는다.
- 저장 성공 후 초기화와 실패·취소 시 입력 보존, 빈 미리보기와 중복 저장 방지를 검사했다.
  참고 사항 표시를 제거해도 Core의 팩 검증과 잘못된 파일 거부는 유지한다.
- 시간 입력의 수정·원복·저장, 빈 값·잘못된 원시 텍스트와 실행 중 간격 잠금,
  슬라이더의 바·핸들 호버, 드래그·바 클릭·키보드 입력과 날짜 펼치기·접기를 headless로 검사했다.

## 남은 확인

변경 범위의 자동 검사에서 실패는 발견하지 못했다. 출시 전 실제 Windows/macOS에서
음량별 미리듣기·알림 출력과 입력 조작을 확인해야 한다. 배포물 생성·서명·게시는 이번 범위에 포함하지 않았다.
