# UI/UX 2단계 최소 창·숨은 상태 검증

2026년 09월 17일 · `release/mvp` `2f02e8a` 기반 현재 작업 트리 · C#/.NET 10 Avalonia.

## 구현 결과

UI/UX 감사의 2단계인 UI-04~UI-06, UI-12, UI-13을 구현했다.

- 공통 `PageBodyScroll`은 세로 스크롤바 트랙을 본문과 분리해 예약하고 8px 거터를 둔다.
  설정의 펫 만들기 탭과 독립 커스텀 펫 창에서 이름, 파일 가져오기, 동작 슬롯 버튼이
  스크롤바와 겹치지 않는다. 펫 팩 창은 480px 최소 폭에서도 384 논리 픽셀 미리보기를 유지한다.
- 접힌 말풍선에서 휴식 초대는 빈 링, 진행 중 휴식은 채운 점으로 표시한다. 트레이 상태는
  **휴식 대기 중 / 휴식 중**으로 바뀌며 **휴식 알림 펼치기**가 세션과 경과 시간을 보존한다.
- 경고가 있는 펫 팩은 고정 작업 영역에 경고 개수를 표시한다. **참고 사항 보기**로 본문 상세
  경고까지 이동하며, 새 팩·정상 팩·열기 실패로 바뀌면 이전 경고 상태를 지운다.
- 설정의 적용 상태는 **현재 알림 설정** 그룹으로 분리했다. 루틴·프로필 하단은 왼쪽 관리 동작과
  오른쪽 주 작업·닫기 그룹으로 정리해 최소 폭에서도 한 행을 유지한다.

## macOS 네이티브 진단

새 `UNFOLD_DATA_DIR=/tmp/unfold-phase2-smoke-final.j5Uen8`에서 Release 스모크 진단을 실행했다.
`verification/smoke.json`은 `success: true`, PNG 42장, 설정 최소 크기 860×680, 커스텀 펫
520×620, 내부 탭, 고정 작업 영역, 가로 넘침 없음, 초안 유지와 휴식 말풍선 흐름을 보고했다.

`custom-pet-editor.png`, `custom-pet-minimum-scrolled.png`,
`settings-pet-create-minimum-scrolled.png`에서 세로 스크롤바가 보이고 입력·동작 버튼과 분리된
것을 확인했다. `speech-folded.png`에서는 접힌 펫의 대기 링 배지를 확인했다.
`settings.png`에서는 **현재 알림 설정** 그룹, `routine-library.png`와
`settings-routines-tab.png`에서는 관리 동작과 주 작업의 분리를 확인했다.

첫 스모크 실행은 파일 배정 뒤 접혀 있던 **동작에 넣기** 버튼의 이전 좌표를 진단 코드가 계속
검사해 실패했다. 제품 UI의 보이는 컨트롤은 겹치지 않았으며, 진단 대상을 이름·파일 가져오기·
보이는 동작 슬롯으로 바로잡은 뒤 새 빈 데이터 디렉터리에서 전체 진단을 다시 실행해 통과했다.

이 진단은 macOS 네이티브 렌더러를 사용했지만 화면 밖 창과 프로그램 방식 입력을 사용했다.
사람의 마우스·키보드 조작이나 실제 메뉴 막대의 트레이 항목 클릭으로 간주하지 않는다.

## 남은 확인 범위

- macOS 실제 메뉴 막대에서 **휴식 알림 펼치기**의 활성 상태와 복구 동작, 펫 배지의 체감 크기·대비.
- Windows 100~200% DPI에서 스크롤바 폭, 투명 펫 창의 배지·클릭 통과와 트레이 복구.

위 항목은 이번 자동 검사와 화면 밖 네이티브 캡처 통과로 대체하지 않는다.
