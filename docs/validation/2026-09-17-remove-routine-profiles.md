# 루틴·업무 프로필 UI 제거 검증

> 후속 변경에서 홈 오른쪽 열에 스트레칭·휴식 시간 카드를 추가했다. 현재 화면은
> [홈 시간 설정 검증](2026-09-17-home-break-time.md)을 함께 확인한다.

2026-09-17 · `release/mvp`의 C#·Avalonia 설정 화면에서 **내 루틴·업무 프로필 설정**
기능을 제거했다. 기존 사용자 데이터는 삭제하지 않고 읽기 호환성을 유지했다.

## 변경

- 사이드바의 **내 루틴·업무 프로필** 탭을 제거했다. 콘텐츠 탭은 타이머, 설정,
  기록·내보내기, 펫 추가의 4개다.
- 타이머 화면의 루틴 선택, 별도 적용, 루틴 편집, 루틴·프로필 페이지 진입 카드를 제거했다.
- 타이머 화면 오른쪽 열에는 오늘의 완료 기록만 남겼다.
- 설정 탭의 자리 비움·스트레칭·다시 알림 시간과 알림 효과음 기능은 그대로 유지했다.
- `settings.json`의 `customRoutine`, `additionalRoutines`, `workProfiles`, `activeProfileId`,
  `breakRoutineId` 필드는 삭제하거나 마이그레이션하지 않았다. 타이머 설정을 적용해도
  기존 사용자 루틴 목록, 프로필 목록, 선택 루틴 식별자는 보존한다.
- 이전 버전 데이터와 기록을 검사하는 내부 모델·편집기·스모크 진단 경로는 유지하지만
  일반 설정 화면에서는 생성하지 않는다.

## 자동 검증

| 검사 | 결과 |
|---|---|
| 설정 대시보드·타이머 집중 테스트 | 13 통과, 실패·건너뜀 0 |
| `dotnet test Unfold.slnx -c Release --no-restore --disable-build-servers` | 171 통과, 실패·건너뜀 0 |
| 새 `UNFOLD_DATA_DIR`의 `--smoke-test` | `success: true`, PNG 42장 |
| 설정 내비게이션 | 콘텐츠 탭 4개, 루틴·프로필 탭 없음 |
| 제거된 컨트롤 | `RoutinePicker`, `SettingsEditRoutine`, `ApplyRoutineSettings`, `SettingsOpenLibrary`, `PersonalizationTabs` 미생성 |
| 최소 창 | 860×680, 타이머·펫 표시와 가로 넘침 없음 |
| 기존 데이터 | 사용자 루틴·업무 프로필·선택 루틴을 타이머 설정 저장 뒤 재로드해 보존 확인 |
| `git diff --check` | 통과 |

원본 진단 결과는
[2026-09-17-remove-routine-profiles.json](2026-09-17-remove-routine-profiles.json)에 보존했다.
자동 캡처에서 기본·최소 타이머 화면과 설정 화면을 확인했고, 사이드바에는 타이머·설정·기록·펫
아이콘만 표시됐다. 제거 전 루틴 화면 캡처는 진단용 직접 생성 결과이며 일반 설정에서 도달할 수 없다.

## 검증 경계

- macOS arm64에서 off-screen Avalonia 진단과 렌더링 캡처를 실행했다. 실제 포인터 입력,
  VoiceOver, 장시간 사용성 검수는 아니다.
- 실제 Windows의 글꼴 배치, DPI, 키보드 포커스 순서는 이 변경에서 실행하지 않았다.
- 기존 루틴·프로필 데이터의 삭제 기능이나 새 편집 경로는 제공하지 않는다. 호환성 모델은
  기존 설치가 데이터 손실 없이 실행되도록 남긴 범위다.
