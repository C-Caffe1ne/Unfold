## AUD-01 · 설정 일부 손상 시 정상 설정도 초기화됨

**발생 조건:** `settings.json` 문법 자체는 유효하지만 한 필드의 자료형이 잘못됐거나, 과거 루틴·프로필 데이터 일부가 유효하지 않은 경우다. 일반 UI로 정상 저장한 값에서 발생했다는 뜻은 아니다.

`AppSettings.Load`는 전체 역직렬화 이후에 `Recover`를 호출한다. 자료형 오류는 그 전에 예외가 나고, 이전 루틴 목록의 잘못된 항목도 전체 로드를 실패시킨다. `AppRuntime`은 이 예외를 받아 모든 설정을 기본값으로 바꾼다.

| 입력의 핵심 값 | 실제 로드 결과 |
|---|---|
| `intervalMinutes:37`, `idleMinutes:9`, `petScalePercent:55` | 간격 37분·자리 비움 9분 유지, 크기만 100%로 복구 |
| 같은 정상 값에 `petScalePercent:"broken"` | 간격 60분·자리 비움 5분으로 함께 초기화 |
| 같은 정상 값에 `additionalRoutines:[null]` | 간격 60분·자리 비움 5분으로 함께 초기화 |

기존 `.invalid-*` 백업은 생성된다. 따라서 원본이 즉시 영구 삭제되는 문제는 아니지만, 앱은 정상 값까지 잃은 기본 설정으로 동작하며 이후 저장도 그 값을 사용한다. 현재 UI에서 제거된 루틴 데이터가 현재 타이머 설정에 영향을 줄 수 있다.

- 근거: [AppSettings.cs](../../src/Unfold.Core/AppSettings.cs) 30–53행, [Personalization.cs](../../src/Unfold.Core/Personalization.cs) 19–41행, [AppRuntime.cs](../../src/Unfold.Desktop/AppRuntime.cs) 79–90행.
- 최소 수정 방향: 유효한 JSON은 필드별 자료형까지 검사해 복구하고, 호환성용 루틴·프로필의 잘못된 항목을 다른 설정과 분리한다. 원본 백업과 저장 시 엄격한 검증은 유지한다.
- 완료 기준: 위 두 실패 사례에서도 37분·9분과 그 밖의 정상 설정을 유지하고, 손상된 필드·참조만 안전하게 복구한다. 전체 JSON 구문 오류는 별도 복구 경로로 남긴다.

## AUD-02 · 펫 로딩 실패를 캐시하고 반응 상태를 해제하지 않음

**발생 조건:** 설치 후 클립 파일 손상·접근 오류 등으로 애니메이션 로딩이 실패한 경우다. 새 `.unfoldpet`를 가져올 때의 전체 자산 검증이 빠졌다는 지적은 아니다.

서로 연결된 두 복구 누락이 있다.

1. `AppRuntime.Clip`은 실패한 `Task`도 캐시에 남긴다. 파일을 복구해도 같은 캐시가 유지되는 동안 다음 호출이 같은 예외를 받는다.
2. `PetWindow.React`는 로딩 전에 `reacting=true`와 행동 이름을 설정하지만, 일반 예외에서는 로그만 남긴다. 실패한 반응을 종료하고 기본 행동으로 돌아가는 처리가 없다. 오리지널 펫의 랜덤 행동·걷기에서 `reacting`을 차단 조건으로 사용한다.

**재현 결과:** 임시 시험용 팩의 `click.gif`를 손상시켜 첫 로딩을 실패시킨 뒤 정상 GIF로 교체했다. 직접 디코딩은 4프레임으로 성공했으나 `runtime.Clip("click")`은 이전 호출과 동일한 Task를 반환하며 다시 `InvalidDataException`을 냈다. 같은 조건의 headless `PetWindow.React("click")` 종료 후에도 `reacting=true`, `ActiveAnimation="click"`이 남았다.

기존 idle 화면 자체가 반드시 멈추는 것은 아니다. 문제는 실패 이후 반응 상태와 재시도 경로가 복구되지 않는다는 점이다. 캐시를 비우는 펫 변경·목록 새로고침·앱 재실행 등은 우회 방법이 될 수 있다.

- 근거: [AppRuntime.cs](../../src/Unfold.Desktop/AppRuntime.cs) 231–239행, [PetWindow.cs](../../src/Unfold.Desktop/PetWindow.cs) 112–152행, [PetWindow.Companion.cs](../../src/Unfold.Desktop/PetWindow.Companion.cs)의 `AdvanceCompanion` 차단 조건.
- 최소 수정 방향: 실패한 요청만 캐시에서 제거하고, 현재 반응의 실패일 때만 반응 상태를 해제해 유효한 기본 클립으로 돌아간다. 이전 요청의 늦은 실패가 새 반응·다른 펫을 덮어쓰지 않도록 기존 세대 번호 검사를 유지한다.
- 완료 기준: 실패→파일 복구→재시도가 성공하고, 실패 후 기본 행동과 랜덤 행동이 재개된다. 연속 클릭·펫 전환·숨김·종료 중의 오래된 요청은 현재 상태를 변경하지 않는다.

## AUD-03 · 사용하지 않는 효과음 파일 누적

효과음 가져오기는 **설정 저장 전** `Sounds/<hash>.wav`에 파일을 복사한다. 이후 취소·기본 복원·다른 파일로 교체해도 설정 참조만 바뀌며 해당 파일을 정리하는 경로는 없다. 같은 내용은 해시로 중복을 피하지만, 서로 다른 파일을 반복 선택하면 사용하지 않는 사본이 계속 남는다. 파일별 5 MiB 제한은 전체 폴더의 누적 크기를 제한하지 않는다.

- 근거: [ReminderSounds.cs](../../src/Unfold.Core/ReminderSounds.cs) 11–19행, [SettingsWindow.Notifications.cs](../../src/Unfold.Desktop/SettingsWindow.Notifications.cs) 117–145행, [SettingsWindow.Preferences.cs](../../src/Unfold.Desktop/SettingsWindow.Preferences.cs) 139–144행.
- `ReminderSoundPlayer`의 임시 음량 조절 파일 삭제는 별개이며 이미 구현되어 있다.
- 최소 수정 방향: 가져오기 초안을 임시 보관하거나, 저장된 설정·현재 초안·재생 중인 파일이 참조하지 않는 사본만 정리한다. 취소 순간에 무조건 삭제하면 다른 알림이 공유하는 파일을 지울 수 있으므로 참조 확인이 필요하다.
- 완료 기준: 가져오기→취소와 여러 번 교체를 반복해도 미사용 사본이 지속적으로 늘지 않고, 저장한 스트레칭·완료 효과음과 미리듣기는 유지된다.

## AUD-04 · 패치노트에서 즉시 적용 설정까지 저장·취소 대상으로 설명

[v0.2.1 패치노트](../releases/v0.2.1.md) 21행은 앱 동작을 포함한 설정 변경을 하단 **취소·저장**으로 처리한다고 읽힌다. 실제로 **바탕화면에 펫 표시**와 **로그인 시 자동 실행**은 선택 즉시 반영되며 하단 취소로 되돌리지 않는다. 이 즉시 적용 방식은 [승인된 설정 문서](../settings-ui.md)에 명시되어 있다.

- 근거: [SettingsWindow.cs](../../src/Unfold.Desktop/SettingsWindow.cs) 71–97행, [SettingsWindow.Preferences.cs](../../src/Unfold.Desktop/SettingsWindow.Preferences.cs) 30–36행.
- 수정 방향: 제품 동작은 유지하고 패치노트에서 저장·취소의 적용 범위를 알림·타이머 설정으로 정확히 한정한다. 앱 안에 설명 문구를 새로 넣자는 제안은 아니다.
- 완료 기준: 배포 파일에 포함하는 패치노트도 같은 설명을 사용한다. 기존 배포물은 이번 감사에서 변경하지 않았다.

## 배포 검증에서 남은 항목

다음은 새로 확인한 코드 결함이 아니라 **검증 공백**이다.

- v0.2.1 Windows x64와 Intel Mac은 패키지 생성·구조 확인 기록이 있지만 해당 배포 파일을 실제 대상 장비에서 실행한 증거는 없다.
- Apple Silicon Mac의 게시 앱 자동 진단은 있으나, 이 배포본의 물리 입력·효과음 청취·로그인 자동 실행·다중 모니터/DPI·장시간 사용은 미검증이다. 특히 투명 펫 창의 잔상과 클릭 통과는 headless 검사로 판정할 수 없다.
- macOS CI는 현재 번들 생성까지 수행한다. 이번 로컬 배포 검증처럼 게시된 앱의 smoke와 다섯 펫 행동 진단을 CI에 연결하면 이후 회귀를 더 빨리 찾을 수 있다. Intel 대상은 현재 CI 매트릭스에 없다.
- Developer ID 공증·Windows 코드 서명 부재는 이미 명시된 배포 제약이다. 이번 감사에서 이를 새 기능 오류로 분류하거나 외부 게시·서명 작업을 실행하지 않았다.

근거: [v0.2.1 배포 검증](2026-09-22-v0.2.1-distribution.md), [desktop.yml](../../.github/workflows/desktop.yml).

- 추가 재현 프로그램은 `/private/tmp/Unfold-audit-20260923-zt302lp0/`에 작성하고 기존 Release 어셈블리를 참조했다. 제품 소스와 테스트 파일은 수정하지 않았다. 재현 프로그램 빌드 경고·오류 0, 최종 실행 종료 0을 확인했다.
- 별도의 `UNFOLD_DATA_DIR`에서 설정 손상과 클립 실패를 주입했다. 캐시 재시도는 실제 메서드로, 반응 상태는 headless 창에서 확인했다. 사용자 데이터·실행 중인 앱·로그인 등록은 변경하지 않았다.

- 루틴·프로필 UI 제거, 말풍선 본문 제거, 앱 동작 체크박스의 즉시 적용은 기존 결정이므로 회귀로 분류하지 않았다. 진단 전용 편집기 문제도 일반 사용 경로의 결함으로 확대하지 않았다.
