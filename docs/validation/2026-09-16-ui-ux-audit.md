# UI/UX 전수 감사와 작업 계획

2026년 09월 16일 · `release/mvp` `7e81f77` + 현재 작업 트리 · C#/.NET 10 Avalonia.

## 결론

현재 UI는 차콜·크림 팔레트, 카드 계층, 한국어 문체, 타이머 상태 표현이 화면 전반에
일관되게 적용되어 있다. 핵심 흐름을 막는 P0 결함은 발견하지 않았다. 지금 필요한 작업은
새로운 시각 콘셉트를 다시 만드는 일이 아니라, **잘못된 대상을 수정하거나 덮어쓸 수 있는 흐름**,
**접힌 알림과 최소 창에서 숨는 상태**, **키보드 포커스와 보조 기술 연결**을 순서대로 보완하는 일이다.

우선 수정할 P1 항목은 다음 세 부류다.

1. 루틴 편집 대상, 업무 프로필 적용 가능 상태, 커스텀 펫 파일 교체처럼 사용자의 의도와
   실제 결과가 어긋날 수 있는 동작.
2. 접힌 말풍선의 대기 상태, 펫 팩 경고, 최소 창의 스크롤바처럼 중요한 정보가 보이지 않거나
   컨트롤과 겹치는 표현.
3. 입력 포커스와 펫 말풍선처럼 키보드 사용자가 현재 위치나 핵심 동작에 도달하기 어려운 경로.

## 진행 상태

**1단계 동작 정확성(UI-01~UI-03)은 구현과 자동 검증을 완료했다.** 선택한 사용자 루틴 편집,
타이머 진행 중 업무 프로필 적용 사전 차단, 커스텀 펫 파일 교체 확인과 다음 빈 동작 이동이
현재 코드에 반영되어 있다. 변경 내용과 검증 경계는
[1단계 동작 정확성 검증](2026-09-16-ui-ux-phase1.md)에 기록한다. UI-04 이후 항목은 이 문서의
후속 계획으로 남아 있으며 이번 구현 범위에 포함하지 않았다.

  회귀로 분류하지 않았다.

## 유지해야 할 강점

- `DesignSystem.cs`의 공통 토큰과 `Ui.cs`의 페이지·카드·필드·작업 영역이 일반 설정,
  편집기, 확인 창까지 같은 시각 언어를 만든다.
- 타이머의 진행·일시정지·자리 비움·중지 상태는 색과 문장을 함께 사용한다. 실행 중 알림
  간격 잠금 사유도 클릭 전에 보인다.
- 설정 최소 크기에서 펫·타이머·사이드바가 유지되고 세부 설정만 스크롤된다. 고정 작업 버튼과
  주요 히트 영역은 자동 검사 범위에서 창 안에 남는다.
- 기본 글자 대비는 토큰 계산상 4.5:1을 넘고, 필드 레이블과 입력의 접근성 연결도 대부분 있다.
- 삭제 확인은 취소에 먼저 포커스를 두며, 제목 표시줄 닫기도 취소로 처리한다.
- 기록이 없는 상태와 오류 문구가 압박하지 않는 한국어 문체를 유지한다.

## 작업 계획

### 1단계 — 의도와 결과가 다른 동작 수정

사용자 데이터와 설정을 잘못 바꾸는 세 항목을 먼저 처리한다.

- `UI-01`: 대시보드 편집 버튼이 현재 선택한 사용자 루틴을 열도록 한다. 기본 제공 루틴은
  직접 편집하지 못하므로 버튼을 비활성화하고 **루틴을 복사해 만들기** 또는 라이브러리 이동 안내를
  제공한다.
- `UI-02`: 프로필 화면에 타이머 편집 가능 상태를 전달한다. 간격이 바뀌는 프로필은 진행 중에
  적용 버튼을 미리 비활성화하고 같은 화면에 이유와 이동 경로를 표시한다.
- `UI-03`: 이미 파일이 있는 동작을 교체할 때 확인한다. 배정 후에는 아직 비어 있는 다음 동작으로
  선택을 이동해 반복 가져오기 실수를 줄인다.

완료 조건:

- 선택한 추가 루틴과 편집기 내용이 일치한다.
- 타이머 진행 중에는 프로필 적용 실패를 클릭 전에 알 수 있다.
- 커스텀 펫 교체 확인을 취소하면 기존 클립이 그대로 남는다.
- 관련 단위·헤드리스 테스트와 전체 Release 테스트가 통과한다.

### 2단계 — 최소 창과 숨은 상태 보완

- `UI-04`: `PageBodyScroll` 본문에 스크롤바 거터 또는 오른쪽 인셋을 둔다. 펫 이름 입력,
  파일 가져오기, 펫 팩 열기 버튼의 모서리와 히트 영역에 스크롤바가 닿지 않게 한다.
- `UI-05`: 말풍선이 접힌 상태에서 알림이 대기하거나 휴식이 진행되면 트레이 상태를
  **휴식 대기 중 / 휴식 중**으로 바꾼다. 펫에는 작은 상태 배지처럼 방해가 적은 신호를 사용한다.
- `UI-06`: 펫 팩 경고 개수와 존재를 고정 작업 영역에 표시하고, 본문 경고로 이동할 수 있게 한다.
  설치 버튼을 누르기 전 경고가 있다는 사실은 스크롤 없이 보여야 한다.
- `UI-12`, `UI-13`: 프로필 상태 라벨을 별도 그룹으로 구분하고 라이브러리 하단 동작을
  주 작업/관리/닫기 그룹으로 재배치한다.

완료 조건:

- 설정 1120×800·860×680, 커스텀 펫 660×880·520×620과 두 크기 사이의 중간 폭에서
  세로 스크롤바가 입력·버튼 위에
  그려지지 않는다.
- 접힌 말풍선에서도 트레이만 열어 현재 대기 상태와 복구 동작을 알 수 있다.
- 경고가 있는 팩은 최소 창의 첫 화면에서 경고 존재를 확인할 수 있다.
- 고정 하단 버튼, 초안 유지, 가로 넘침 없음 회귀 검사가 계속 통과한다.

### 3단계 — 키보드와 접근성 경로 정리

- `UI-07`: 기존 요구대로 입력의 호버와 일반 포커스에서 배경·테두리 색과 두께는 바꾸지 않는다.
  `:focus-visible`에만 필드 레이블 강조 또는 컨트롤 밖의 겹치지 않는 표시를 사용해 키보드 위치를
  알린다. 내부·외부 테두리가 겹쳐 보였던 문제를 다시 만들지 않는다.
- `UI-08`: 먼저 macOS와 Windows에서 다른 앱에 포커스를 둔 채 실제 알림을 발생시켜 접근 가능성을
  확정한다. 창 강제 활성화로 작업 포커스를 빼앗지 않고, 트레이의 **휴식 알림 열기**와 명시적
  키보드 진입 경로를 우선 검토한다.
- `UI-09`~`UI-11`: 비활성 버튼에 도움말을 연결하고, 탭 그룹 이름·기록 행 그룹·펫 이름을
  접근성 트리에 추가한다. 펫 팩 실패 상태에는 `Error` 토큰을 적용한다.

완료 조건:

- Tab만으로 모든 설정 필드를 순회하면서 현재 위치를 식별할 수 있다.
- 펫 알림의 시작·미루기·완료에 키보드만으로 도달할 수 있다.
- VoiceOver와 Narrator에서 탭 그룹, 기록 한 행, 비활성 버튼 사유가 의미 단위로 읽힌다.
- 포커스 표시가 입력의 기존 1px 테두리나 NumericUpDown 화살표 반경과 겹치지 않는다.

### 4단계 — 기록 정보와 세부 마감

- `UI-14`: 날짜 행을 펼치면 그날의 루틴명, 완료 시각, 실제 휴식 시간을 앱 안에서 볼 수 있게 한다.
- 고정 높이 때문에 내용이 적을 때 여백이 과도한 말풍선과 펫 빈 상태는 실제 사용성 확인 뒤
  콘텐츠 기반 최소 높이를 검토한다.
- 버튼 라벨, 빈 상태, 오류 문구는 기존 한국어 문체와 용어표를 유지한다.

이 단계는 1~3단계가 끝난 뒤 진행한다. 데이터 모델과 CSV 형식은 바꾸지 않고 이미 저장된
`BreakReview.Entries`를 표시하는 범위로 제한한다.

컨트롤을 다시 만지므로 B 뒤에 진행한다. 각 묶음은 사용자 변경을 보존하고 자기 소유 파일 밖의
변경을 되돌리지 않는다.

## 검증 계획

### 자동 검사

1. 항목별 헤드리스 테스트를 먼저 실행한다.
2. `dotnet test Unfold.slnx -c Release --no-restore`로 전체 회귀를 확인한다.
3. 새 `UNFOLD_DATA_DIR`에서 Release 스모크 진단을 실행하고 기본·최소·중간 폭을 캡처한다.
4. 레이아웃 검사는 보임 여부뿐 아니라 스크롤바와 컨트롤 경계의 실제 좌표가 겹치지 않는지 확인한다.

### macOS 실제 확인

- 마우스와 Tab 키로 설정, 루틴, 프로필, 펫 만들기, 펫 팩 설치를 처음부터 끝까지 조작한다.
- 다른 앱이 활성화된 상태에서 말풍선 알림을 발생시키고, 접힌 상태와 키보드 진입을 확인한다.
- 1배·Retina, 최소 창과 중간 창 폭에서 스크롤바·포커스 표시·팝업을 확인한다.
- VoiceOver로 탭 그룹, 기록 행, 비활성 사유를 확인한다.

### Windows 실제 확인

- 100%, 125%, 150%, 200% 배율에서 최소 창과 스크롤 영역을 확인한다.
- Narrator와 키보드만으로 펫 말풍선의 시작·미루기·완료를 확인한다.
- 투명 펫 창의 클릭 통과, 트레이 상태, 파일 선택기를 확인한다.

현재 세션에서 Windows, VoiceOver, Narrator, 실제 DPI 전환, 실제 파일 선택기는 확인하지 않았다.
이 항목들은 자동 검사 통과로 대체하지 않는다.

## 이번 단계의 변경 범위

감사 문서를 처음 작성할 때는 제품 UI 코드를 수정하지 않았다. 이후 **1단계 동작 정확성**을
구현하고 별도 검증 기록을 남겼다. 이 문서는 UI-04 이후 작업의 순서, 파일 소유, 완료 조건을
계속 관리한다.
