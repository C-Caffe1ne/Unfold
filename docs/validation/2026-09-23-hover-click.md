# 시간 말풍선 표시 중 연속 클릭 수정 — 2026-09-23

## 원인과 수정

클릭을 누르면 `down` 상태 때문에 시간 말풍선이 닫히고, 놓으면 다시 열렸다.
투명 네이티브 창이 192×192와 240×300 사이에서 반복 변경되고,
동시에 펫의 스퀴시·바운스와 클릭 프레임 교체가 진행되는 구조였다.
변형되는 `AnimationView`의 포인터 이탈도 호버를 종료해 창 크기를 바꿀 수 있었다.

- 열린 시간 말풍선을 누르기·드래그 중 유지한다.
- 호버는 변형되지 않는 창 좌표로 판단한다. 처음에는 불투명 픽셀에서 열고,
  열린 뒤에는 고정된 펫 영역을 벗어날 때 닫는다.
- 드래그 중 시계 갱신은 텍스트만 바꾸며 화면 경계의 말풍선 방향을 바꾸지 않는다.
- 기존 스트레칭 알림 우선순위, 클릭 애니메이션, 드래그 위치 저장, 펫 숨김은 유지한다.
- 이전 macOS OpenGL 렌더링 설정은 유지했다. 펫 리소스는 변경하지 않았다.

변경: `src/Unfold.Desktop/PetWindow.cs`, `Tests/Unfold.Tests/PetHoverTests.cs`.

## 실제 macOS

macOS 26.6.2 arm64, 새 `UNFOLD_DATA_DIR`, 실제 네이티브 창과 CUA 마우스 입력을 사용했다.
화면 밖 렌더링이나 Headless 입력으로 대체하지 않았다.

| 조건 | 입력 확인 | 창 크기 변경 | 창 위치 변경 | 시간 말풍선 |
| --- | --- | --- | --- | --- |
| 보리, 시간 표시 후 빠른 연속 클릭 | 누르기 20 / 놓기 20 | 0 | 0 | 유지 |
| Mochi, 클릭 반응 중 반복 클릭 | 누르기 20 / 놓기 20 | 0 | 0 | 유지 |
| Mochi 드래그 | 누르기 1 / 놓기 1 | 0 | 드래그로 1회 | 유지 |

Mochi 클릭 이벤트에서 서로 다른 포즈 값 10개를 기록했다. 스퀴시·바운스가 진행되는
중에도 창과 펫 배치가 유지됐다. 드래그는 화면 좌표를 가로 45px·세로 20px 이동했다.
스트레칭 초대 미리보기로 전환하면 시간 표시 대신 기존 알림과 두 버튼이 나타났다.
클릭 후 캡처에서 시간 표시와 단일 펫 모습을 확인했으며, 테스트 앱은 종료했다.

수치 근거: `artifacts/validation/2026-09-23-hover-click/native-click-result.json`과
`native-profile/events.jsonl`. 하네스 소스는 같은 경로의 `native-harness/`에 남겼다.

## 검증 한계

연속 클릭에 따른 창 재배치와 호버 끊김은 자동 검사와 실제 macOS 입력으로 확인했다.
모든 중간 프레임의 잔상 소멸을 연속 영상으로 검수한 것은 아니다.
Windows 실기, 다른 GPU·DPI·다중 모니터 및 이번 수정의 전체화면 입력은 미검증이다.
배포 파일은 다시 만들지 않았다.
