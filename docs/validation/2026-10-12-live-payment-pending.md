# Live 결제 pending 원인과 복구

2026년 10월 12일 · 공개 앱 `v1.1.3-beta` (`b1242ea`), 최신 작업트리 `codex/remove-unused-features`. 서버 수정은 `a6b1411`·`a61ee4f`, 운영 `lemon-webhook` v21이다.

## 결과

기존에 실패한 실제 Live `order_created`를 판매자 콘솔에서 재전송했다. HTTP 200으로 처리돼 주문은 `pending→paid`, Live 구매 권한은 `active`로 바뀌었다. 같은 이벤트를 한 번 더 보내도 HTTP 200·`duplicate=true`이며 저장된 이벤트는 1개다. 수동 권한 부여나 새 결제를 하지 않았다.

운영 `get_app_access()`를 해당 구매자의 JWT subject와 `authenticated` 역할을 트랜잭션 안에서 설정해 호출했고 `active`를 확인했다. 역할 설정은 쿼리 종료 후 초기화됐다. 이는 운영 RPC·RLS 검증이며 실제 Google 토큰 또는 고객 앱 화면의 로그인 검증은 아니다.

## 실제 원인

- 실패 이벤트는 운영 Live 주문과 연결된 `order_created`였으며 기존 v19에서 세 번 HTTP 422로 거절됐다. 판매자 콘솔의 원문·전송 시간·주문을 대조했다.
- `tax_inclusive=true`인 실제 이벤트는 `subtotal=total`로 이미 세금을 포함했다. 기존 검증은 여기에 세금을 다시 더해 합계 불일치로 거절했다. 기존 세금 포함 테스트의 소계도 실제 공급자 형식과 달랐다.
- 상품 가격은 4,900원이지만 실제 이벤트 총액은 4,906.03원이다. 서명된 `total_usd=366`과 `currency_rate=0.00074602`를 대조하면 USD 센트 반올림 후 KRW 재환산과 일치한다. 기존의 총액 4,900원 완전 일치 검사도 이 이벤트를 거절했다.

실제 주문의 기록된 세금은 442.35원, 정규화한 세전 소계는 4,463.68원, 총액은 4,906.03원이다. 명목 가격과 실제 주문 총액을 구분하며, 이번 복구에서 상품 가격이나 기존 청구를 변경하지 않았다. 개인정보·주문 식별자·서명된 영수증 URL은 문서와 회귀 자료에 저장하지 않는다.

## 수정과 배포

- 세금 포함 이벤트는 공급자 소계에서 세금을 빼 내부 세전 소계로 정규화한다. 세금 별도 이벤트는 기존 합계 계약을 따른다. DB의 `total=net subtotal+tax` 계약을 유지하므로 마이그레이션은 없다.
- 상품 항목의 계약 가격은 정확히 검사한다. 환산 총액 차이는 서명된 USD 총액·소계·세금·유효한 환율로 검증할 수 있을 때만 허용한다. 공급자 금액 최소 단위의 반올림 오차 안에서 환산 결과와 일치해야 하며 할인·설정 비용·위조된 금액은 거절한다.
- 공급자의 `partial_refund` 상태를 처리한다. 부분 환불은 권한을 유지하고 전체 환불은 회수하며, 늦게 온 결제 이벤트로 회수된 권한이 다시 활성화되지 않는다.
- HMAC 서명, 주문·스토어·상품·통화 검증, Test/Live 분리, 서버 전용 결제 반영 RPC와 호출자 RLS를 유지했다. 기존 무료 초대 코드는 유지했다.
- 진단 v20은 정적인 단계·오류 코드만 로그에 남긴다. 요청 본문·메일·주문 ID·비밀값을 기록하지 않는다. 수정 v21을 배포하고 원격 파일 5개가 로컬 소스와 일치함을 확인했다. 웹훅의 기존 HMAC 인증과 `verify_jwt=false`를 유지했다.

## 검증

- 변경 전 Node/PGlite 38개, 진단 보완 후 39개 통과. 실제 세금 포함 형식으로 기존 결함을 두 검사에서 재현한 뒤 수정 후 전체 41개 통과(실패·건너뜀 0).
- 익명화한 실제 금액 형식으로 예약·체크아웃·서명 결제·Live 권한·중복·부분/전체 환불·늦은 결제 이벤트를 검사했다. 잘못된 환율·USD 증빙·상품 가격·총액·할인·설정 비용의 반영 차단을 확인했다.
- 공개 진단 v20의 GET은 405, 서명 없는 POST와 잘못된 서명은 401이었다. 최종 v21의 서명 검증 회귀 검사도 통과했다.
- 운영 v21의 실제 결제 재전송·중복 재전송 HTTP 200, 주문 `paid`, Live 권한 `active`, 이벤트 1개를 확인했다. 실제 환불 거래는 실행하지 않았으며 환불 검증은 자동 검사에 한정한다.
- `git diff --check` 통과. 앱 C#·공개 설치본·웹 UI는 수정하지 않았다.

## 앱에서 이용

현재 앱은 로그인·저장된 로그인 복원·결제 확인에서 `get-app-access`를 조회하고 `active`일 때 이용을 허용한다. 결제한 계정으로 앱을 재시작하거나 진행 중인 결제 화면의 결제 확인을 누르면 갱신된 권한을 조회한다. 고객의 실제 앱 화면에서 잠금 해제를 직접 확인하지는 않았다.
