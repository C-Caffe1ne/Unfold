# UI/UX 재검수 — 2026-09-18

## 결론

현재 UI는 색상·카드·입력 필드·탭 구조가 대체로 일관되고, 기본 크기와 최소 크기에서 가로 넘침 없이 동작한다. 우선 보완할 부분은 **날짜 변경 후 기록 갱신, 작성 중인 펫의 종료 보호, 휴식 상태 표시, 설정의 저장 상태 구분**이다. 펫 만들기 첫 화면의 조작 노출과 비활성 아이콘도 개선이 필요하다.

아래 12개 항목은 확정 결함과 사용성 개선을 구분했다. 실제 OS 입력 확인이 필요한 항목은 별도의 검증 목록으로 분리했다. 이번 작업에서는 제품 코드·테스트·자산을 수정하지 않았다.

## P1 — 우선 수정

### UX-01. 기록 화면의 날짜가 고정된다

- **상태/영향:** 기록 탭을 한 번 연 뒤 앱을 밤새 실행하면, 다음 날 휴식을 완료해도 이전 날까지의 7일이 계속 표시된다. 새로고침·탭 재진입으로도 최신 날짜가 반영되지 않는다. 홈의 ‘오늘’ 집계와 기록 화면이 달라질 수 있다.
- **근거:** `BreakReviewWindow.cs:40,57,85–115`의 `today`는 생성 시 한 번 정해지는 readonly 값이다. `Refresh()`는 기존 `endDay`만 읽는다. `SettingsWindow.Layout.cs:168–170`은 같은 `reviewPage`를 계속 사용한다.
- **확인 수준:** 코드 경로 확인. 실제로 자정을 기다리는 장시간 재현은 하지 않았다. [현재 기록 화면](images/2026-09-18-ui-ux-audit/settings-review-tab.png)은 일반 배치 참고이며 자정 재현 증거는 아니다.
- **수정 방향:** 현재 날짜를 새로 읽고, 최신 기간을 보고 있었다면 새 날짜를 따라간다. 사용자가 과거 기간을 보고 있었다면 조회 위치를 유지한다.
- **완료 기준:** 날짜 공급원을 바꾼 자동 검사에서 최신 기간·다음 버튼·CSV 범위가 새 날짜를 반영하고, 과거 조회는 유지된다. macOS/Windows에서 다음 날 탭 재진입도 확인한다.

### UX-02. 펫 작성 중 앱 종료에 대한 보호가 없다

- **상태/영향:** 이름과 행동 파일을 넣은 뒤 사이드바 종료 또는 트레이 종료를 선택하면, 만들던 펫이 저장 안내 없이 사라진다. 탭 전환·창 숨김 시 유지되는 초안과 종료 시 동작이 다르다.
- **근거:** `CustomPetWindow.cs:30`의 초안은 메모리에만 있다. `AppRuntime.cs:368–379`의 종료 확인은 진단용 픽셀 편집기만 확인하고 펫 작성 초안은 확인하지 않는다. `docs/settings-ui.md:40–41`에도 종료 시 미저장 초안 소멸이 명시되어 있다.
- **분류:** 현재 명세대로 동작하지만, 사용자가 투입한 작업을 보호할 필요가 있는 P1 개선이다. 원본 GIF/MP4가 삭제된다는 의미는 아니다.
- **수정 방향:** 변경된 초안이 있을 때 종료 취소·버리기·저장 선택을 제공한다. 완성 조건이 부족하면 작성 화면으로 돌아가 수정하도록 한다. 취소를 기본 선택으로 유지한다.
- **완료 기준:** 파일 배정·교체·제거·이름 변경이 미저장 상태에 반영되고, 종료 취소 시 그대로 남는다. 성공적으로 내보낸 뒤 변경이 없다면 불필요하게 경고하지 않는다. 탭 전환과 창 숨김에는 확인창을 추가하지 않는다.

## P2 — 상태와 조작 개선

### UX-03. 휴식 대기와 진행이 홈에서 같은 상태로 보인다

- **상태/영향:** 말풍선에 ‘휴식 시작’이 남아 있는 초대 단계에서도 홈은 ‘휴식 중 · 타이머 대기’라고 표시한다. 실제 휴식을 시작했는지 혼동할 수 있다.
- **근거:** `SettingsWindow.cs:149–153`은 `ActiveReminder != null`만 검사한다. `AppRuntime.cs:62,276–286`상 초대 단계에도 세션이 존재한다. 트레이는 이미 `AppRuntime.cs:32–38`에서 대기와 진행을 구분한다.
- **수정 방향:** 홈도 `PetNotice.Invitation`과 `PetNotice.Resting`을 구분해 ‘휴식 대기 중’ / ‘휴식 중’을 표시하고 작업 타이머가 멈춘 이유를 일치시킨다.
- **완료 기준:** 초대→시작→초과→완료/미루기/중지 상태에서 홈·말풍선·트레이의 의미가 일치한다. [초대 말풍선](images/2026-09-18-ui-ux-audit/speech-top.png)은 초대 UI 근거이며 홈 오표시는 코드 확인이다.

### UX-04. 저장된 값과 편집 중인 값이 명확히 구분되지 않는다

- **상태/영향:** ‘저장했어요’가 나온 뒤 값을 다시 바꿔도 성공 문구가 남는다. 같은 알림 설정 카드 안에서 위치·효과음 사용은 ‘적용’이 필요하지만 WAV 가져오기·기본 복원은 즉시 저장된다. 미적용 간격을 편집한 뒤 재생하면 이전 값으로 되돌아가는 동작도 설명이 부족하다.
- **근거:** `SettingsWindow.cs:117–139,165–175`에 저장 결과 표시와 진행 시 간격 복원이 있지만 입력 변경 시 미적용 상태 처리가 없다. `SettingsWindow.Notifications.cs:22–30,40–63`의 저장 시점이 서로 다르다. [설정 화면](images/2026-09-18-ui-ux-audit/settings-options-overview.png).
- **수정 방향:** 적용형 설정은 저장값과 초안을 비교해 ‘변경사항 있음’을 표시하고 저장 후에만 해제한다. 알림 카드 내 WAV 변경까지 적용으로 통일하는 것을 권장한다. 즉시 저장을 유지한다면 해당 행에 이를 명시한다. 재생으로 미적용 간격이 버려질 때도 상태를 설명한다.
- **완료 기준:** 입력→미적용→성공/실패가 구분되고, 실패한 값이 저장된 것처럼 보이지 않는다. 값을 다시 편집하면 과거 성공 메시지가 사라진다. 적용이 작업 타이머를 임의로 시작하지 않는다.

### UX-05. 다른 행동을 지워도 재생 중인 미리보기가 사라진다

- **상태/영향:** 쉬는 모습과 스트레칭 파일을 넣고 스트레칭을 미리보는 중에 쉬는 모습 파일을 제거하면, 남아 있는 스트레칭 미리보기까지 비워진다. 현재 어떤 행동을 보고 있는지 별도 표시도 없다.
- **근거:** `CustomPetWindow.cs:78–81`이 제거한 key와 무관하게 `preview.SetFrames([], true)`를 호출한다. `Preview()`의 key는 지속되는 선택 상태로 저장되지 않는다(`255–267`).
- **수정 방향:** 현재 미리보기 행동을 추적한다. 그 행동을 제거했을 때만 미리보기를 비우고, 재생 중인 카드에 선택 상태나 행동명을 표시한다.
- **완료 기준:** 다른 카드 제거 시 현재 재생은 유지되며, 현재 카드 제거 시에만 빈 상태로 전환한다. 파일명은 카드에 다시 표시하지 않고 기존의 사이즈·프레임·시간 표기를 유지한다.

### UI-01. 비활성 아이콘과 오류가 정상 상태처럼 보인다

- **상태/영향:** 빈 펫 팩의 일시정지·재생, 파일이 없는 행동의 미리보기·제거 아이콘이 밝게 남는다. 팩 열기 실패는 일반 안내와 같은 muted 색이고, 알림 설정 저장 실패도 색상 구분이 없다.
- **근거:** `PetPackWindow.cs:126,134`와 `CustomPetWindow.cs:303–304,335–340`의 아이콘에 Cream이 직접 설정된다. 공통 비활성 색은 presenter에 적용되어 아이콘의 로컬 색을 바꾸지 못한다. `PetPackWindow.cs:89,199,218,233–236`과 `SettingsWindow.Notifications.cs:30,52,63`의 오류 경로는 오류 색을 설정하지 않는다.
- **수정 방향:** 공통 아이콘 버튼이 enabled/disabled/danger 상태 색을 상속하도록 통일한다. 오류에는 명시적 실패 문구와 오류 색을 사용하고 성공·재시도 시 정상 색으로 복귀시킨다.
- **완료 기준:** [빈 팩 화면](images/2026-09-18-ui-ux-audit/settings-pet-open-tab.png), [빈 행동 카드](images/2026-09-18-ui-ux-audit/settings-pet-create-minimum-scrolled.png)에서 조작 가능 여부가 구분된다. [팩 오류 화면](images/2026-09-18-ui-ux-audit/pack-error.png)과 성공 상태의 의미가 다르게 보인다. 팩 오류 캡처는 같은 View를 사용하는 진단용 별도 창이며 상단 제목 복원을 제안하는 근거가 아니다.

### UI-02. 작은 창에서 첫 파일 추가가 화면 아래에 있다

- **상태/영향:** `860×680`의 펫 만들기 첫 화면에서 카드 이름만 보이고 + 버튼은 본문 아래로 가려진다. 첫 파일을 넣으려면 스크롤부터 해야 한다. 스크롤하면 모든 행동에 도달할 수 있으므로 조작 불가능 문제는 아니다.
- **근거:** [스크롤 전](images/2026-09-18-ui-ux-audit/settings-pet-create-minimum.png) / [스크롤 후](images/2026-09-18-ui-ux-audit/settings-pet-create-minimum-scrolled.png). `CustomPetWindow.cs:131–156`의 미리보기와 상단 설명이 작은 높이에서도 같은 공간을 차지한다.
- **수정 방향:** 높이가 작은 창에서는 미리보기 높이·여백을 줄여 첫 줄 카드 버튼을 노출한다. 다섯 카드는 현재처럼 줄바꿈하고 가로 스크롤을 만들지 않는다.
- **완료 기준:** 최소 창 첫 화면에서 필수 ‘쉬는 모습’ 카드의 + 버튼이 온전히 보이며, 두 번째 줄은 세로 스크롤로 접근할 수 있다. 하단 만들기 버튼은 계속 고정된다.

### UX-06. 설정에서 효과음을 확인할 수 없다

- **상태/영향:** 사용자가 가져온 소리가 맞는지 실제 알림이 발생하기 전에 확인할 수 없다. 두 소리 모두 ‘가져온 WAV’로 표시되어 서로 식별하기 어렵다.
- **근거:** `SettingsWindow.Notifications.cs:35–73`의 각 행에는 파일 가져오기와 기본 복원만 있다. 파일 식별 정보와 재생 버튼은 없다.
- **수정 방향:** 짧은 미리듣기/정지 버튼과 가져온 소리의 표시명을 제공한다. 긴 이름은 줄임표·툴팁으로 처리한다. 카드 레이아웃과 가져오기 제한 안내를 유지한다.
- **완료 기준:** 알림·완료 소리를 각각 확인할 수 있고 동시 재생은 겹치지 않는다. 디코딩·장치 오류를 표시한다. 실제 음량·지연·체감은 macOS/Windows에서 별도 청취한다.

### A11Y-01. 키보드 위치와 현재 탭의 의미 전달이 부족하다

- **상태/영향:** 입력류의 호버·포커스 시각 상태가 동일하고 FocusAdorner가 제거되어 있다. 특히 선택 필드에서 키보드 이동 위치를 찾기 어렵다. 사이드바는 버튼의 클래스·색상만 바뀌고 선택된 탭의 의미가 명시적으로 제공되지 않는다.
- **근거:** `DesignSystem.cs:80–97` 및 NumericUpDown 내부 템플릿, `SettingsWindow.Layout.cs:190–223`. 버튼 접근성 이름은 이미 있으므로 이름 자체가 없다고 판단하지 않는다. TextBox의 편집 캐럿까지 없다는 의미도 아니다.
- **수정 방향:** 사용자가 요청한 입력 필드의 호버·포커스 테두리 제거는 유지한다. **키보드 이동일 때만 라벨 또는 별도 표시로 현재 위치를 알려주는 방식**을 설계한다. 내비게이션에는 선택 상태를 전달하고 탭별 포커스 진입 규칙을 통일한다.
- **완료 기준:** Tab/Shift+Tab으로 현재 위치를 식별하고 선택 탭을 보조기술로 알 수 있다. 마우스 호버 때 입력 배경·테두리가 다시 변하지 않는다. 실제 읽기 결과는 VoiceOver/Narrator로 확인해야 한다.

### VIS-01. 기본 펫의 동작 전환에서 배경과 크기가 바뀐다

- **상태/영향:** 기본 Mochi가 쉬는 모습에서는 투명 배경으로 보이지만 스트레칭에서는 베이지색 사각형과 작은 캐릭터로 바뀐다. 같은 펫이 자연스럽게 움직인다는 인상이 약해진다.
- **근거:** [쉬는 모습](images/2026-09-18-ui-ux-audit/speech-five-minutes.png) / [스트레칭 이후 프레임](images/2026-09-18-ui-ux-audit/speech-overtime.png). `Assets/Characters/default-cat/character.json`은 idle에 spritesheet, stretch에 별도 GIF를 사용한다. `SmokeDiagnostics.cs:106`에서 기본 펫을 명시적으로 선택한 캡처다.
- **수정 방향:** 기본 팩의 투명 배경, 캐릭터 화면 점유율, 바닥 기준점을 통일한다. 사용자가 가져온 MP4 배경을 자동 제거하는 새 요구사항으로 확대하지 않는다. 보리 팩 완성도 작업과도 별도다.
- **완료 기준:** 같은 192px 영역에서 idle→stretch→idle 전환 시 사각형 배경과 급격한 크기 변화가 없다. 밝은/어두운 바탕과 모든 프레임에서 시각 확인한다.

## P3 — 표현과 밀도

### UI-03. 시간 설정의 명칭과 보조 설명

- **문제:** ‘스트레칭 시간 (분)’은 실제로 작업 후 알림까지의 간격이다. 바로 아래의 ‘휴식 시간’과 지속 시간처럼 읽힐 수 있다. 이 차이를 설명하는 글씨는 10px, 라벨·저장 안내는 11px다.
- **근거:** `SettingsWindow.Layout.cs:132–138`, [홈 최소 창](images/2026-09-18-ui-ux-audit/settings-minimum.png).
- **제안/완료 기준:** ‘스트레칭 알림 간격 (분)’처럼 의미를 명확히 하고 보조 설명을 공통 caption 크기에 맞춘다. 홈으로 옮긴 배치는 유지하며 최소 창에서 줄바꿈·높이를 다시 확인한다.

### UI-04. 짧은 말풍선의 빈 공간

- **문제:** 5분 전 알림·완료 알림에도 휴식 타이머와 같은 `320×268` 영역을 사용해 화면을 많이 차지한다.
- **근거:** `PetSpeechBubble.cs:20,33,75–84`, [5분 전 알림](images/2026-09-18-ui-ux-audit/speech-five-minutes.png).
- **제안/완료 기준:** 사전·완료 알림은 내용에 맞는 작은 높이를 사용하고 초대·타이머는 충분한 버튼 영역을 유지한다. 말풍선 높이와 네 방향 배치 계산을 함께 바꿔 화면 밖 잘림·펫 위치 이동·클릭 영역 불일치를 방지한다.

## 이미 확인된 개선과 유지할 사항

- 진단 범위에서 가로 스크롤과 가로 넘침은 없다. 펫 행동 카드는 고정 크기·줄바꿈을 사용한다.
- 파일명은 행동 카드에서 생략하고 사이즈·프레임·시간만 표시한다.
- 펫 팩 열기 버튼은 동작 드롭다운 옆, 재생 조작은 미리보기 아래 중앙에 있다.
- 홈·설정·기록·펫 추가가 같은 창에서 전환되고 큰 페이지 헤더는 제거되어 있다.
- 일반 내비게이션의 루틴·프로필 편집 진입점은 제거되어 있다.
- 팩 경고 요약과 설치 버튼의 하단 노출, 기존 행동 파일 교체 확인, 접힌 휴식 알림의 배지·트레이 복구가 구현되어 있다.
- 기록의 날짜별 상세 펼침은 현재 구현되어 있다. 과거 감사의 ‘상세 없음’ 지적을 재사용하지 않는다.
- 입력 숫자의 왼쪽·세로 중앙 정렬과 단일 테두리 방향을 유지한다. 포커스 개선을 이유로 기존 호버 효과를 되살리지 않는다.

## 권장 진행 순서

1. **정확성과 작업 보호:** UX-01 기록 날짜, UX-02 초안 종료 보호, UX-03 휴식 상태. 날짜 전환·종료 취소·상태 전이 회귀 검사.

3. **공통 상태와 접근성:** UI-01 아이콘/오류 상태, A11Y-01 키보드 표시·탭 선택 의미, UX-06 효과음 확인. 말풍선 키보드 진입도 실기 확인.
