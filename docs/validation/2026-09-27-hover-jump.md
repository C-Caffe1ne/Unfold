# 클릭·호버 순간 펫 위치 튐 수정 — 2026-09-27

## 원인

말풍선을 열고 닫을 때 네이티브 창 위치는 즉시 변경됐지만 `Canvas.Left/Top`은 다음
배치 단계에서 반영됐다. 창이 이동하는 순간 펫은 이전 내부 좌표에 남았다. 수정 전 회귀
검사에서 위·아래·왼쪽 방향 3개가 실패했고, 왼쪽 말풍선은 252px, 위쪽은 가로 24px·세로
108px의 일시적인 차이를 기록했다. 최종 배치만 확인하던 기존 검사는 이를 놓쳤다.

배치를 먼저 갱신하는 것만으로는 충분하지 않았다. 명시적 크기를 가진 캔버스가 이전
클라이언트 영역 안에서 잠깐 가운데로 정렬됐다. 또한 누름과 호버 표시가 연달아 발생하면
드래그가 말풍선 표시 전 창 위치를 기준으로 계산될 수 있었다.

수정 전 macOS 진단 로그에서도 기본 자세의 창 이동 이벤트 중 실제 펫 원점과 논리 원점이
다른 사례 28개를 확인했다. 이는 좌표 불일치의 근거이며, 모든 영상 프레임을 검사한 결과는 아니다.

## 변경

- 캔버스의 가로·세로 정렬을 왼쪽·위쪽으로 고정해 크기 전환 중 원점을 유지한다.
- 펫과 말풍선의 배치를 확정한 다음 네이티브 창 위치를 변경한다.
- 드래그 시작점은 창 원점 대신 펫의 화면 좌표로 저장한다.
- 포인터 이동량은 애니메이션 변형에 영향을 받지 않는 창 좌표와 화면 배율로 계산한다.
- 기존 짧은 클릭·누름 유지 구분과 펫별 리소스는 유지한다.

변경 코드: `src/Unfold.Desktop/PetWindow.cs`.
회귀 검사: `Tests/Unfold.Tests/PetHoverTests.cs`.
기존 미커밋 클릭 분리 작업 및 별도의 Rive 작업 파일은 보존했다.

## 실제 macOS 진단

새 프로필 `native-after-ui`에서 출하 앱과 같은 렌더링 설정을 사용하는 네이티브 창을 열었다.
CUA로 첫 호버·클릭, 연속 클릭 10회, 가로 30px·세로 20px 드래그를 수행했다.
전체 진단 로그의 펫 누르기·놓기는 각각 14회다.

- 최초 호버 배치 후 펫 원점은 `(750, 350)`으로 유지됐다.
- 이후 클릭 중 창 크기·위치가 추가로 변경되지 않았다.
- 드래그 후 원점은 `(780, 370)`으로 입력 이동량과 일치했다.
- 창 위치 변경은 호버 확장과 드래그의 2회이며, 두 이벤트 모두 실제 펫 원점과 논리 원점이 일치했다.
- 클릭·드래그 후 화면 캡처에서 펫과 시간 말풍선을 확인했다. 진단 앱에 종료 명령을 보냈다.

근거: `native-result.json`, `native-before-ui/events.jsonl`, `native-after-ui/events.jsonl`.
하네스는 같은 증거 폴더의 `native-harness/`에 있다.
