## FOLLOW-01 — 펫 파일 오류로 휴식 알림도 누락

**발생 조건:** 이미 설치된 사용자 펫의 `idle.gif` 내용이 손상되거나 읽기에 실패하는 경우다.
정상적인 펫 가져오기에서 손상 파일을 허용한다는 뜻은 아니다.

`ShowReminder()`는 idle 클립을 읽은 뒤에야 휴식 세션을 만들고 알림 효과음을 요청한다.
앞 단계가 실패하면 로그만 남기고 반환한다. 화면에 알림 실패를 표시하거나 다른 기본 펫으로
대체하는 경로가 없다. 자동 타이머는 알림 요청 직전에 이미 남은 시간을 전체 간격으로
되돌리므로, 한 번의 일시적인 로딩 실패도 그 회차 알림을 건너뛸 수 있다.

**재현:** 임시 사용자 팩의 유효한 manifest·PNG는 유지하고 idle GIF만 손상시켰다.
일반 실행 모드의 `ShowReminder()` 호출 후 `Notice=None`, `Session=null`, 효과음 요청 0회였다.
파일 복구 후 동일 메서드는 `Invitation`과 효과음 요청 1회로 정상 진행했다.
실제 오디오 출력은 음량 0으로 막았다. 실제 작업 간격 전체를 기다린 검사는 아니다.

- 근거: [AppRuntime.cs](../../src/Unfold.Desktop/AppRuntime.cs) 152–165, 294–318행;
  [StretchClock.cs](../../src/Unfold.Core/StretchClock.cs) 46–53행.
- 최소 수정 방향: 펫 이미지 로딩 실패와 알림 세션 생성을 분리한다. 기본 펫 대체 또는
  복구 가능한 알림 오류 상태를 제공하되, 무한 재시도·중복 알림은 막는다.
- 완료 기준: 손상된 사용자 idle, 일시적 파일 접근 실패에서도 휴식 도래 사실을 전달하고,
  복구 후 하나의 세션만 진행한다. 중지·종료 중인 과거 요청은 되살리지 않는다.

## FOLLOW-02 — 복구된 펫이 홈 미리보기에 반영되지 않음

홈 화면은 로딩 성공 전에 `previewCharacter`를 새 펫으로 변경한다.
이후 로딩 실패는 로그만 남기며 이전 이미지도 남는다. 다음 화면 갱신에서는 이미 해당 펫을
표시한 것으로 판단해 재시도하지 않는다. 이름·선택 값은 새 펫인데 그림은 이전 펫일 수 있다.

**재현:** 1프레임 시험용 펫 A를 표시한 뒤 손상된 idle GIF를 사용하는 펫 B를 선택했다.
B 파일을 정상 4프레임 GIF로 복구했고 `runtime.Clip("idle")`도 4프레임을 반환했지만,
일반 런타임 갱신 후 홈은 A의 1프레임을 유지했다. `previewCharacter` 값은 B였다.

- 근거: [SettingsWindow.cs](../../src/Unfold.Desktop/SettingsWindow.cs) 255–275행.
- 최소 수정 방향: 선택된 펫과 실제 표시 완료된 펫을 분리하고, 실패 시 이전 펫을 새 펫처럼
  표시하지 않는다. 명시적인 재시도 또는 제한된 재시도를 연결한다.
- 완료 기준: A→B 로딩 실패→B 복구에서 홈과 바탕화면의 펫이 일치한다.
  늦게 완료된 A의 로딩이 새 선택 B를 덮어쓰지 않으며 숨김·종료 후 재생하지 않는다.

앞서 고친 실패 클립 캐시와 바탕화면 반응 복귀는 정상 동작한다.
이 항목은 그 캐시 위에서 홈 화면이 다시 요청하지 않는 별도 소비자 문제다.

## FOLLOW-03 — 미사용 효과음 파일 정리

이전 감사의 **AUD-03**이며 새로 발생한 회귀는 아니다.
효과음 파일은 가져오기 즉시 `Sounds/<hash>.wav`에 복사된다.
하단 취소·기본 복원·다른 파일 선택은 참조만 바꾸므로 서로 다른 파일을 반복 가져오면
사용하지 않는 사본이 누적된다. 파일당 5 MiB 제한은 폴더 전체 용량을 제한하지 않는다.

- 근거: [ReminderSounds.cs](../../src/Unfold.Core/ReminderSounds.cs) 11–19행;
  [SettingsWindow.Notifications.cs](../../src/Unfold.Desktop/SettingsWindow.Notifications.cs) 116–136행;
  [SettingsWindow.Preferences.cs](../../src/Unfold.Desktop/SettingsWindow.Preferences.cs) 140–143행.
- 수정 방향: 저장된 설정·현재 초안·재생 중 파일이 참조하지 않는 사본만 정리한다.
- 완료 기준: 가져오기→취소와 반복 교체 후 미사용 파일이 계속 늘지 않고,
  스트레칭·완료 알림이 공유하는 파일은 보존된다.

패치노트 설명 수정은 이전 사용자 요청에 따라 이번 수정 후보에서 제외했다.

## 배포와 플랫폼에서 남은 사항

**RELEASE-01:** 현재 소스의 버전과 기존 ZIP의 버전은 모두 0.2.1이지만 내용은 다르다.
`artifacts/Unfold-v0.2.1-{osx-arm64,osx-x64,win-x64}.zip` 내부 `Unfold.dll`에는
현재 어셈블리에 있는 `RefreshHover`와 `MacPetWindow` 식별자가 없다.
배포 기록도 9월 22일 소스를 기준으로 한다. 따라서 기존 ZIP 재설치로는 최근 호버 시계,
클릭 중 창 유지, macOS 전체화면 표시 변경이 적용되지 않는다.
기존 배포물은 보존하고 다음 배포에 새 버전·빌드 구분과 패키지 검증을 권장한다.

다음은 확인된 새 결함과 구분한 **기존 제약·검증 공백**이다.

- macOS 투명 영역은 뒤의 다른 앱으로 클릭을 통과시키지 않는다.
  `PetWindow.UpdateClickThrough()`는 Windows 전용이며 [플랫폼 안내](../cross-platform.md)에도
  명시된 제약이다. 호버 말풍선으로 창 영역이 커진 만큼 실제 작업 방해 여부를 확인할 가치가 있다.
  이번 감사에서 macOS 클릭 통과를 직접 조작해 재검증하지는 않았다.
- 앞선 현재 Mac의 40회 연속 클릭 기록은 창 크기·위치 안정성 근거다.
  모든 중간 프레임의 잔상 소멸, 다른 GPU, Windows·Intel Mac을 증명하지 않는다.
- Windows·Intel Mac 배포본의 실제 입력, 로그인 자동 실행, 다중 모니터·배율 전환 검증이 남아 있다.
- CI는 Windows 게시 앱 smoke를 정의하지만 macOS는 번들 생성까지다.
  macOS 게시 앱 smoke·기본 펫 진단을 자동화하고, Intel 대상 검사 범위를 정할 필요가 있다.
  CI 정의를 확인했으며 원격 실행 결과는 조회하지 않았다.
