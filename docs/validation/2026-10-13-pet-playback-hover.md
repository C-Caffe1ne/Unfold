# 펫 행동 반복·타이머 호버 후속 검증

## 기준과 원인

`codex/pet-overlay-hover`, `09853c7`, `1.1.3-beta`와 직전 타이머 분리 변경을 이어서 수정했다.
최신 개발 기준 `codex/gif-glb-import-guidance`와 HEAD가 같고, 이 대화의 미커밋 타이머 변경을 보존했다.
다른 작업트리의 소스·사용자 데이터·배포 버전은 수정하지 않았다.

- GLB 들어올리기는 `pickup.Loop`가 저장돼도 런타임에서 항상 한 번만 재생했다.
- 이미지·영상의 한 번 재생 `pointerDown`은 누르고 있어도 완료 후 기본 동작으로 복귀했다.
  눌림 도중 알림이 도착하면 눌림 동작을 덮는 경로도 있었다.
- 클릭·놓기·하품·잠자기는 이미 완료 이벤트를 기다리는 구조였다.
  이번에는 긴 클립·핑퐁·GLB 속도 설정을 포함해 전체 시간과 마지막 디코딩 프레임을 검사했다.
- 직전 타이머는 펫 진입 후 2초로 표시를 제한했고, 타이머 이탈 후에도 2초 기다렸다.

## 변경과 소유 범위

GLB 들어올리기의 반복은 누르는 동안 유지한다. 완료 이벤트가 없는 반복 클립은 바로 Held 상태로 둔다.
한 번 설정이면 끝 자세를 놓을 때까지 유지한다. 기본 2D의 pickup → held → land 흐름을 유지하며,
이미지·영상 눌림도 반복 또는 끝 자세를 유지한다. 눌림 중 알림은 유예하고 놓기 전체 재생 후
아직 유효한 알림을 재개한다. 클릭·놓기·하품·잠자기는 전체 재생 후 기본 동작으로 복귀한다.
진행 중인 휴식·알림의 기존 동작 소유권은 보존한다.

타이머는 펫 또는 조작 바 위에서 계속 표시한다. 두 영역을 벗어나면 대기 없이 180ms 페이드 아웃을 시작한다.
펫을 누르면 즉시 숨기고, 영역 밖으로 나가기 전에는 다시 표시하지 않는다.
누름 시점 몸체 영역을 펫 내부 좌표로 저장하므로 클릭 애니메이션의 투명 픽셀 변화나
펫 창 드래그가 커서 이탈로 오인되지 않는다. 펫·알림·타이머의 별도 창 구조는 유지한다.

감독자는 `PetWindow.cs`, `PetWindow.Companion.cs`, `PetWindow.PointerArt.cs`,
`PetTimerReveal.cs`, `PetTimerWindow.cs`와 기존 재생 검사를 소유했다.
테스트 워커는 `PetTimerHoverTests.cs`만 수정했고, 구조 워커는 읽기 전용 검토를 수행했다.
저장 형식·반복 선택 UI·캐릭터 자산·버전은 변경하지 않았다.

## 실제 macOS 관찰

최종 제품 DLL과 SHA256이 같은 격리 검증 호스트에서 실제 네이티브 펫·타이머 창을 실행했다.
단축키로 실제 커서 아래에 창을 이동하고 제품의 커서 폴링을 관찰했다.
들어올리기·놓기 상태는 단축키로 제품 메서드를 호출했다. 실제 네이티브 누름 이벤트도 샘플에 기록됐다.
검증 호스트의 데이터는 `/tmp/unfold-pet-playback-hover-20261013/profile-final/`에만 저장했다.

- GLB의 14초 들어올리기 클립이 여러 차례 반복하며 pickup/Held를 유지했고, 타이머는 숨김을 유지했다.
- 놓기 `Move_End_Normal`은 지정 길이 약 1.533초를 모두 재생하고 약 1.598초 뒤 idle로 복귀했다.
- 실제 커서가 몸체를 벗어난 뒤 다음 폴링에서 페이드가 시작됐다. 2초 대기는 발생하지 않았다.
- 실제 펫 누름이 시작된 샘플에서 타이머 불투명도가 바로 0이 됐다.
- 관찰 구간에서 펫 창 288×288과 내부 원점 (0,0)이 유지됐다. 사용자·검증 단축키의 드래그와
  위치 변경은 창 위치 불변 검사에서 제외했다.

[네이티브 샘플 요약](2026-10-13-pet-playback-hover/native-evidence.json)에 시각·프레임 순환·창 계측을 보관했다.
헤드리스 완료 이벤트와 마지막 디코딩 프레임 검사는 모든 최종 포즈가 네이티브 화면에
한 프레임씩 표시됐다는 영상 증거와 구분한다. Windows 실기 입력, 혼합 DPI·여러 모니터,
장시간 동작 및 모든 최종 포즈의 연속 영상 분석은 이번 검사에 포함하지 않았다.
