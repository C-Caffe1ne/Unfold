# 펫 추가 · 동작별 GIF/MP4 가져오기 검증

2026-09-16 · `release/mvp`, 기준 커밋 `a42d492` 위의 작업 트리.
macOS arm64, .NET SDK 10.0.401 / 런타임 10.0.12.

## 구현

- 설정의 ‘펫 팩 설치…’를 ‘펫 추가’로 바꾸고, 기존 팩 열기 옆에 ‘파일 가져오기’를 추가했다.
- 가져온 GIF/MP4에 동작을 선택하고, 다섯 동작 각각에 파일 배정·교체·제거·미리보기를 제공한다.
  쉬는 모습만 필수이며 이름을 입력해야 팩을 만들 수 있다.
- 생성한 `.unfoldpet`은 원본 GIF 시간·픽셀, 동작별 반복 설정, 고유 ID와 해시 목록을 보존한다.
  파일 저장 후 기존 미리보기→설치 흐름으로 돌아온다. 기존 팩 업데이트·재설치는 그대로다.
- MP4는 로컬 FFmpeg에서 소리 없이 최대 192px/12fps GIF로 변환한다. 입력은 128 MiB·10초
  이하이며, 긴 영상·손상 파일을 거부하고 취소·시간 초과 시 변환 프로세스와 임시 파일을 정리한다.
- 게시 스크립트/CI는 LGPL FFmpeg 8.1.2의 고정 배포 파일을 해시 검사 후 준비한다.
  소스 출처·라이선스와 Windows 의존 DLL도 함께 복사한다. 기존 작업 트리의 앱 버전과
  Windows `app/` 배포 구조를 보존하고 CI 스모크 경로를 그 구조에 맞췄다.

## 자동 검사

```sh
dotnet test Unfold.slnx -c Release --no-restore -m:1 -p:UseSharedCompilation=false
```

전체 **147개 통과, 실패·건너뜀 0**. 실제 LGPL FFmpeg로 H.264 MP4 변환, 움직이는 프레임,
GIF 시간·픽셀 보존, 길이 초과와 손상 영상 거부, 다섯 동작의 팩 생성→재열기→설치,
잘못된 교체 시 기존 파일 유지, 필수 idle 검증, 제작 취소와 기존 미리보기 유지까지 검사했다.

가져오기 완료 뒤 배정 패널 숨김·미리보기 보간, 파일 크기 오류 안내·변환 취소 처리까지
수정한 최종 Release 관련 테스트 **28개 재통과**.
마지막 Release 빌드는 경고·오류 0. `git diff --check`와 macOS 게시 스크립트 구문 검사도 통과했다.

변환 도구 준비는 macOS arm64/x64, Windows x64/arm64에 대해 해시 검사·압축 해제까지 완료했다.
Windows MSBuild 항목에서 실행 파일, 지원 DLL, 라이선스·소스 안내가 `Tools/`로 복사됨을 확인했다.
이는 Windows 실행 검증이 아니다.

## macOS 렌더링·설치 진단

```sh
dotnet run --project src/Unfold.Desktop -c Release --no-build -- --smoke-test
```

새 임시 데이터에서 종료 코드 0, [진단 JSON](2026-09-16-custom-pet.json)의 `success: true`와
`customPetGifAuthoringVerified: true`를 확인했다. 전체 PNG 30장 중 커스텀 제작 화면,
520×620 최소 크기의 마지막 동작까지 스크롤한 화면, 생성된 팩 미리보기를 직접 확인했다.
최소 크기를 실제 `ClientSize`로 검사하고 가로 넘침·하단 생성 버튼 잘림이 없음을 확인했다.
생성한 펫의 설치·선택과 기존 타이머 일시정지 유지도 확인했다.

이 진단은 macOS 네이티브 렌더러를 사용하되 화면 밖 창과 프로그램 방식 버튼 이벤트,
지정된 파일·저장 경로로 실행한다. 실제 OS 파일 선택창·수동 입력, Windows/Intel Mac에서의
실행, Windows Arm의 x64 변환 도구 실행은 미검증이다. 게시 스크립트를 통한 새 배포물 생성과
서명·공증은 이번 작업에서 실행하지 않았다. 짧은 진단의 자원 표본은 성능 판정으로 사용하지 않는다.
