# 루틴·업무 프로필·주간 회고

2026-09-13 · Plus 가치 검증을 위한 2차 데모 사용 안내.
현재 개발 빌드에서는 아래 기능을 결제 없이 사용할 수 있다. 상품별 가격·권한은 아직 구현하지 않았다.

## 여러 루틴 관리

Settings의 **My routines & work profiles**를 열고 **My routines** 탭을 사용한다.

- **New routine**: 이름과 1–3개 안내 문구·시간을 입력해 저장한다.
- **Edit routine**: 선택한 사용자 루틴의 내용과 이름을 바꾼다. ID는 유지한다.
- **Use routine**: 다음 휴식 초대에 사용할 루틴을 선택한다.
- **Delete routine**: 확인 후 삭제한다. 완료 기록과 이미 열린 휴식은 유지한다.

기본 루틴 3개는 편집·삭제할 수 없다. 사용자 루틴은 기존 `my-routine` 슬롯 1개와
추가 19개를 저장할 수 있다. 이 20개 한도는 현재 저장·UI 운영 범위이며 확정된
Free/Plus 과금 경계가 아니다. 각 단계는 1–300초, 전체는 600초 이내다.
빈 안내 문구는 해당 단계를 제외한다.

저장하면 그 루틴이 다음 초대에 선택된다. Settings의 기존 **Edit my routine**은
이전 버전의 개인 루틴 슬롯을 계속 편집한다. 업무 프로필이 참조하는 루틴은 해당
프로필의 루틴을 변경하거나 프로필을 삭제한 뒤 제거할 수 있다.

## 업무 프로필

**Work profiles** 탭에서 **New profile**로 이름·알림 간격·유휴 임계 시간·루틴을
묶어 저장한다. 예: ‘집중 작업 / 45분마다 / 3분 이상 자리를 비우면 일시 정지 / 손 쉬기’.
프로필은 최대 10개이며, 저장만으로 적용되지 않는다. **Apply profile**로 직접 전환한다.

새 프로필 적용이나 알림 간격 변경은 새 작업 간격을 예약한다. 사용자가 설정한 Pause는
유지한다. Stop 상태에서는 00:00을 유지하고 새 간격만 저장한다. Play로 새 간격을
시작하거나 Reset으로 새 간격을 표시한 채 대기한다. 같은 프로필을 다시 적용해 값이
바뀌지 않으면 남은 시간을 유지한다.
이미 열린 휴식은 초대를 열 때의 루틴·프로필 이름을 유지한다. 그 휴식을 완료한 뒤의
작업 간격은 현재 설정을 사용한다. 5분 미루기는 기존과 동일하게 활성 작업 시간을 센다.

적용된 프로필 이름은 Settings에 표시된다. 알림 설정을 직접 적용하거나 루틴을 저장·
선택하면 프로필 표시는 해제된다. 적용 중인 프로필을 편집·삭제해도 이미 적용된
알림 값은 유지하고 프로필 표시만 해제한다. 편집한 프로필은 다시 Apply해야 적용된다.
Settings의 알림 간격은 값을 바꾸면 즉시 저장·적용되며, 유휴 기준과 루틴 선택은
**Apply reminder settings**로 적용한다. Reset은 설정 간격으로 되돌린 뒤 일시정지한다.

시간대·요일별 자동 전환, 회의·전체화면 감지는 현재 없다. 프로필 전환은 수동이다.

## 7일 회고와 내보내기

Settings의 **Review & export**에서 오늘을 포함한 최근 7일의 완료 횟수, 날짜별
횟수와 계획된 휴식 시간, 기록이 있는 날의 수를 확인한다. 목표 달성률이나 연속 사용
벌칙은 두지 않는다. **Previous 7 days / Next 7 days**로 이전 구간을 볼 수 있다.
오늘을 포함해 최대 84일 범위를 표시하며 미래 날짜로 이동하지 않는다. **Refresh**는 현재
보이는 구간의 기록을 다시 읽는다.

**Export CSV**는 현재 화면의 7일을 저장한다. 파일 선택 창에서 사용자가 경로와
덮어쓰기 여부를 정한다. 내보내는 열은 다음과 같다.

| 열 | 의미 |
|---|---|
| `confirmed_at` | 완료 당시의 UTC offset을 포함한 시각 |
| `routine_id`, `routine_name` | 당시 루틴 ID·이름. 이전 기록에 이름이 없으면 ID 사용 |
| `planned_seconds` | 선택한 루틴의 계획 시간 |
| `character_id` | 초대 당시 캐릭터 ID |
| `profile_id`, `profile_name` | 초대 당시 적용된 프로필. 없거나 이전 기록이면 빈 칸 |

날짜 집계는 완료 시 기록된 현지 날짜를 사용한다. 이름은 나중에 바꾸거나 삭제해도
과거 기록이 바뀌지 않는다. CSV는 한글 호환을 위한 UTF-8 BOM, 따옴표·쉼표 처리,
수식으로 해석될 수 있는 텍스트의 앞부분 보호를 적용한다. 빈 구간도 헤더만 내보낼 수 있다.
서버 전송이나 자동 공유는 없다. 기록은 완료 버튼을 누른 사실이며 신체 활동 측정이 아니다.

## 저장·호환성

`settings.json`의 기존 개인 루틴은 그대로 보존하고 `additionalRoutines`, `workProfiles`,
`activeProfileId` 필드를 추가했다. 라이브러리의 참조·ID·개수·입력 범위를 검사한다.
유효하지 않은 새 라이브러리·프로필은 원본 설정을 별도 `.invalid-*` 파일로 보존한 뒤
기본 설정으로 실행한다. 기존 단일 루틴만 잘못된 경우의 기본값 복구는 유지한다.

`break-history.json`은 기존 version 1을 유지하며 이름과 프로필을 선택 필드로 추가했다.
옛 기록은 계속 읽는다. 최대 2,000건과 새 완료 추가 시 90일 보관 규칙을 유지한다.
한글 이름이 긴 기록도 저장 후 다시 읽을 수 있도록 읽기 한도를 4 MiB로 조정했다.
실제로 유지된 기록만 회고에 표시되므로 오래 사용한 앱의 전체 과거가 남는 것은 아니다.

세부 검증과 남은 OS 확인은 [2차 검증 기록](validation/2026-09-13-companion-stage2.md)을 따른다.
