# 기존 루틴·업무 프로필 호환과 주간 회고

2026년 10월 9일 · Beta v1.1.3 개발본의 데이터 이전 안내.

## 제거 범위와 데이터 이전

- 루틴·업무 프로필 설정 모델과 작성·검증 코드를 제거했다.
- 시작 시 기존 설정의 `breakRoutineId`, `customRoutine`, `additionalRoutines`, `workProfiles`, `activeProfileId`를 백업 없이 제거한다. 현재 타이머 간격·휴식 시간·자리 비움 시간과 펫·소리·테마 설정은 유지한다.
- 과거 완료 기록의 루틴·프로필 ID와 이름 스냅샷은 저장 데이터와 CSV에서 보존한다.
- 사용자 정정에 따라 타이머 화면의 펫 미리보기를 복원했다. 제거 대상은 별도 펫 팩 가져오기 미리보기 창이다. 펫 편집 미리보기는 유지한다.
- Piskel 코덱·픽셀 원본 편집 및 저장 코드를 제거했다. 라이브러리가 재생 가능한 패키지를 검증한 후 해당 폴더의 `source.piskel`만 백업 없이 삭제한다. 이미지·애니메이션·설치한 펫은 유지한다. 손상되거나 접근할 수 없는 패키지와 외부 링크는 삭제하지 않는다.
- 실제 사용자 데이터는 검증에 사용하지 않는다. [제거 검증](validation/2026-10-09-retired-feature-removal.md)을 참고한다.

## 7일 회고와 내보내기

설정의 **회고 · 내보내기**에서 오늘을 포함한 최근 7일의 완료 횟수, 날짜별
횟수와 기록된 휴식 시간(새 기록은 실제 진행 시간, 이전 기록은 계획 시간), 기록이 있는 날의 수를 확인한다. 목표 달성률이나 연속 사용
벌칙은 두지 않는다. **이전 7일 / 다음 7일**로 이전 구간을 볼 수 있다.
오늘을 포함해 최대 84일 범위를 표시하며 미래 날짜로 이동하지 않는다. **새로고침**는 현재
보이는 구간의 기록을 다시 읽는다. 기간 조작은 상단 기간 오른쪽의 아이콘 버튼으로 제공한다.

날짜 행을 펼치면 완료 당시의 시각(`HH:mm 완료`)과 실제 휴식 시간만 표시한다.
실제 시간이 없는 구형 기록은 상세에 “실제 휴식 시간 미기록”으로 표시하고,
상단·날짜별 합계는 기존 규칙대로 당시 목표 시간을 포함한다. 이 차이는 요약 카드에 안내한다.
완료 시각은 저장된 UTC offset의 시각을 유지한다. 이름을 숨겨도 CSV 열과 저장 데이터는 변경하지 않는다.
[2026-09-20 기록 UI 검증](validation/2026-09-20-review-ui-implementation.md).

**CSV 내보내기**는 현재 화면의 7일을 저장한다. 파일 선택 창에서 사용자가 경로와
덮어쓰기 여부를 정한다. 내보내는 열은 다음과 같다.

| 열 | 의미 |
|---|---|
| `confirmed_at` | 완료 당시의 UTC offset을 포함한 시각 |
| `routine_id`, `routine_name` | 당시 루틴 ID·이름. 이전 기록에 이름이 없으면 ID 사용 |
| `planned_seconds` | 선택한 루틴의 계획 시간 |
| `actual_seconds` | 시작부터 완료까지 실제 진행 시간. 기존 기록은 빈 값 |
| `character_id` | 초대 당시 캐릭터 ID |
| `profile_id`, `profile_name` | 초대 당시 적용된 프로필. 없거나 이전 기록이면 빈 칸 |

날짜 집계는 완료 시 기록된 현지 날짜를 사용한다. 이름은 나중에 바꾸거나 삭제해도
과거 기록이 바뀌지 않는다. CSV는 한글 호환을 위한 UTF-8 BOM, 따옴표·쉼표 처리,
수식으로 해석될 수 있는 텍스트의 앞부분 보호를 적용한다. 빈 구간도 헤더만 내보낼 수 있다.
서버 전송이나 자동 공유는 없다. 기록은 완료 버튼을 누른 사실이며 신체 활동 측정이 아니다.

## 저장·호환성

`settings.json`의 기존 개인 루틴은 그대로 보존하고 `additionalRoutines`, `workProfiles`,
`activeProfileId` 필드를 추가했다. 라이브러리의 참조·ID·개수·입력 범위를 검사한다.
유효하지 않은 새 라이브러리·프로필은 원본 설정을 별도 `.invalid-*` 파일로 보존한 뒤
기본 설정으로 실행한다. 기존 단일 루틴만 잘못된 경우의 기본값 복구는 유지한다.

`break-history.json`은 기존 version 1을 유지하며 이름과 프로필을 선택 필드로 추가했다.
옛 기록은 계속 읽는다. 최대 2,000건과 새 완료 추가 시 90일 보관 규칙을 유지한다.
한글 이름이 긴 기록도 저장 후 다시 읽을 수 있도록 읽기 한도를 4 MiB로 조정했다.
실제로 유지된 기록만 회고에 표시되므로 오래 사용한 앱의 전체 과거가 남는 것은 아니다.

세부 검증과 남은 OS 확인은 [2차 검증 기록](validation/2026-09-13-companion-stage2.md)을 따른다.
