# 펫 리소스 관리

2026-09-13 · Unfold의 C# 로더 계약을 기준으로 한다. Codex 앱용 펫 규격을 쓰지 않는다.

## 원본, 실행 자산, 판매 정보를 분리한다

| 위치 | 내용 | 원칙 |
|---|---|---|
| `Art/Characters/<id>/` | 제작 원장 `resource.json`, 향후 원본 `.aseprite`·작업용 PNG·제작 지시와 검수 기록 | 재편집할 수 있는 원본을 보존. 앱 번들 제외 |
| `Art/Characters/<id>/runtime/<id>/` | 별도 설치 후보의 manifest와 실행 PNG/GIF | `.unfoldpet`으로 내보내는 입력. 기본 번들에 자동 추가하지 않음 |
| `Assets/Characters/<id>/` | 런타임 `character.json`, 참조하는 PNG/GIF | 실행에 필요한 완성 산출물. 현재 프로젝트가 빌드·게시 시 복사하는 위치 |
| 사용자 데이터의 `Characters/<id>/` | 기존 사용자 패키지 | 하위 호환 유지. 진단이나 번들 갱신으로 덮어쓰지 않음 |
| 이후 판매 카탈로그/구매 기록 | 상품 가격·콘텐츠 버전·구매 권한 | 렌더링 manifest와 분리. 현재 미구현 |

ID는 한번 배포하면 유지한다. manifest의 `version: 1`은 파일 형식 버전이다.
`Art/Characters/<id>/resource.json`의 `contentVersion`은 그림·애니메이션의
개정 버전이다. 배포 팩을 만들 때 같은 버전을 별도 `pack.json`에 넣는다.
앱은 로컬 팩 파일을 열 때 이 값을 비교하며 원격 자동 업데이트는 하지 않는다.

제작 원장에는 제작자, 원본 위치, 권리 증빙, 원본·내보내기 도구, 수정 이력과 출시
상태를 남긴다. 생성형 도구를 썼다면 원본 결과·입력 참조의 출처·수정 내용을 남긴다.
Mochi 원장은 확인된 기존 실행 파일만 가리키며, 원본 제작 파일과 권리 증빙은
미확인으로 기록한다. 이 상태를 유료 팩 출시 승인으로 사용하지 않는다.

[보리 0.1.0](../Art/Characters/bori-rabbit/README.md)은 생성 원본 PNG·최종 프롬프트·
SHA-256을 보존한 별도 설치 후보다. `releaseStatus: art-candidate`,
`rightsStatus: commercial-review-pending`으로 관리한다. 생성 경로를 기록한 것은
상업적 권리 승인과 다르다. 256px 원본, alpha 1의 가장자리 잔여, 연속 재생·고DPI
미검수 항목도 [제작 원장](../Art/Characters/bori-rabbit/resource.json)에 남긴다.

## 런타임 계약과 상태

[CharacterLibrary](../src/Unfold.Core/CharacterLibrary.cs)는 version 1 manifest,
안전한 상대 파일 경로와 ID, 최대 4096×4096 시트, 필수 `idle`을 확인한다.
시트 셀은 최대 2048×2048이고, PNG 시트와 GIF를 지원한다. GIF는 최대 512프레임,
시트 애니메이션은 최대 4096개의 인덱스를 참조한다. 두 경로 모두 **클립당 디코딩
픽셀 128 MiB 한도**를 적용한다. 코덱의 한도는 상품 품질 목표와 다르다.

| 애니메이션 키 | 실행 시점 | 없을 때 | 새 판매용 팩 기준 |
|---|---|---|---|
| `idle` | 기본 대기와 미리보기 | 패키지 거부 | 필수, 자연스러운 루프 |
| `attention` | 휴식 초대 창이 열릴 때 | 현재 애니메이션 유지 | 개성 있는 짧은 초대 권장 |
| `stretch` | 사용자가 휴식 시작을 누를 때 | 현재 애니메이션 유지 | 필수, 1회 재생 |
| `celebrate` | 시간을 채운 뒤 사용자가 완료를 확인할 때 | 현재 애니메이션 유지 | 필수, 과하지 않은 1회 반응 |
| `click` | 펫의 짧은 일반 클릭 | 현재 애니메이션 유지 | 필수, 휴식 동작과 시각적으로 구분 |

현재 Mochi는 `idle`과 `stretch`만 제공한다. 기존 패키지에 선택 키를 강제하지
않고, 없는 반응을 다른 동작으로 대체하지 않는다. `LoadAnimation`의 일반 미리보기용
idle fallback은 유지하되 펫 이벤트 호출 전에 정확한 키 존재를 확인한다.
2026-09-18부터 기본 Mochi의 stretch는 기존 투명 PNG 시트의 8~15번 프레임을 왕복해 사용한다.
idle과 동일한 384×384 캔버스이며 15프레임·7fps·1회 재생이다. 불투명한 기존 `stretch.gif`는
보존하지만 런타임 manifest는 더 이상 참조하지 않는다. 원본 이미지를 재생성하거나 재인코딩하지 않았다.
숨긴 펫을 이벤트가 다시 표시하지 않으며, 세션 시작 이후 선택한 다른 펫에 이전
세션의 반응을 전달하지 않는다.

## 새 팩의 제작 기준

- 우선 384×384 RGBA 캔버스, 모든 클립에서 동일한 캐릭터 크기·발 위치·방향을
  유지한다. pixel/smooth 스타일은 `renderStyle`로 일관되게 지정한다.
- 프레임 PNG 또는 `.aseprite`를 편집 원본으로 보존하고 런타임 PNG 시트/GIF를
  내보낸다. 기존 Mochi 파일은 이 작업에서 다시 인코딩하지 않는다.
- 투명 배경은 실제 alpha여야 한다. 체크무늬를 그림에 넣거나 불투명한 흰 배경을
  투명 배경으로 간주하지 않는다. 원본은 PNG를 우선해 GIF 색상·alpha 제약을 피한다.
- 새 이벤트 클립은 10초 이내, 패키지 디코딩 픽셀 합계 64 MiB 이내를 제작 목표로
  잡는다. UI bitmap 복사와 GPU 메모리는 별도이므로 실기 자원 사용을 확인한다.
- 단순 색상 교체가 아니라 실루엣·성격·시작/완료/클릭 동작에 차이를 둔다.
  실제 192px 표시 크기에서 이 차이가 읽혀야 한다.
- 생성형 이미지 결과를 그대로 상품화하지 않는다. 방향, 팔다리 수, 프레임 사이
  깜박임·크기 변화, 루프 이음새, 한 번 재생 후 idle 복귀를 검수한다.

## 검사와 출시 판정

Release 빌드 후 저장소 루트에서 실행한다:

```sh
dotnet build Unfold.slnx -c Release --no-restore
bash Scripts/validate-character-assets.sh > /tmp/unfold-character-audit.json
```

Windows와 게시 파일에서도 같은 읽기 전용 진입점을 쓸 수 있다:

```text
Unfold.exe --validate-characters <character-directory>
```

이 명령은 앱 창·사용자 데이터 프로필을 만들지 않는다. JSON에 클립별 프레임 수,
길이, 크기, 디코딩 바이트, 투명/빈 프레임과 참조 파일의 SHA-256을 출력한다.
손상된 GIF, ID 불일치, 중복 ID, 완전히 빈 프레임, loop 규칙 오류는 실패(exit 1)다.
선택 반응 누락, 크기 차이, 투명 배경 의심 등은 경고로 남긴다.

**자동 검사 성공은 판매 승인이나 애니메이션 시각 검수 완료가 아니다.** 실제
밝고 어두운 바탕, 100%·고DPI, 클릭 영역, 시작·완료·반복·숨김·캐릭터 전환을
검수하고 프레임별 alpha와 원본 권리 기록을 확인한다. Mochi의 캔버스 크기·불투명 배경 차이는
기존 시트 연결로 개선했으며, 남아 있는 선택 반응 누락과 원본 권리 확인은 원장으로 관리한다.

`--review-pet-pack <file.unfoldpet>`은 새 격리 프로필에서 설치와 실제 시간 기반 재생을
검사하고 밝고 어두운 배경의 캡처를 만든다. off-screen 창과 코드로 실행한 버튼 이벤트를
사용한다. [실행 방법과 한계](verification.md#펫-팩-재생-진단),
[보리의 측정 결과](validation/2026-09-14-bori-candidate.md)를 참고한다.

팩은 검증된 contentVersion과 파일 해시 목록으로 고정해 배포한다.
[로컬 팩 설치기](pet-packs.md)는 미리보기 → staging 검증 → backup을 통한 교체·복구를
지원한다. 기존 팩을 보존하며 설치·버전 갱신·같은 버전 재설치를 제공한다.
계정 구매 권한 복원과 판매용 아트 검수는 [개발 계획](development-plan.md)의 남은 3차 범위다.
