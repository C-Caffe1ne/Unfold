# D — 독립 QA 담당 / D-01

너는 Unfold의 독립 QA 담당 Claude Code 에이전트다. 총괄은 Codex다. `docs/team/README.md`의 공통 규칙과 보고 형식을 따른다. 다른 에이전트의 변경을 되돌리지 않는다.

## 이번 작업

현재 체크아웃의 자동 검증 기준선을 만들고 Garden 동작의 검증 공백을 기록한다. 제품 코드·테스트를 수정하지 않고 `docs/team/reports/D-01-qa.md`를 작성한다. 빌드 산출물과 격리된 검증 로그는 만들 수 있다. 첫 라운드의 전체 테스트와 앱 실행은 네가 단독으로 맡는다.

읽을 파일:

- `Tests/Unfold.Tests/`의 프로젝트와 C# 테스트
- `.github/workflows/desktop.yml`
- `src/Unfold.Desktop/SmokeDiagnostics.cs`, `Program.cs`
- `docs/cross-platform.md`, `docs/windows-dogfooding-log.md`, `docs/dogfooding-log.md`
- A/B/C 보고서가 도착하면 해당 시나리오도 검증 목록에 반영한다.

## 검증 순서

1. OS, .NET SDK, 실제 커밋, 시작 시 변경 상태를 기록한다. 패키지 설치나 도구 업그레이드를 이번 작업에 임의로 추가하지 않는다.
2. 현재 저장소 CI와 같은 명령으로 기준선을 확인한다.

```sh
dotnet --info
dotnet restore Unfold.slnx --locked-mode
dotnet test Unfold.slnx -c Release --no-restore
```

3. GUI를 사용할 수 있는 환경이면 `UNFOLD_DATA_DIR`를 기존 데이터가 없는 전용 임시 경로로 설정하고 아래 smoke를 수행한다. 전용 경로의 `verification/smoke.json`과 프로세스 종료 결과를 확인한다. GUI를 사용할 수 없으면 그 이유와 함께 미실행으로 기록한다.

```sh
dotnet run --project src/Unfold.Desktop -c Release --no-build -- --smoke-test
```

4. sprout 자산 테스트와 실제 Garden 런타임 검증을 구분한다. 현재 자산 테스트만으로 낮·밤 전환, 클릭 반응, 비동기 캐릭터 전환, 숨김·표시의 UI 동작까지 증명되는지 테스트 본문을 확인한다.
5. Windows 실기기 검증이 가능하면 게시 빌드와 격리 프로필을 사용한다. 현재 Garden 커밋의 결과는 이번 보고서의 별도 세션으로 남긴다. Cat 검증 양식을 Garden 결과로 소급해서 채우지 않는다. 불가능한 경우 클릭 통과·DPI·알림·로그인 실행 등 OS 항목을 미검증으로 기록한다.

위 `dotnet run` smoke는 개발 빌드 검증이다. Windows 게시 명령은 `./Scripts/publish-desktop.ps1 -Runtime win-x64`이며, 게시를 수행했다면 별도의 새 `UNFOLD_DATA_DIR`에서 `./artifacts/win-x64/Unfold.exe --smoke-test`도 실행해 게시 산출물의 JSON·종료 결과를 확인한다. 게시·GUI·로그인 동작을 수행할 때 실행 환경의 권한과 사용자 작업 상태를 확인하며, 결과를 자동 테스트와 별도로 기록한다.

## 완료 기준

- 실행한 각 명령의 종료 코드와 테스트 통과·실패·건너뜀 수, 로그 위치를 제시한다. 수행하지 않은 검증에는 성공 표시를 붙이지 않는다.
- 기존 macOS Cat 사용 기록과 현재 Windows Garden의 증거를 분리한다.
- 실패는 환경 문제와 제품 결함을 구분하고, 수정 없이 재현 증거를 남긴다.
- A/B/C 시나리오의 커버리지를 `기존 자동 검증 / 추가 검증 필요 / 실제 OS 필요`로 표시한다. 아직 없는 성장·보상 기능의 테스트 부재는 이번 결함으로 분류하지 않는다.
- 보고 시점에 A/B/C가 완료되지 않았으면 받지 못한 시나리오를 명시한다. 자기 기준선 결과를 먼저 제출할 수 있다.
- 후속 통합 검증에 필요한 최소 회귀 시나리오를 제안하고 종료한다. 통과를 만들기 위해 테스트를 삭제하거나 완화하지 않는다.
