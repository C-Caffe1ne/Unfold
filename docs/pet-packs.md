# 펫 관리 · 커스텀 펫 팩 만들기

2026년 10월 8일 · Beta v1.1.2의 로컬 펫 관리·파일 배포 계약.
최신 공개 배포는 Beta v1.1.2다. 펫 팩 상점·계정별 팩 다운로드는 제공하지 않는다.
현재 Mochi·보리는 [확장 행동이 있는 기본 팩](../Art/Characters/original-companions-v2/README.md)으로 제공한다.
같은 행동 프로필의 [강아지·고슴도치·펭귄](../Art/Characters/original-companions-v3/README.md)도 기본 목록에 포함한다.
기존 [보리 0.1.0 아트 후보](../Art/Characters/bori-rabbit/README.md)는 역사 자료로 보존한다.

## 사용 방법

1. 설정 사이드바의 **펫 관리** 화면을 연다.
2. 펫 이름 오른쪽 **파일 열기…**에서 `.unfoldpet` 파일을 고른다. 이때는 임시 공간에서만
   검사하고 미리본다. 창을 닫으면 설치하지 않는다.
3. 이름·내용 버전·현재 설치 버전을 확인한다. 미리 볼 동작에서 제공되는
   반응을 선택하면 재생하며, 한 번 재생하는 반응이 끝나면 idle로 돌아온다.
   참고 사항 목록과 이동 버튼은 표시하지 않는다. 파일 검증과 잘못된 팩 거부는 유지한다.
4. **저장**을 누른다. 설치·업데이트·재설치 또는 선택한 팩으로 교체한다. 낮은 콘텐츠 버전이나 같은 버전의 다른 내용도 적용할 수 있다. 성공하면
   해당 펫을 캐릭터 목록에 반영하고 선택한다. 타이머의 일시 정지 상태는 유지한다.

### 설치한 펫 편집·삭제 — Beta v1.1.2

미리보기 아래 **펫 선택**은 설치한 GLB·이미지·GIF·MP4 펫을 모두 표시한다.
선택하면 형식에 맞는 편집 화면과 기존 이름·행동·재생 방식을 불러온다. **편집**으로 저장된 내용을 다시 불러올 수도 있다.
기본 제공 펫 5종은 이 관리 대상에 포함하지 않는다.

- 이미지·영상 펫은 이름, 행동 파일과 **한 번 / 반복 / 핑퐁**을 수정하고 **저장하고 적용**한다.
  기존 스프라이트 팩의 추가 행동도 편집할 수 있으며, 수정하지 않은 프레임·시간·동작과 렌더링 설정을 보존한다.
- GLB는 기존 애니메이션·방향·속도·재생 설정을 수정하고 같은 **저장하고 적용**을 사용한다.
- 저장은 같은 펫 ID를 유지하고 내용 버전을 증가시킨다. 저장 실패 시 초안을 보존한다.
  편집 중 파일이 외부에서 변경·삭제되면 덮어쓰거나 다시 생성하지 않고 오류를 표시한다. **편집**으로 현재 내용을 다시 불러온다.
- **펫 삭제**는 확인 후 해당 설치 펫을 제거한다. 취소하면 펫과 초안을 유지한다.
  사용 중인 펫을 삭제하면 기본 펫으로 전환하고 선택을 저장한다. 다른 펫·타이머·기록과 가져온 원본 파일은 보존한다.
- 이전 픽셀 펫도 현재 실행 행동을 편집할 수 있으며 `source.piskel`은 보존한다. 픽셀 그림 편집 UI를 다시 추가하지 않는다.

검사 결과와 macOS 실행 범위는 [펫 편집·삭제 검증](validation/2026-10-08-pet-management-edit-delete.md)에 기록한다.

### GLB·이미지·GIF·MP4에서 펫 팩 만들기

1. **펫 관리 → 파일 열기…**에서 GLB·GIF·MP4 또는 이미지를 고른다. 파일 형식은 자동 전환된다.
2. 펫 이름을 입력하고 **행동 연결 → 상황**에서 편집할 행동을 고른다.
3. GIF·MP4·이미지는 선택한 행동에 파일을 배정하고 **한 번 / 반복 / 핑퐁**을 고른다.
   다른 파일은 해당 행동의 **파일추가(＋)** 또는 상단 **파일 열기…**로 불러온다.
   긴 파일명은 말줄임으로 표시하며 툴팁에서 전체 이름을 볼 수 있다.
   파일 교체 취소나 검증 실패 시 기존 파일과 설정을 유지한다.
   핑퐁은 끝 프레임에서 내부 프레임을 역순으로 재생한다.
4. GLB는 모델에 포함된 애니메이션·재생 방식·속도를 지정한다. [GLB 계약](glb-pets.md)을 따른다.
5. **펫 팩 만들기…**로 `.unfoldpet` 파일을 저장한다. 이때 설치되지는 않는다.
6. 자동으로 열리는 **펫 팩 확인** 창에서 미리본 뒤 **저장**을 누른다.
   GLB는 **저장하고 적용**으로 바로 설치할 수도 있다.

두 형식은 같은 반응형 미리보기·선택 행동 편집 레이아웃을 사용한다. 한 번에 선택한 행동만 보이며,
미리보기 옆에서 일시정지·다시 재생을 조작한다. 항목별 설명·재생 요약·모델 통계는 표시하지 않는다.
파일 형식·사이드바를 오가거나 설정 창을 숨겨도 두 초안과 선택 상태를 유지한다.
동일한 팩에서 GLB 모델과 GIF/MP4를 혼합하지는 않는다. GIF·MP4·정지 이미지는 서로 섞어 배정할 수 있다.

새 영상·이미지 팩은 새 ID로 생성하며 내보내기 성공 후 빈 초안으로 초기화한다. 설치 펫의 편집 저장은 같은 ID를 유지한다. GLB는 같은 ID와
행동 설정을 유지하고 성공적으로 내보내거나 설치할 때 내용 버전을 올린다.
저장 취소·실패 시 초안을 유지한다. 앱 종료 후에는 저장한 팩과 설치한 펫만 남는다.
종료 시 두 형식의 미저장 초안을 모두 확인한다.

| 동작 | 파일 필요 여부 | 실행 시점 / 기본 재생 설정 |
|---|---|---|
| 기본 | 필수 | 평상시 / 반복 |
| 알림 | 선택 | 휴식 초대 / 한 번 |
| 휴식 | 선택 | 휴식 시작 / 한 번 |
| 휴식 완료 | 선택 | 완료 확인 / 한 번 |
| 클릭 반응 | 선택 | 펫 클릭 / 한 번 |
| 마우스 호버 | 선택 | 펫 위 진입 / 한 번 |
| 마우스 눌림 | 선택 | 왼쪽 버튼 누름 / 한 번 |
| 마우스 뗌 | 선택 | 왼쪽 버튼 해제 / 한 번 |

반복 설정은 팩에 저장되며 만들기·열기 미리보기와 커스텀 펫 런타임에 적용한다.
반복 반응은 다음 행동이 시작될 때까지 유지한다. 호버 반복은 포인터가 떠나면 기본으로 돌아간다.
마우스 뗌 파일이 있으면 해당 반응이 클릭 반응보다 우선한다.
기존 팩의 행동 ID는 유지하며 새 재생 설정이 없는 팩의 기본 재생 계약도 유지한다.

선택 동작이 없으면 현재 동작을 유지한다. 원본 파일은 수정하지 않고, 가져올 때의 파일
내용을 보관한다. 새 팩에는 고유 ID와 내용 버전 `1.0.0`을 부여하므로 기존 펫을 덮어쓰지 않는다.
제작 창을 취소하면 팩 파일과 라이브러리를 생성하지 않는다. 저장된 팩은 다음에도 기존
**파일 열기…**로 열고 재설치할 수 있다.

- GIF: 원본 픽셀·투명도·프레임 시간을 유지한다. 파일당 32 MiB, 최대 2048px·512프레임,
  기존 디코딩 예산을 적용한다. 완전히 투명한 프레임과 손상된 파일은 거부한다.
- 정지 이미지·사진: PNG·JPG/JPEG·WEBP·BMP, 파일당 32 MiB, 각 변 최대 8192px,
  총 16,777,216픽셀 이하. 사진의 회전·반전 정보를 적용하고 비율을 유지해 긴 변을 최대 512px로 줄인다.
  작은 이미지는 확대하지 않으며 투명도를 유지한다. 정지 동작은 1프레임·1초로 저장하고,
  같은 팩의 정지 이미지들은 중앙 정렬한 PNG 시트에 넣어 기존 버전 1 형식을 유지한다.
  GIF·MP4와 함께 넣을 수 있다. 배경 제거는 하지 않으며 움직이는 WEBP는 GIF·MP4로 가져온다.
- MP4: 파일당 128 MiB, 10초 이하. 로컬에서 소리를 제외하고 비율을 유지한 최대 192px,
  초당 12프레임의 GIF로 변환한다. 10초가 넘는 영상은 자동으로 자르지 않고 거부한다.
  MP4의 배경은 그대로 남으며 배경 제거 기능은 포함하지 않는다.
- 커스텀 팩의 가져온 미디어 스냅샷 합계는 약 32 MiB, 디코딩 픽셀 합계는 128 MiB 이하로 제한한다.
  완성 팩도 기존 크기·해시·디코딩 검사를 모두 통과해야 저장된다.

MP4 변환 도구는 게시 스크립트가 `Tools/`에 동봉한다. 개발 환경 준비와 OS별 제한은
[플랫폼 안내](cross-platform.md#development-and-packaging)를 참고한다. 앱은 사용자의
영상을 업로드하거나 실행 중 도구를 다운로드하지 않는다.

### 설치 전 외형과 반응 확인

파일을 선택한 뒤 열리는 **펫 팩 확인** 창에서는 미리보기 영역을 최대 520px 너비로 가운데 배치하고,
상단 **펫 팩 열기…** 버튼은 120×40px다.
팩 이름·버전은 파일을 연 뒤 표시한다. 미리보기 아래에는 재생 아이콘 두 개를 중앙에 두고,
그 아래 왼쪽에는 **미리 볼 동작** 200×40px, 오른쪽에는 **미리보기 크기** 148×40px를 배치한다.
작은 창에서는 사용 가능한 너비까지
미리보기 표면을 줄이며, 200% 미리보기도 본문 안에서 세로 스크롤할 수 있다.
상태·오류는 하단 왼쪽, 저장·만들기 버튼은 하단 오른쪽에 고정한다.

- 배경 선택 항목은 표시하지 않으며 현재 앱 테마의 표면색을 사용한다.
- **미리보기 크기 → 100% / 150% / 200%**로 192 / 288 / 384 논리 픽셀 크기를 확인한다.
  이 선택은 미리보기 창에만 적용된다. 원본 해상도나 데스크톱 펫의 크기를 변경하지 않는다.
- **일시정지 / 계속**은 현재 위치에서 미리보기를 멈추거나 이어 재생한다. 멈춘 상태에서
  다른 반응을 고르면 그 반응의 첫 프레임에서 대기한다.
- **다시 재생**은 선택한 반응을 처음부터 재생한다. 반응이 끝나면 기본 대기로 돌아가지만
  선택 항목은 유지하므로 같은 반응을 바로 다시 볼 수 있다. 멈춘 상태에서도 다시 재생을
  누르면 재생을 시작한다.

기본 반응은 쉬는 모습, 휴식 안내, 스트레칭, 휴식 완료, 클릭 반응으로
표시한다. 팩의 ID와 애니메이션 키는 그대로 유지한다. 미리보기 창이 숨겨지면 재생을
멈추며, 다시 표시해도 사용자가 선택한 일시정지는 유지한다. 크기 선택은 이 창을
열어 둔 동안만 유지된다. 큰 미리보기나 작은 창에서는 세로로 스크롤한다.

| 파일과 현재 라이브러리의 관계 | 동작 |
|---|---|
| 새로운 ID | 설치 |
| 같은 ID, 더 높은 내용 버전 | 업데이트 |
| 같은 ID, 같은 내용 버전 | 재설치. 손상·누락된 실행 이미지를 원본 팩으로 복구 |
| 같은 ID·버전인데 배포 파일의 해시 목록이 다름 | 선택한 팩으로 교체 |
| 같은 ID, 더 낮은 내용 버전 | 선택한 이전 팩으로 교체 |
| 기본 펫 ID 또는 기존 사용자 제작 패키지 ID | 거부. 사용자 원본을 팩으로 덮어쓰지 않음 |
| ID의 대소문자만 다름 | 거부. Windows/macOS 간 충돌 방지 |

재설치는 사용자가 보관하거나 다시 받은 같은 버전의 파일을 사용한다. 계정에서 구매
내역을 조회하거나 다운로드하는 기능은 없다. 설치 메타데이터 `pack.json` 자체가 손상된
경우는 자동 재설치 대상 판정을 할 수 없으므로 오류를 표시하고 파일을 보존한다.

## 배포 파일 계약

`.unfoldpet`은 ZIP이며 루트에 `pack.json`, `character.json`, 런타임에서 참조하는
PNG/GIF 또는 GLB 모델만 담는다. 별도 최상위 폴더나 원본 `.piskel`·`.aseprite`를 넣지 않는다.
원본과 권리 기록은 [제작 원장](pet-resources.md)에 보관한다.

`pack.json` 예시의 SHA-256은 실제 각 파일 전체 바이트로 계산한다:

```json
{
  "formatVersion": 1,
  "id": "example-pet",
  "contentVersion": "1.0.0",
  "files": {
    "character.json": "<64 lowercase hex characters>",
    "spritesheet.png": "<64 lowercase hex characters>"
  }
}
```

- `formatVersion`은 팩 형식, `character.json`의 `version`은 런타임 형식,
  `contentVersion`은 그림·애니메이션 개정 버전이다. 서로 대체하지 않는다.
- 내용 버전은 `1.0.0`처럼 숫자 세 부분으로 비교한다. prerelease·build 접미사는
  현재 지원하지 않는다. 제작 원장의 버전과 일치시켜 배포한다.
- ID는 런타임 manifest와 일치해야 한다. 파일명은 최대 128자의 ASCII 영숫자,
  점·밑줄·하이픈으로 제한하며 영숫자로 시작한다. 폴더, 링크, Windows 예약 이름,
  대소문자 중복 파일은 허용하지 않는다.
- ZIP은 최대 32개 파일, 압축 파일 및 압축 해제 합계 각각 64 MiB,
  개별 파일은 32 MiB, 팩 메타데이터는 64 KiB 이하다.
- 최대 16개 클립, 디코딩 픽셀 합계 128 MiB를 넘으면 설치를 거부한다.
  판매용 제작 목표 64 MiB는 더 엄격하며 설치 통과가 품질 승인은 아니다.
- 목록 밖 파일, 해시 불일치, 잘못된 이미지·GIF, 빈 프레임, idle/반응 loop 오류는
  거부한다. 크기·배경·선택 반응 경고는 미리보기에도 표시한다.

해시는 내용 일치 검사다. **제작자 서명이나 구매 권한 증거가 아니다.** 현재 형식은
로컬 파일 설치이며 원격 카탈로그·라이선스 잠금·DRM을 포함하지 않는다.

`character.json`의 선택 필드 `behaviorProfile: "unfold-original-v1"`과 열 개 행동 키를
모두 가진 팩만 랜덤 대기·미루기 반응·휴식 중 이동을 사용한다.
누르기·유지·드래그·놓기에 앱이 덧붙이던 캔버스 확대/축소·상승·바운스는 제거했다.
배정된 애니메이션과 창 드래그는 유지하며, 놓기는 `land` 클립을 지연 없이 시작한다.
키는 기존 다섯 개와 `sleep`, `look`, `yawn`, `sulk`, `walk`다. 이 필드가 없거나
클립이 부족하면 기존 행동을 유지한다. 커스텀 제작기의 다섯 파일 슬롯과 출력 규격은 그대로다.
기본 Mochi·보리·강아지·고슴도치·펭귄 팩 파일은 열어 미리볼 수 있지만 현재 앱에서 같은 기본 ID를 다시 설치할 수는 없다.
다섯 펫은 홈 선택 목록에서 바로 선택한다.

## 제작자가 파일 만들기

Release 빌드 후 저장소 루트에서 실행한다. 입력 폴더 이름은 manifest ID와 같아야 한다.
출력 파일이 이미 있으면 덮어쓰지 않는다.

```sh
dotnet src/Unfold.Desktop/bin/Release/net10.0/Unfold.dll \
  --pack-character /path/to/example-pet 1.0.0 /path/to/example-pet-1.0.0.unfoldpet
```

게시 앱에서도 `Unfold.exe --pack-character <directory> <version> <new-output.unfoldpet>`
형태로 사용할 수 있다. 이 경로는 앱 창과 사용자 데이터 프로필을 만들지 않는다.
실제 런타임 이미지 검사와 생성한 ZIP의 재검증을 거친 뒤 파일을 게시한다.
검사 오류는 종료 코드 1, 인자 오류는 2다.

## 저장과 실패 복구

설치 위치는 사용자 데이터의 `Characters/<id>/`다. 미리본 파일은 독립된 임시
스냅샷으로 유지하므로 원래 ZIP을 바꿔도 설치 내용이 바뀌지 않는다. 설치 직전에
이 스냅샷의 해시와 실제 디코딩을 다시 검사한다.

기존 에디터와 같은 라이브러리 잠금을 사용한다. 같은 파일시스템의 staging 폴더에서
검증한 뒤 기존 폴더를 backup으로 옮기고 새 폴더를 배치한다. 배치 실패 시 이전 폴더를
되돌린다. 중간에 앱이 종료되면 다음 라이브러리 읽기에서 backup/staging을 복구·정리한다.
이는 **복구 가능한 디렉터리 교체**이며 두 번의 rename이 하나의 원자적 OS 연산이라는
뜻은 아니다. 미리보기 이후 기존 파일이 바뀌면 덮어쓰지 않고 다시 열도록 안내한다.

설치 후 목록 갱신·설정 저장이 실패한 경우에는 설치 실패와 구분하여 표시한다.
팩 파일은 설치되어 있으므로 설정을 다시 열어 선택할 수 있다.

정상 종료 시 미리보기 임시 폴더를 삭제한다. 강제 종료 시 OS 임시 디렉터리에 남을 수
있으며, 구매 파일 보관·백업 수단으로 사용하지 않는다.
